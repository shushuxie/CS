  - 一句话概括：一个从被调剂到计算机、毕业拿到十多个 offer 的过来人，按九个常见问题讲语言选择、课程、计划、笔记、刷题与看书方法，适合新手搭自己的学习框架。
  【方法/论点要点】
  - 选语言：有方向就按方向选（算法/机器学习选 Python，Web 选 Java/PHP，底层选 C）；没方向时别纠结性能与难易。在校生先 C 再 C++，花小半年了解底层，向下打通操作系统、编译原理、网络、组成原理；上班族时间零碎，从 Python 入手先做出小应用保住兴趣，再读《深入理解计算机系统》补体系。
  - 看课程：本科课程面向“面”，工作读研面向“点”；高数、离散、线代、概率论支撑算法，数电模电帮助理解 CPU 中的逻辑器件，不必因“用不上”而抵触；有明确方向可自行调整优先级。
  - 学习法：采用改良版项目驱动——学一段时间，做个小项目，把遇到的问题记下来，针对性补知识，再实践，同时每天抽固定时间完整读一本书，防止知识只剩碎片。作者以爬虫系统为例，从 request/response 牵出 HTTP/HTTPS、DOM 解析、代理池、JS 解密、Redis 任务队列、数据库选型与索引、验证码识别与深度学习，说明每条分支都能深挖，整个路径是网而不是树。
  - 做计划：从 13 年入学起定期列计划，把需要学的内容编号存入表格；大四拿到 offer 后仍列了学英语和补专业课的计划。计划很难完全执行，但能让人清楚该干什么、过得有条不紊。
  - 做笔记：博客可以不写，笔记必须做且长期坚持；笔记是定制化的，“是自己写给自己看的东西”，比搜来的答案更容易内化，作者已积累四年、1G 多内容，等一两年就是巨大财富。
  - 控节奏：同一时间段别学太多门，避免一门没学多久就换下一门；按艾宾浩斯曲线，难课每天半小时效果差，宁可每天两门、每门两小时，别想一口吃成胖子。
  - 刷 OJ：初期要刷，目的是熟悉写代码、记语法关键字、理解概念，不必为竞赛背代码；熟练后转向 GitHub 项目，甚至脱离 IDE，用 vim 或 sublime 加 gdb 写 C++。刷题对校招笔试突击同样有效（刷二十多道华为 OJ，600 分考了 500）。
  - 书与视频：视频入门快，能迅速知道技术能干什么、需要什么先修；缺点是杂而不系统。书系统化、可由浅入深按薄弱章节读，所以“看视频入门，看书进阶”。
  - 选资料：最大的问题不是没资料，而是在海量资料前不知道选什么；作者整理了一份免费资料包，并推荐了可在线上运行的编程环境，省去搭环境的麻烦。
  - 多久学会：只做小应用两个月足够，但学编程是学一个生态，没有终点；先定方向再开工，比反复换语言省时间。

  #+end_quote

  项目驱动式学习最大的好处是让你知道你应该去学习什么，而不是先学一大堆知识，再去做一个项目。

  【我的想法】
  这篇的方法论密度在同类文章里算高，“改良版项目驱动”和“定制化笔记”都能直接照做，尤其适合刚入门、容易被资料淹没的人。计划与笔记都要长期坚持，这一点比具体工具更重要；作者后来脱离 IDE、只用编辑器和 gdb 也能写代码，正说明基本功比工具更值钱。局限是案例停留在 2017 年前后的爬虫与 TensorFlow 环境，文末的资料网盘和在线环境带明显推广色彩，链接多半已失效；把它当方法书而非资源清单来读更合适。
