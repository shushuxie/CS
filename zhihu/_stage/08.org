- 一句话概括：一位五年经验的 C++ 程序员换工作被拒后的自省：面试官嫌他"什么都会一点、什么都不深"，由此谈熟练工与领域专家的差别，文末附成长路线图（并带课程导流）。
【方法/论点要点】
- 转折点：五年经验、自认资历不浅，换工作时却被拒；面试官的原话是"我们不需要熟练工，我们需要在某领域拥有超过常人的积累认知，和拥有整套完整思维模式和优秀认知事物能力的人"。
- 被戳中的短板：线程池、TCP/IP 被问得"人仰马翻"，回来才下决心把这两块研究透——此前是"这也用过、那也知道"，但只停留在见过、会用。
- 核心判断：只停留在 API 层、不读源码、不体会设计思想，就只是"敲代码的机器"；程序员应是最有活力和思想的群体，前提是不肯浮于表面、勤于思考。
- 年龄与精力：年纪渐长后无法再靠加班，时间更多给家人、社区教育和开源小组；对"新技术喧嚣"的忍耐度越来越低，更看重技术的稳定与清晰。
- 竞争背景：截至 2018.07 中国 C++ 程序员已超 100 万，培训班与应届生持续涌入，初级和"三五年后开始迷茫"的老程序员都绕不开知识体系问题。
- 给出的解法：总结了一张"2~5 年 C++ 程序员成长路线图"（以图片形式），并推荐了工程化、高性能与分布式、性能调优、TCP、协程、Nginx 源码分析等方向的学习视频。

【我的想法】
前半段是真诚的复盘，"熟练工 vs 领域专家"这句放到今天依然戳人；后半段明显转向课程广告（路线图是图片、答案是视频链接），读的时候要分开看。真正可操作的是他无意中给出的方法：被问倒的那两个点（线程池、TCP/IP）就是最好的学习清单——面试暴露的空白比任何路线图都准。另外"五年经验"不等于"五年深度"，这点对今天卷八股的行情反而是提醒：与其背面经，不如把一两个系统真正读透。
