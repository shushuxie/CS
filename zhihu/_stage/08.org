  - 一句话概括：把大学 Java 课最常被拿来当课程设计的七个项目一一点名，每个都配上实验楼对应课程的知识点清单和技术栈，等于一份“老师会布置什么”的选题地图，适合按已学章节挑练手项目。
  【方法/论点要点】
  - 计算器（课程 185）：学完一点语言基础就会被要求“这周下去自己开发一个计算器，下次上课前交给我”。用 Java Swing 做图形界面，重点在 UI 组件的事件响应和四则运算逻辑，知识点只有两条：Swing 界面编程、计算器逻辑运算实现。
  - 记事本（课程 154）：安排在学完文件读写之后，项目简单但有趣。Swing 界面 + 文件操作 + Java IO，练的是可视化界面和读写文件的配合。
  - 日记软件（课程 260）：支持用户注册、登录以及日记的增删改查，涉及 Swing 界面、文件和 IO 流、JDOM 解析 XML 文档。作者自述当年学得差，为这个项目熬了几个通宵。
  - 网页聊天室（课程 113）：用 WebSocket 做实时通信，前端 AmazeUI，编辑器 UMEditor，后端 Java。知识点横跨网页前端（HTML + CSS + JS）、Java、WebSocket，是七个里唯一的前后端混合项目。
  - 课程管理系统（课程 891）：作者明说它就是“图书管理系统”的变体，用 Spring + Spring MVC + Hibernate 实现，使用者分课程管理者与课程制作者两种角色，各有各的功能和权限。他当年的做法是四人小组，一人负责一块。
  - 人事管理系统（课程 824）：和图书管理、课程管理同属“XX 管理系统”家族，用 SSM（Spring + Spring MVC + MyBatis）+ easyUI 搭一个简易版本，目标是完整走一遍 SSM 项目的开发流程。
  - 支付平台业务流程（课程 576）：对应“购物网站”这个必布置题目，但不做完整商城，只模拟买家付款到平台、卖家从平台取款的一段流程；没有界面，结果打在控制台，真正讲的是 Java 线程与同步、并发与并行、操作系统进程状态。想要完整商城，作者另外推荐了一门 Go 语言课程，理由是语言不同但业务逻辑相通。
  - 全文的组织方式统一为：一句吐槽式引入 + 效果图 + 课程简介 + 知识点（或实验列表）+ 课程链接，没有难度分级，也没有代码讲解。

  【我的想法】
  价值不在教程本身，而在那张“题目—知识点”的对应表：想练 Swing 就挑计算器/记事本，想练 IO 和 XML 挑日记本，想碰 WebSocket 挑聊天室，想走 SSM 就挑人事管理，选型时不用再猜。局限也明显，它本质是课程导流文，每个项目只有两三行简介和知识点罗列，没有难度、工作量、验收标准的比较，链接还都指向同一个平台。技术栈停留在 Swing + Hibernate + SSM 的年代，今天重做这些题目更合理的组合是 Spring Boot + Vue，支付流程那个例子倒是例外——线程与同步的练习和框架无关，现在依然成立。
