  - 一句话概括：介绍三个“玩着学”的编程平台——CodinGame（游戏化刷题，支持 25+ 语言）、FreeCodeCamp（开源、体系化，前端/数据可视化/后端三大块）、Codecademy（更专业完善的专项课），并补上 W3Schools、MDN 和给初学者的学习建议；值得收是因为它按“入门阶段该玩什么”分了层，选平台时不用再乱试。
  【方法/论点要点】
  - 总原则：有趣的未必最高效，但能让你保持对编程的热情；三个平台里第一个适合入门后练手，后两个适合初学者了解一门语言的基本内容。
  - CodinGame（~codingame.com~）：通过玩游戏学编程的挑战平台，支持 25+ 语言；有等级和经验值，完成挑战涨经验；Clash of Code 模式是几个人限时同题竞技，第一个完成很有成就感；另有按难度分级的单人训练、竞赛和奖品，社区已有中文频道。
  - FreeCodeCamp（~freecodecamp.com~）：开源项目，GitHub 上 197k Star；基于挑战但更系统，分前端开发、数据可视化、后端开发三大部分，有完整任务列表；每部分学完有实际项目（番茄时钟、Markdown 预览器）和证书；被 LinkedIn 认证为大学，可写进教育经历；作者建议在学 Python/Flask 的空闲时间完成它的前端内容。
  - Codecademy（~codecademy.com~）：和 FreeCodeCamp 类似但更专业完善，有专项课程和 12 种语言教程；如果觉得 FreeCodeCamp 太简单、完整挑战太耗时，可以选它。
  - 更轻的入口：只想快速入门一门语言（主要是前端），可以用 W3Schools 或 MDN。
  - 给初学者的建议：后两个平台适合熟悉语法和学习工具，但语法只是技能树的一小部分；过了初学阶段要多接触好书、做实际项目、补算法/计算机原理/网络原理等基础，可参考《编程入门指南》。

  - 一句话概括：作者把自己整理的 LeetCode 刷题顺序完整公开——按专题排好题、每道都是筛过的经典高频面试题，并配 200 多篇题解、60 万字图解和视频；值得收是因为它直接解决了“从近两千道题里选哪道”的启动成本，文章顺序就是刷题顺序。
  【方法/论点要点】
  - 问题：LeetCode 有近两千道题，初学者（甚至老手）自己找经典题的时间成本极高，还不一定找到经典题。
  - 核心主张：想用最短时间把经典题做一遍，效率最高的方式是照现成顺序刷——“文章顺序就是刷题顺序，挨个刷就可以，不用自己再去题海里选题”。
  - 刷题主线（按顺序）：数组 → 链表 → 哈希表 → 字符串 → 双指针法 → 栈与队列 → 二叉树 → 回溯算法 → 贪心算法 → 动态规划 → 单调栈（图论、高级数据结构在规划内）；每个专题先做简单题，做几个类型题后再上中等、困难。
  - 配套资源：官网 ~programmercarl.com~；开源仓库 ~github.com/youngyangyang04/leetcode-master~（支持 C++、Java、Python、Go、JS 等语言）；B 站有视频讲解；重要专题另出 PDF（二叉树、回溯、动态规划、贪心等），含刷题大纲、刷题顺序和 20 万字图解。
  - 攻略结构：每个专题开头有理论基础篇（从实战中归纳，不是教科书式介绍），结尾有总结篇；目前更新了数组、链表、哈希表、字符串、栈与队列、树、回溯、贪心八个专题，动态规划在讲。
  - 作者强调的复习法：经典题不是刷一遍就完事，要刷很多遍——刷到贪心时回溯可能已经忘了；面试前一段时间集中看各专题的总结篇做快速回顾。
  - 适合谁：刚起步不知道从哪刷的人照着走；算法老手把各专题总结篇过一遍，可以快速重建知识体系。

  - 一句话概括：把《费曼思考法》的五个步骤（观察、动机、提问、模型、输出）逐一对照自己的差距，并提炼出“火星人观察法”“12 个问题启动动机”“去除三种杂草”“IRADE 教学法”等可直接用的工具；值得收是因为它把一本学习方法书读成了自查清单，每个步骤都落到具体做法。
  【方法/论点要点】
  - 第一步，像“火星人”一样观察：费曼的“观察”不是无意识地看，而是对常规事物保持陌生感。书中举例：火星人看见人类睡觉会追问——突然失去意识是什么感觉？不清醒意味着什么？大脑还能工作吗？意识是突然消失还是逐渐消失？作者由此反省：我们对常规事物失去好奇心，也就错失了向它们学习的机会。费曼的科学方法被概括为：先猜测，再计算猜测的结果，然后与自然现象/经验/观察比较，不一致就说明错了。
  - 第二步，用 12 个问题启动内在动机：不要问“我擅长什么、什么能挣钱、什么能给别人留下印象”，而是找“这天地间那些让自己一直以来十分着迷的小角落”。费曼不关心荣誉，物理就是那个让他着迷的小角落；他还习惯怀揣 12 个有趣的问题和 12 个相关答案，并在它们之间寻找联系——把不懂的主题写下来，会引导你持续关注相关人事物。
  - 第三步，去除“杂草”、发现“精华”：三种杂草——① 内心的傲慢（学了一点就以为掌握，于是不再提问，世界也不再提供信息）；② 伪科学（科学术语是伪科学的最强掩护，应把见解“翻译”成日常用语，让提主张的人暴露潜在逻辑）；③ 表面的问题（问谁/是什么/何时只是界定边界，问“为什么”才研究现象如何产生和相互作用）。
  - 第四步，构建思维模型：每个人都可以有自己的视角和观点，费曼的强项是知道何时、如何切换工具。培养元认知——养成审视自己想法的习惯，对自己提出的问题再提问题（比如“看待这个问题的不同方式”），从而拓展思考边界，避免困在狭小的“思维盒子”里。
  - 第五步，输出知识：教学＝沟通，这也是衡量一个人是否擅长教学的尺子；身边不擅长沟通的人往往也不擅长教别人。费曼认为，再复杂重要的事，只要用合适的水平解释，任何人都能理解；解释不通，多半不是内容太复杂，而是自己没彻底掌握。
  - IRADE 教学/表达法：① I 介绍——用描述和故事激发兴趣，把概念与已知事物、与对方的目标联系起来；② R 关联——用现实世界的例子说明概念是什么，至少列三个；③ A 应用——说明这个工具能帮人实现什么目标，用从简到难的实践让人看到用途；④ D 演示——视觉演示更容易记住，做一个小实验或演示，一图顶千言，一次真实演示顶 1000 张图；⑤ E 检验——让学生解释、总结、辩论，或给一个讲过的问题看是否会做，也可以展示错误解法让他们指出错在哪。
  - 收束：观察与学习、用问题引擎找动机、去杂草、构建并审视视角、以教助学——这五步不止是学习方法，更是深度思考的路径。

  【方法/论点要点】
  - 先分类再选型：总体带宽（nload、bmon、slurm、bwm-ng、cbm、speedometer、netload）、批量/可记录输出（vnstat、ifstat、dstat、collectl）、按套接字连接（iftop、iptraf、tcptrack、pktstat、netwatch、trafshow）、按进程（nethogs）。
  - 实现机制不同：nload 等读 /proc/net/dev 拿统计；iftop/tcptrack/trafshow 用 pcap 抓包再汇总，因此能过滤流量但更重。
  - nload：分入站/出站显示并画图，选项少，适合快速看总带宽。
  - iftop：按连接显示带宽，可用 -n 禁止反解主机名（反解本身会产生流量），支持 pcap 过滤。
  - iptraf：交互式、彩色，显示连接与主机间数据量。
  - nethogs：按进程排序显示带宽，能定位「是谁把带宽吃满」，给出 PID、用户、路径。
  - bmon：显示所有接口的负载、图表与包级信息。
  - slurm：ASCII 图形接口负载，c/s/l 切换图形类型，功能简单。
  - vnstat：后台守护进程持续记录，适合出历史报表（日/月），不是严格实时工具。
  - bwm-ng、cbm、speedometer、netload：都是轻量实时总览，差别在输出形式（条形图/仪表/简短报告）。
  - pktstat、netwatch、trafshow：按活动连接显示协议与速率，trafshow 仅 TCP、支持 pcap 过滤。
  - ifstat、dstat、collectl：批处理输出，便于写日志或用其他程序分析；dstat/collectl 还能同时看 CPU、内存、磁盘。
  - 安装：多数在发行版默认源，CentOS 常需 EPEL/RepoForge；文末提醒还有 ntop、darkstat 等 Web 方案与 Nagios 等企业级监控。
