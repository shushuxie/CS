#+begin_src text

对于一个数组和一个指针：

#+end_src

** 如果你仅依据它们

都支持偏移运算：

#+begin_src c

#+end_src

#+begin_src c

#+end_src

#+begin_src c

#+end_src

** 是不是就犯了和刚才整型和浮点型那个问题一样的错误？

同样的，我们也可以靠例举一些数组和指针不同的行为来驳斥这种错误的结论。

---

说到数组和指针的不同，根本地，你只需要掌握这个准则就好：

* 数组是一系列相同类型的元素的集合， *其中存储了这 N 个元素的信息本身**

* 而指针，只不过代表了一种引用， *它只记录了它所引用的内容在内存中的哪个位置的信息**

好，一下子没理解也没关系，我们就带着这个准则，结合具体的例子来领悟。同时，这些例子也很好地展现了两者的一些不同的行为。

*** 1. 通过 sizeof 去计算数组跟指针的尺寸，结果是不同的：

#+begin_src c
#include <stdio.h>

int main()
{
    int a[100];
    int * p;

    printf("%zu\n", sizeof(a));
    // 结果等于 sizeof(int) * 100，如果你的机器上 sizeof(int) 为 4，那么结果就是 400

    printf("%zu\n", sizeof(p));
    // 如果你的环境是 32 位的，那么结果就是 4 (4 个字节就是 32 位)
    // 如果你的环境是 64 位的，那么结果就是 8 (8 个字节就是 64 位)

}
#+end_src

我们可以把这个例子对应着准则来看：

要表达一个 ~int~ 的信息，需要 ~sizeof(int)~ 个字节。显然，一个存储了 100 个 ~int~ 的数组，总共就需要 ~sizeof(int) * 100~ 个字节。

而 32 位机器最多支持的寻址空间是 ~2 ^ 32~ 个字节，要能表示这么大范围的地址空间，需要至少 4 个字节，所以一个指针的 size 就是 4 个字节。

** 2. 数组和指针是不同的类型， *数组就是数组类型，指针就是指针类型**

对于：

#+begin_src c
int a[100];
int * p;
#+end_src

对数组 ~a~ 、指针 ~p~ 分别取地址（ ~&a~ , ~&p~ ），得到的结果是什么类型呢？

对数组 ~a~ 取地址， ~&a~ ， 得到的是一个 *指向数组的指针类型* ~int (*) [100]~ ，这个复合类型是一个指针，指向的元素的类型是一个长度为 100 的数组 ~int[100]~

而，

对指针 ~p~ 取地址， ~&p~ ， 得到的是一个 *指向指针的指针类型* ~int **~ ，这个复合类型是一个指针，指向的元素的类型是一个（指向 int 型的指针） ~int*~

我们可以写个实验验证下：

[Compiler Explorer - C (x86-64 gcc 11.1)](https://godbolt.org/z/xzY9EP549)

#+begin_src c
#include <stdio.h>

int main()
{
    int a[100];
    int * p = a;
    
    int (*ptr_to_array)[100] = &a; // 1
    int ** ptr_to_array2 = &a; // 2

    int ** ptr_to_ptr = &p; // 3
    int (*ptr_to_ptr2)[100] = &p; // 4
}
#+end_src

对于第 2、4 两行，编译器给我们报了一个警告：

[[https://pic1.zhimg.com/50/v2-0768480bcedee584c78850e39ccea217_720w.jpg?source=2c26e567]]

告诉我们， ~int **~ 和 ~int (*)[100]~ 这两个指针类型之间的转换是不兼容的。这么做是会出问题的。这么做在老的 C 语言编译器上，编译器会帮你打个马虎眼糊弄过去。但是在 C++ 里以及从 gcc14 开始，这么写就是语法错误了。

我们还可以做另外一个实验。在这个实验中，由于 C 语言的功能限制，我们不得不转而使用 C 语言的增强版 —— C++ 语言来实现。

[https://godbolt.org/z/c8sbjdYMd](https://godbolt.org/z/c8sbjdYMd)

#+begin_src cpp
#include <type_traits>
#include <stdio.h>

int main()
{
    int a[100];
    int * p;
    if (std::is_same_v<decltype(a), int[100]>) {
        printf("a 是 int[100] 类型\n");
    }
    if (! std::is_same_v<decltype(a), int*>) {
        printf("a 不是 int* 类型\n");
    }
    if (std::is_same_v<decltype(&a), int(*)[100]>) {
        printf("&a 是 int(*)[100] 类型\n");
    }
    if (std::is_same_v<decltype(&p), int**>) {
        printf("&p 是 int** 类型\n");
    }
    if (! std::is_same_v<decltype(&a), decltype(&p)>) {
        printf("&a 跟 &p 不是同样的类型\n");
    }
}

#+end_src

在 C++ 中， ~decltype(表达式)~ 可以推断出表达式的类型，而 ~std::is_same_v<A, B>~ 可以判断 AB 两个类型是否为同一个类型。相同结果为真，不同结果为假。

输出为：

*** 4. 数组中存放了这一系列的元素，而指针只不过记录了位置

我们举一个初学者学到字符串这章时绝对会碰到，但就是一直搞不明白的例子放在这：

[https://godbolt.org/z/16df96oqd](https://godbolt.org/z/16df96oqd)

#+begin_src c
#include <stdio.h>

int main()
{
    char s1[] = "_ is easy or hard, that's not a question";
    printf("%s\n", s1);
    s1[0] = 'C';
    printf("%s\n", s1);

    char * s2 = "_ is easy or hard, that's not a question";
    printf("%s\n", s2);
    s2[0] = 'C'; // 运行到此行发生崩溃
    printf("%s\n", s2);
}
#+end_src

在情况 1 中，我们使用字符数组来表示字符串，修改第 0 位的元素后，程序正常。

而在情况 2 中，我们使用指针来表示字符串，而这一次，当尝试修改第 0 位的元素时，程序发生崩溃了。

为什么差不多的例程，一个就是对的，而另一个就会发生崩溃呢？

很多新生之所以觉得这个例子难，搞不懂这个问题，就是因为他们只看到数组跟指针都支持 "+ [] *" 操作这些共性的部分，而没有彻底搞懂他们的区别。如果你还把数组跟指针当成一回事，那么当然是没法理解这个问题的。

要想搞明白不同的代码，背后究竟做了什么样的事情，最好的做法就是去看编译器生成的汇编。

[[https://picx.zhimg.com/50/v2-bb22f56be18104748d5f3f9792e1bb55_720w.jpg?source=2c26e567]]

在情况 1 中，当声明数组 s1 时，程序是真真正正分配了连续的一二三四五六七 ... 总共 41 个 char 类型的变量在这里的。（注意：这里的字符串长度为 40，但是还包括结尾的 '\0' 千万不要忘了）

当元素分配好后，程序会把 .LC0 和 .LC1 中的数据（也就是等价于 "_ is easy or hard..." 的数据）搬运到数组当中，然后，执行到 ~s1[0] = 'c'; ~ 这一行时，修改了第 0 位的元素。这一切都是没有问题的。

[[https://picx.zhimg.com/50/v2-63f04edf416c8b86704596030415482a_720w.jpg?source=2c26e567]]

而在情况 2 中，编译器把字符串 "_ is easy or hard..." 安排在了 *常量区* 中，即这一段：

#+begin_src nasm
.LC0:
        .string "_ is easy or hard, that's not a question"
#+end_src

当声明指针 s2 时，程序只不过是分配了一个 8 字节的空间（64 位环境下 8 字节；32 位环境下则是 4 字节）。这么小的空间是根本不足以容纳 "_ is easy or hard..." 这个这么长串的字符串的信息的。之前讲过，指针中只是记录了一个位置信息，这个位置就是指针所引用的对象的位置。

当执行 ~char* s2 ="_ is easy or hard...";~ 时，s2 中记录下了那个位于常量区的字符串的位置。向下继续执行到 ~s2[0] = 'c'~ 这一行时， *你就是在要求修改常量区中的数据。而现代的绝大多数的操作系统都会对常量区实施保护，一旦检测到尝试往常量区中写入数据，那么会触发保护机制，程序就立即崩溃了。*

打个比方，上面这两个情况就像：

情况 1：你把别人的作品复印一份，然后自己修改修改 —— 这当然是没问题的；

** 情况 2：你知道别人在某个地方有一份作品，这份作品不属于你，而你去强行改它，你看别人干不干。

** 5. 将数组赋值给指针，是 *类型转换** 的过程，也是类型中长度信息丢失的过程

在 C 语言中，可以把数组赋值给一个指针，也即很多老师会讲的，拿到数组的首地址（数组中首个元素的地址）

#+begin_src c
#include <stdio.h>

int main()
{
    int a[100];
    int * p = a;

    printf("%p\n", &a[0]);
    printf("%p\n", p); // 以上两行输出相同的内容

    printf("%p\n", a + 2);
    printf("%p\n", p + 2); // 以上两行输出相同的内容

    printf("%d\n", a[2]);
    printf("%d\n", p[2]); // 以上两行输出相同的内容
}
#+end_src

* 这个说法本身是没有问题的。但是，正是因为在这里，数组和指针的一系列用法十分相似，导致了很多学生在这里学的稀里糊涂。加之很多庸师（大部分自己也是稀里糊涂），为了学生能应付考试中的数组偏移计算题，就提出了“数组名就是首地址”的 *错误说法** ，让学生强行记忆。然而，这样误人子弟的提法却加深了“数组和指针是一回事”的错误印象。当碰到一些需要充分理解两者之间区别的情况时（就比如上面 4 中的例子），学生反倒是更云里雾里的了。

其实，对于数组可以赋给指针的现象 ~int * p = a~ ，有个更专业的名字， *叫 decay (退化，衰退)* 。

*数组 decay 成指针，其实就是类型转换中的一种* ，而且是损失了信息的转换。由原来等号右边的 ~int[100]~ （带长度信息的数组类型）转换为 ~int *~ 指针类型。在这个过程中，原来蕴含的长度信息丢失了，所以为什么叫退化。

*这同样也可以类比浮点数跟整型之间的类型转换*

#+begin_src c
float a = 3.14;
int b = a; // 结果为 3
// 显式的写法为 int b = (int) a;

float c = b; // 结果为 3
// 显式的写法为 float c = (float) b;
#+end_src

在上面这个例子中，我们把一个浮点型隐式转换成了整型，然后又转换了回去。

在浮点数转换成整型的过程中，小数点后的信息丢失了，哪怕转换回去，丢失的信息也不存在了。

数组的例子是完全相同的道理：

#+begin_src c
int a[100];
int * p = a;
// 同样的，以上只不过是 int * p = (int *) a; 的隐式写法
// 这里有个隐式的类型转换，编译器允许你省略，它能帮你自动补上罢了

// int a2[100] = p; // 错误!
#+end_src

数组类型可以转换为指针类型，跟数值转换的区别只不过是彻底丢失了长度信息后，没法再转换回来罢了。

在上面的整型浮点型互换的例子中， *你肯定能将其归结为类型转换，肯定不会得出“浮点数就是整型”的结论* 。这个道理在数组跟指针间也是一样的，

* 你不能因为数组类型可以转换为指针类型，就得出“数组就是指针”的结论。 *况且，能转换过去，却不能转换回来，就更不能说它俩完全一样了** 。

#+begin_src c
int a[100];

a + 100;
((int *) a) + 100;
#+end_src

同样的，数组所支持的 ~数组名 + 整数~ 操作，无非也可以看成是先发生了一次隐式类型转换，由数组类型转换为了指针类型，然后计算指针和整数的加法罢了。

*** 6. C 语言中的一种特殊情况

在 C 语言中，函数参数列表中的数组记号存在特殊情况。

#+begin_src c
void use_array1(int a[], int n);
void use_array2(int a[100], int n);
#+end_src

** 注意！当作为函数的参数时，无论方括号中带不带长度，以上两个函数的参数列表都与下者是完全相同的！

#+begin_src c
void use_array3(int * p, int n);
#+end_src

是的，只是形式上是数组的形式，但是实际上是指针。

在向这类函数传递参数时：

#+begin_src c
int a[100];
use_array1(a, 100);
use_array2(a, 100);
use_array3(a, 100);
#+end_src

根据我们上面讲过的内容，是的没错，是发生了隐式的类型转换的：

#+begin_src c
int a[100];
use_array1((int *)a, 100);
use_array2((int *)a, 100);
use_array3((int *)a, 100);
#+end_src

至于怎么检验，也可以使用我们之前介绍过的两种方法：计算 sizeof 或者判断类型

#+begin_src c
#include <type_traits>
#include <stdio.h>


void use_array(int a[])
{
    printf("a 的大小为: %zu\n", sizeof(a)); // 结果与指针类型相等
    if (std::is_same_v<decltype(a), int *>) {
        printf("a 的类型为 int *\n");
    }
}

int main()
{
    int a[100];
    use_array(a);
}
#+end_src

这也是为什么如下例子中：

#+begin_src c
void use_array(int a[100])
{
    printf("len: %zu\n", sizeof(a) / sizeof(a[0]));
}

int main()
{
    int a[100];
    printf("len: %zu\n", sizeof(a) / sizeof(a[0]));
    use_array(a);
}
#+end_src

在主函数中使用 ~sizeof(a) / sizeof(a[0])~ 可以正确计算得到数组的长度，而在 ~use_array~ 函数中，得到的会是错误的结果（因为 sizeof(a) 计算出的是指针的大小）。

*** 7. 二维数组传递

如何向函数传递二维数组，通常也是很多 C 语言初学者觉得困难的问题。像这样的写法是无法通过编译的：

#+begin_src c
void use_2d_array(int a[][], int row, int col)
{
}

int main()
{
    int a[3][4];
    use_2d_array(a, 3, 4);
}
#+end_src

我们还是把问题类比到一维的情况，就可以很容易地理解这个问题。

当数组是一维时， ~int[100]~ 类型退化成了 ~int*~ 类型：

#+begin_src c
void use_array(int * p, int n);

int main()
{
    int a[100];
    use_array(a, 100);
}
#+end_src

~float[100]~ 类型退化成了 ~float*~ 类型：

#+begin_src c
void use_array(float * p, int n);

int main()
{
    float a[100];
    use_array(a, 100);
}
#+end_src


 那么，什么是二维数组？

二维数组当然就是数组的数组。

比如三行四列的数组 ~int[3][4]~ ，就是一个有着三个元素的数组，里面的每一个元素都是 ~int[4]~ 数组类型。

~int[100]~ 数组类型中，数组中的每一个元素都是 ~int~ 类型，那么数组可以退化成指向 ~int~ 的指针类型 ~int*~ 。

~float[100]~ 数组类型中，数组中的每一个元素都是 ~float~ 类型，那么数组可以退化成指向 ~float~ 的指针类型 ~float*~ 。

那么显然地，

~int[3][4]~ 数组类型中，数组中的每一个元素都是 ~int[4]~ 类型，那么数组可以退化成指向 ~int[4]~ 的指针类型 ~int(*)[4]~ 。

理解清楚其中的逻辑，一切也就不难了。

因此，向函数传递二维数组时，参数列表中一定需要指定数组的列长度：

#+begin_src c
void use_2d_array(int a[][4], int row)
{
}

// 或者写成指针的形式，也是可以的
void use_2d_array2(int (*a)[4], int row)
{
}

int main()
{
    int a[3][4];
    use_2d_array(a, 3);
    int b[4][5];
    use_2d_array(b, 4); // 错误！
}
#+end_src

而且，传递进去的二维数组，也必须是正好为 4 列的二维数组。

比如在上面的例子中，向 ~use_2d_array~ 函数传递 ~int[3][5]~ 就是不行的。

原因之前我们也是谈到过的：

** 数组的长度是数组类型信息的一部分，不同长度的数组有着不同的类型

这样的错误，就跟下面的这个错误，是一样的。

一个函数，明明要求的是 ~int~ 类型的数组，但是你却给了它一个 ~float~ 类型的数组，这肯定是不行的。

#+begin_src c
void use_int_array(int a[], int n)
{
}

int main()
{
    float a[3];
    use_int_array(a, 3);
}
#+end_src
