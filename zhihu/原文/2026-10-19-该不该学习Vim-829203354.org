我觉得正确态度是，无所谓“该不该”。如果你问我“学vim好不好“，我会说”好“。如果你问我”不学可不可以“，我会说”可以“。我身边一大群用vim就只会进插入模式然后当记事本用的人都活得好好的，完全不妨碍他们出活升职加薪跳槽。所以你说“有没有必要”，答案是“没必要”。别人看到你用vim会不会对你高看一点，也许有些会，但一般不会。

不过既然问题是“有什么无法替代的优点”，那我可以说说我所理解的优点。但是有这样的优点，不代表我劝你去用。肯不肯忍受大概一个月的低效率工作（可能导致加班）去尝试是你自己的选择。

首先，vim的操作方案是一套经过时间证明的，不用考虑“易上手”而纯粹考虑“高效率”的文字编辑方案（之一）。我这个人从来不相信什么“又便宜又好吃”的说法，一个东西你要么说它便宜，要么说它好吃。你妈妈买回来一个“又便宜又好吃”的东西，那多数就是“便宜里面比较好吃”的。同样我也不相信“又容易上手效率又高”的方案，那多数是“容易上手的方案里效率比较高”的。你可以想想，容易上手的编辑方案为什么容易上手？因为它跟你刚刚接触电脑时首先接触的操作系统的默认操作方式一脉相承。而在你刚刚接触电脑时，易学性重要还是操作效率重要？作为入门小白，不易上手的操作系统都被我们抛弃了。所以最后能活下来成为我们日常桌面的操作系统，都是“易学性好里面效率比较高”的方案。而所谓的“现代编辑器”全部都陷在这个魔咒里，你要是不向“易学性”妥协，一味追求“高效率”，根本就无法在立项初期吸引大量用户流行起来。但你如果说一套面向所有用户的，易上手的方案，刚好又是一套面向专业人士效率最高的方案。不知道你信不信，反正我是不信的。唯有vim和emacs这种上古异类，在它们出生的年代，没有鼠标没有图形界面，键盘上甚至没有方向键，用户又都是名副其实的极客。才有机会打破这种“易学”模式，专心冲着“高效率文字编辑”这个单纯的目标去演化。

（为了避免出现杠精，特意预先说明一下，“又易学效率又高”，只是很罕见，不是完全没有。通常发生在基础设施出现根本性变革的时候，比如屏幕键盘代替打孔机。鼠标和图形化界面还达不到这个层次）

所以有些人说vim和emacs过时了，新时代有新的操作方式，有新式的编辑器。这种说辞打动不了我（注意，我没说这不对，我只是说不能打动我）。“新操作，新编辑器“，恰恰都受到了”计算机普及到非技术市场，所以对初学者的易学性非常关键“这个新需求所累。当然，如果你说，你的时间很宝贵，生命中每一个月都在做非常有价值的事情，不值得浪费这样一个月去学一套基本上不会过期可以用一辈子的高效率编辑方案。我觉得确实也是有道理的，所以完全是看个人的选择。

其次，vim的操作方式可以用到各种软件上，基本上各种可扩展的开发工具都有人为它们写vim插件。本质的原因是因为vim的用户群就是具有给其他软件写插件的能力（只要你这个软件是可扩展的）。有人说过（真的不是我），如果一个开发工具或者编辑工具上没有vim插件，那说明它要么不可扩展，要么还不够流行，没必要去用（除非不得不用）。vim的操作方式并不会占有大量“修改键+字母“的快捷方式，不会与大部分软件的原有快捷按键冲突。有的vim插件还支持把软件本身的功能映射成vim的按键组合。所以，以vim的操作方式作为核心，你事实上可以无痛在各种流行的编辑器和开发环境之间切换，简直是开发界的乾坤大挪移。我在前东家的时候，整个公司都在用eclipse，只有我一个人在用intellij。但只需要我在intellij里和同事eclipse里都装vim插件，我日常随便去其他同事的eclipse上结对编程一下，非常流畅。

下图是2019年9月19日的intellij插件下载数排行，vim插件排在第七（6百万次下载）。可见有不少人是用vim的操作方式来使用intellij的。

[[https://picx.zhimg.com/50/v2-784159429a99f019740d3fdf9da3fe56_720w.jpg?source=2c26e567]]

所以不要说用vim的人老古董，事实上每次有大厂的新编辑器出来，公司都是我这个死硬vim党先去尝试，发现好用再推荐给公司里的同事。我给同事推过sublime，推过atom，推过vs code。因为这堆东西都有vim插件，我随便装一个用个一两星期把玩一下毫无压力。

至于学习曲线，其实并没有那么陡峭，因为你要恢复到“用其他编辑器的输入速度和使用常用的编辑功能“，其实最多两个星期。后面的高级内容都是vim的特有功能，你投入的时间是赚来的新技能，并不应该拿来跟没有这些功能的其他编辑器去对比。

其次是选好一个退出插入模式的方案。许多初学者被劝退就是因为模式切换要频繁按ESC。可以考虑在插入模式下把jk连按映射为ESC，或者把ctrl-k映射为ESC。

题外话，当年初学时差点把我劝退了的第二大坑居然是j和k谁是上跟下。后来我的记忆法是中指比食指长（高），所以动中指就是向上，动食指就是向下。另外，你想想咱们日常竖个友善度中指，也是中指向上，就豁然开朗了。据我所知，也有一些程序猿记成嘴巴（kou）在上，老二在下（jiji）。仅供参考。

接下来用一个星期时间达到“不需要频繁使用hjkl移动光标，进入插入模式后基本上不需要按箭头和退格键（可以用退格键删掉刚刚输错的一两个字符）”的状态。其实只需要掌握以下知识：

#+begin_src text
各种action + text object 组合命令（自己上网查定义）：
ciw, caw, ci", ci(, ce, diw, daw, =i(, viw, vi(, df. 等等

:数字 （或者 数字G）跳到指定行
w, W, e, E, b, B, ge, gE, 0, 0w, $  (光标移动）
gg, G, <ctrl-f>, <ctrl-b>, <ctrl-d>, <ctrl-u> (各种翻页）
zz, zt, zb, <ctrl-e>, <ctrl-y>  (光标不动调整页面位置）
H，M, L   （页面不动调整光标到页面的上中下部）
i, I, a, A, s, r, R, cc, o, O, gi, c+text object  (各种进入编辑模式的方法）
v, V, ctrl-v, gv  (各种选中方式）
x, dd, D, d+text object  (各种删除)
ctrl-w （插入模式下删除一个词）
u (undo), <ctrl-r> (redo)
f, F, t, T, ;(分号) (当前行内找字符）
/ (查找） ? （反向查找）
* （查找光标所在单词）  # （反向查找光标所在单词）
n （查找下一个）  gn （查找下一个并选中）
:s/查找内容/替换内容/g   (查找替换)
:s/查找内容/替换内容/gc   (带确认的查找替换)
y （复制）  p （粘贴到光标之后）  P （粘贴到光标之前）
yy （复制一行）
"0p (指定粘贴用y复制的内容。不使用"0 (双引号+0）指定的话，p会复制最后一次用y复制或者删除的内容）
<ctrl-r>0 （插入模式下粘贴）
.(小数点) （重复上一次的编辑命令）
#+end_src

基本上熟练使用和组合以上的命令，你就能在vim内恢复到使用其他编辑器的正常输入水平了。后面的都是赚的了。所谓组合就比如说，“在当前词的后面插入”这个需求，你不要想着先e移到单词尾部，再a进入插入模式，而是直接记成要在当前单词尾部加东西，就按“ea” （记为“End Append”，要在单词前面加东西，就按“bi” （记为 “Begin Insert”）。再比如，调换相邻两个字符，直接就记成“xp”；同理，调换上下两行，直接就记成“ddp”。

但是，万一你真的入了坑，真的上了手，记住“办公室vim党第一原则”， *不要试图推广，不要试图推广，不要试图推广* 。“办公室vim党第二原则”， *不要试图装逼，不要试图装逼，不要试图装逼* 。低调自爽就行。别人来你这边结对，老老实实用hjkl挪光标，不要直接跳来跳去。要做什么操作，先选中停半秒再做，不要直接用text object搞，人家根本不知道你在搞什么（对方可能对此表示震惊佩服，然后从此再也不找你结对，并且今后对你程序里的一些低级错误特别关注）。把键盘给别人用之前，自己用快捷键关掉vim插件，不要让别人来你这里一开搞就光标乱飞。否则别人去吃午饭都不叫上你可别怪我没提醒。
