  【方法/论点要点】
  - 路径一：本地音乐导入 Apple Music（Windows 10）。
  - ① 打开微软商店：按 ~Win + Q~ 搜索“商店”。
  - ② 下载 Apple Music。

  【方法/论点要点】
  - 线条控制最终服务于三件事：形状、光影、质感。
  - 外形线条：直线与曲线，准备 4 个 5×5cm 格子，线距 1~2mm；眼睛别盯笔尖，要盯着两侧参考线。
  - 斜线先画中间一根作参考，再平行补两边；曲线练不同方向的椭圆，慢画、边画边判断调整。
  - 短线动手腕，超过 5cm 的长线改动手肘。
  - 光影线条：4 个 1.5×7.5cm 长条各分 5 格，用「叠加层数」或「改变疏密」两种方法做出 5 个色阶。
  - 质感四类：蓬松＝小曲线，柔软＝悠长完整的大曲线，坚硬＝规整直线或弧线，粗糙＝短小转折线。
  - 在球体上画线条要用「包裹式」贴上去，才符合朝向规律。
  - 收尾作业：4 个 4×4cm 质感方格；画树枝先画前面几棵粗树，再补中间，最后加远处细树。

  - 本地原文：[[file:原文/2026-10-27-如何在 clion 运行多个 main 函数.org][打开本地归档]]
  - 一句话概括：解决 CLion 里一个项目多个 cpp 各带 main 的编译冲突：用 CMake 的 file(GLOB) + foreach 自动为每个 cpp 生成可执行文件，新增文件后 Reload CMake Project 即可；值得收是因为它把「每写一题改一次 CMakeLists」变成全自动，还附带了子目录递归写法。
  【方法/论点要点】
  - 报错原因：一个 target 只能有一个 main，多个 cpp 直接 add_executable 会冲突。
  - 笨办法：手动为每个文件补一行 add_executable(a a.cpp)。
  - 正确做法：file(GLOB files *.cpp) 遍历，foreach 里用正则取出文件名当 target 名。
  - 新建 cpp 后按两次 Shift 输入 reload，执行 Reload CMake Project，main 旁就会出现绿色运行按钮。
  - Auto-Reload 只监听 CMakeLists.txt 的修改，新建 cpp 不会触发，别指望它。
  - 子目录：file(GLOB files test/*.cpp) 或 *.cpp */*.cpp；官方递归写法是 file(GLOB_RECURSE files *.cpp)。
  - 想在运行框显示「文件夹/文件名」，可用两级正则替换，但排序可能会乱。
  【原文摘录】
  #+begin_quote
  之前这里写了一个小程序解决这个问题，就是就是读文件名写字符串。因为 Clion 使用的是 CMAKE 来管理编译执行，所以在其中加入对应的 add_executable(a a.cpp) 即可。
  #+end_quote
  #+begin_src text
  file (GLOB files *.cpp)
  foreach (file ${files})
      string(REGEX REPLACE ".+/(.+)\\..*" "\\1" exe ${file})
      add_executable (${exe} ${file})
      message (\ \ \ \ --\ src/${exe}.cpp\ will\ be\ compiled\ to\ bin/${exe})
  endforeach ()
  #+end_src
  #+begin_quote
  在新建对应的 xx.cpp 文件之后，创建 main 函数，在项目处右击，选择 Reload CMake Project，在 main 函数旁边就会出现那个绿色的运行按钮了（快捷操作，按两次 shift，输入 reload，就会出现选项）。
  #+end_quote
  #+begin_quote
  之前尝试过 Auto-Reload CMake Project 选项，但是作者发现该选项应该是监听 CMakeLists.txt 文件修改的，在创建新的 cpp 文件后应该不会自动 reload，所以没有用这个功能。
  #+end_quote

  - 方案三 Redis SETNX：以业务唯一字段为 key，设置成功是首次，失败即已执行，记得设过期时间。
  - 其他：状态机、悲观锁、乐观锁；转账、支付这类涉及钱的接口尤其要优先考虑幂等。

  - 一句话概括：把 Java 泛型里最容易混的几组东西拆开讲清楚：T/E/K/V/? 的命名约定、? extends / ? super 的读写差异、T 与 ? 的四点区别，以及 ~Class<T>~ 与 ~Class<?>~ 在反射里的用法；值得收是因为每一条都配了会编译失败的反例。
  【方法/论点要点】
  - 泛型的本质是参数化类型，价值在编译期做类型检查，并把强制转换变成隐式自动的。
  - 命名约定：~?~ 不确定类型，~T~ 具体类型，~K V~ 键值，~E~ 元素——只是约定，换成 A-Z 任意字母程序照跑，只影响可读性。
  - 无界通配符：方法参数写成 ~List<? extends Animal>~ 时，传 ~List<Dog>~ 能编译；写成 ~List<Animal>~ 就报错。通配符在声明局部变量时几乎没意义，用在方法形参上才关键。
  - 上界 ~? extends E~：类型必须是 E 或其子类，好处是「传错编译不过」＋「可以直接调用 E 的方法，不用强转」；类型参数可以多重限定 ~<K extends A, E extends B>~。
  - 下界 ~? super E~：类型必须是 E 或其父类，典型用法是把 src 的元素灌进 dst（~List<? super T> dst, List<T> src~），因为 dst 的范围「大于等于」src 才装得下。
  - T 与 ? 的核心差别：T 可以被操作（~T t = operate();~），? 不行（不能声明 ? 变量），所以 ? 只能出现在调用代码和形参里，不能用于定义类或泛型方法。
  - 区别一，一致性：~<T extends Number> void test(List<T> dest, List<T> src)~ 能保证两个 List 元素类型相同；两个 ~List<? extends Number>~ 则不能，进到方法体里照样要转型。
  - 区别二，多重限定：类型参数能用 ~&~ 设多重边界，通配符不行，因为它不是确定类型。
  - 区别三，下界：类型参数只有 ~T extends A~ 一种限定，通配符有 extends 和 super 两种。
  - ~Class<T>~ vs ~Class<?>~：反射里 ~Class.forName(...).newInstance()~ 若不转型，运行期才抛 ClassCastException；用 ~Class<T>~ 可以把检查提前到编译期。~Class<?>~ 可以直接声明字段，~Class<T>~ 只有当所在类本身带 T 时才能用。

  #+begin_quote
  T 是一个 确定的 类型，通常用于泛型类和泛型方法的定义，？是一个 不确定 的类型，通常用于泛型方法的调用代码和形参，不能用于定义类和泛型方法。
  #+end_quote
  #+begin_quote
  但是通配符 ? 可以进行 两种限定：? extends A / ? super A
  #+end_quote
  【我的想法】
  这篇的优点是反例驱动：每个概念都给一段「这样写会飘红」的代码，比只背定义有效。但它没点出这整套规则的正式名字——PECS（Producer Extends, Consumer Super），也就是「只读用 extends、只写用 super」，记住这一条比记六个区别更省事。另外两处缺失：一是类型擦除完全没提，而 ~List<String>~ 和 ~List<Integer>~ 在运行期是同一个类，这正是「泛型不能 new、不能 instanceof、不能是基本类型」的根源；二是 ~List<?>~ 不等于 ~List<Object>~，前者不能 add（null 除外），后者可以，这点在实际排错时最常踩。文中「通配符在声明局部变量时没意义」说得略绝对，声明 ~List<? extends Number> nums~ 至少能防止你往里乱 add。

  【方法/论点要点】
  - 适用场景：多个互相独立的「是/否」状态要存进同一个整数。
  - 优点：省内存、判断快，且是成熟的编程定式，可读性好。
  - 常量定义：每个常量只有一位是 1——~PROGRAMMER=1(0001)~、~GAMER=2(0010)~、~OTAKU=4(0100)~、~MAN=8(1000)~，所以必须是 2 的 n 次方。
  - 存：用按位或把标签拼起来，~zhang = PROGRAMMER | GAMER | OTAKU | MAN~ 得 15，~liu = GAMER | OTAKU~ 得 6；比直接写魔数 15 / 6 直观。
  - 查：用按位与，~if ((zhang & PROGRAMMER) != 0)~——用常量把不关心的位「遮掩」掉，只看目标位是否为 1。
  - 可持久化：拼出来的整数可以直接存配置文件和数据库。
  - 同源应用：子网掩码判断是否同一子网、Linux 传统 rwx 权限（4/2/1）。

  对于多个可以用「是」「否」来定义的状态，可以使用「掩码」的方式把它们保存在同一个整数中。

  可以看到，换算成二进制后，每个数字都只有一位是1，其余位都是0。这样，我们只用四位二进制数就可以表示一个人是否具有四种不相关的特质。
  #+end_quote
  #+begin_quote
  即用「按位与运算」，使用常量「PROGRAMMER」将不关注的位遮掩掉，只判断我们关心的「2的0次方」那个二进制位，这种操作，被习惯性称为掩码操作。
  #+end_quote
  #+begin_quote
  在指定计算机网络地址时，需要指定的「子网掩码」，便是用掩码的原理，来判断计算机是否属于某个子网。另外Linux传统的rwx文件权限也是同样的原理。

  这是那种「一页纸解决一个具体困惑」的好短文：先说现象（为什么都是 2 的 n 次方），再给二进制解释，最后落到两个真实系统（子网掩码、rwx 权限），链条完整。可以补充的是工程上的几条纪律：常量应该用 ~1 << n~ 而不是硬写 1/2/4/8，超过 31 位要用 ~long~（Java 的 int 只有 32 位，~1 << 31~ 会变负数），判断多用 ~(x & FLAG) != 0~ 而不是 ~== 1~（避免把组合值判错），以及 Java 里更现代的做法是 ~EnumSet~——可读性和类型安全都更好，掩码留给协议、权限位这类必须紧凑的场景。

  - 新手墙＝技术不熟＋心理畏惧，两者互相拖累，越拖越不敢开。
  - 先立一条安全习惯：~脚跟不动脚尖动，脚跟放在刹车下~——右脚跟固定在地板，脚尖左右偏去踩刹车/油门，平时脚停在刹车位以缩短反应时间；这是防「油门当刹车」最直接的办法。

  - 五个必练项：熟悉车宽/车长与前后左右的距离感、停车（竖向＋侧方）、坡道起步（手动挡必练，地库和引桥都会遇到）、平顺刹车（从踩下到停住都不让人前倾）、窄路转弯（内轮差与盲区）。
  - 练车杆练法：两根杆，练空间感时间隔 2.5–2.2 m（后视镜宽＋30 cm），能穿过不碰就逐渐收窄；一根杆当转弯角练左右前后；两根杆摆成车长＋1 m 模拟侧方停车。关键动作是「在重要位置停住、下车看误差」，2–3 周内多次练、每次不低于 1 小时、间隔不超过一周。
  - 上路从易到难：家附近空旷路段 → 易堵路段/环路/快速路（限速由低到高）→ 山路 → 夜间 → 雨雪雾 → 高速；每种路况先查注意事项再上路，并做针对性车况检查。
  - 速度：慢是相对的，「最安全的速度是当前车流的平均速度」，高速上大家 100 你开 60 只会增加被追尾风险。
  - 跟车用秒距不用米：前车经过某点时开始默数，自己到达该点的秒数就是秒距，新手保持 3–4 秒；默数节奏可先用手机秒表校准。
  - 好习惯：变道转弯「一看二灯三转」（先看后视镜、再打灯、再动方向）；转弯全程分阶段观察（转前看左前、转到一半看右、快转完再看右左），A 柱挡视线就伸脖子。
  - 防御性驾驶＝随时准备应对突发；可量化指标是「同里程下的急刹次数」，应随经验增加而下降（可放一瓶水在副驾做提示）。
  - 交规要点：认清主标识、早看限速、早选车道避免压实线、变灯距离不够就停不要抢、停车找正规停车区；驾照不满一年不能独自上高速。
  - 心态：紧张要控制在适度区间（太松也危险）；怕被按喇叭就贴新手标、不违规就按自己节奏开；警惕「熟能生巧也生骄」，高速重大事故很大比例出在 6–7 年驾龄；原则是「宁让莫抢」。
  - 辅助系统：ADAS 的车道偏移、前碰撞、行人碰撞预警对新手有用，但不能依赖，「人工智能，能人所不能，但绝非无所不能」。
  - 独家方法：想象训练——闭眼模拟起步、换挡、转弯，练车当晚再回想一遍；也可用来预演爆胎等突发处置。写总结——记录每次的失误与教训，下次练车前回看，形成自己的素材库。

  【方法/论点要点】
  - 查文档：normal 模式按 gQ 进入 VimScript 交互环境；:h <关键词> 查内建帮助。示例里 <符号> 是占位符，正式使用要替换掉尖括号。
  - 变量：let 赋值、unlet 删除、unlet! 忽略不存在的错误。函数外初始化默认全局，函数内默认局部；显式前缀 g:/a:/l:/b:/w:/t:/s:/v: 分别对应全局、参数、函数局部、buffer、window、tab、脚本、Vim 内部变量；$name 读写环境变量，&option 读写选项。
  - 类型：Number（32 位有符号）、Float（需 +float）、String、Funcref（变量名必须大写开头）、List、Dictionary；没有布尔类型，0 为假、非 0 为真，字符串转整数时多数变 0；Vim 8.1 起有 v:true/v:false。整体是动态弱类型，1 . "foo" 得 "1foo"，1 + "1" 得 2。
  - 比较：==、!=、=~、!~，后缀 # 区分大小写、? 忽略大小写；ignorecase 会影响默认行为，用后缀明确指定最稳。字符串连接用点号。
  - 流程控制：if/elseif/else/endif、for…in、while、try/catch/finally；for 可以直接解构 [var1, var2]。
  - 函数：function! 定义并允许覆盖，函数名必须大写开头；delfunction 删除，call 调用；... 可变参数用 a:1、a:2、a:0 访问；加 range 关键字可让函数只调用一次并用 a:firstline/a:lastline 取范围。
  - 面向对象：没有原生类，用字典 + dict 关键字把 self 暴露出来；实例化用 deepcopy() 拷贝字典。
  - 延伸资源：Vim 中文帮助 usr_41、lymslive 的《Vim 脚本指北》、vim-china 的脚本风格指南。
