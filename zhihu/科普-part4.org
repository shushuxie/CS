  - 一句话概括：从神经科学实验证据论证人类采用十进制不是因为十根手指，而是由短时记忆的「4 组块容量」和「逢五变符」原则决定的，长几根手指都改不了。
  【方法/论点要点】
  - 进制由短时记忆容量决定，而非手指数：~人类选择十进制不是因为十根手指，而是因为人类的短时记忆容量为4~。
  - 4 是精确分辨的上限：≤4 个物体能瞬间分辨，>4 就必须一个个数；~人类数数一定是4个为一组~。
  - 超过 4 就要换符号，所以一切计数手段「逢五变号」：算盘逢五进一、罗马数字 V、玛雅数字、语言中 5 的倍数嘴型不同。
  - 字符容量上限推出可能进制：4 个相同字符（如 ~VVIII~ 已爆内存）使实用上限落在 12，又必须是 5 的倍数，只剩 5 和 10；而短时记忆上限为 9，所以十进制的记忆效率优于五进制。
  - 结论：~人类就是长37个指头，只要神经系统不变，最适合和最流行的也仍然是十进制。~
  - 英语 eleven/twelve、法语 11-16 的「特殊」数字并非特殊，源头是「十加一」「十加二」等组合（拉丁语 undecim、duodecim 等），本质仍是十进制变体或与二十进制的混合。
  - 反例证据：只有 1-4 有精确数值的蒙杜鲁库人用十根手指也发展不出进位，10 以上无法用手指表示；用不用手指对儿童解题准确性无显著差异。
  - 4 组块能力可能起源极古老：猴、乌鸦、蜜蜂都只能数到四，或可追溯到五亿年前四辐对称的水母（化石 Auroralumina Attenboroughi，意为「黎明提灯」）。

  - 本地原文：[[file:原文/2026-10-19-请问如何理解极限的精确定义-3331035721.org][打开本地归档]]
  - 一句话概括：从数学史（无穷小危机到柯西、魏尔斯特拉斯）和「任意／存在」逻辑语言出发，一步步拆解极限的 ε-δ 与 ε-N 精确定义，并给出用「误差容忍值」直观理解的方法。
  【方法/论点要点】
  - 教科书难懂有两个原因：一是极限理论牵连着数学史难题「无穷小究竟是什么」，牛顿、莱布尼兹、欧拉都没解决，直到柯西定义、魏尔斯特拉斯用 ε-δ 完善；二是初学者不熟悉 *任意*、*存在* 这类逻辑语言，需要长期训练。
  - 历史回顾：高中求瞬时速度时把 Δt 先放分母、后令其「趋于零」，~那么 Δt 究竟是不是零呢？这个问题曾经困扰着无数的数学家~，这即「第二次数学危机」。柯西 1821 年定义「变量的极限」并把无穷小定义为极限为零的变量，魏尔斯特拉斯补上 ε-δ 严谨定义。
  - 定义前先分清两种「无限接近」（自变量、因变量），二者有因果关系，必须分开处理。
  - 自变量的「无限接近」化为逻辑语言：数列是「存在自然数 N，使对所有 n≥N 成立 P(n)」；函数是「存在 δ>0，使对所有满足 0<|x-a|<δ 的 x 成立 P(x)」，其中 {x: 0<|x-a|<δ} 是「去心邻域」，且要求 f 在 a 的某去心邻域有定义。
  - 因变量的「无限接近」用「对任意 ε>0 都有 |x_n−A|<ε」表述；关键结论是非负实数比任意正实数都小则必为零，~不可以把它换成"存在"~。
  - 合并后的数列极限定义：设 (x_n) 为实数列，A 为实常数，若 ~对任意给定的 ε>0，存在自然数 N，使得对所有满足 n≥N 的 n 都成立 |x_n−A|<ε~，则称 (x_n) 收敛于 A。
  - 函数极限定义：设 f 在点 a 的某去心邻域有定义，若 ~对任意给定的 ε>0，存在 δ>0，使得对所有满足 0<|x-a|<δ 的 x∈X 都成立 |f(x)−A|<ε~，则称 A 是 f 在点 a 的极限。
  - 直观理解——误差容忍：给定任意误差容忍值 ε>0，总能找到足够大的 N（或控制自变量误差的 δ），使后续项（或邻域内的函数值）误差都小于 ε。

* 为什么凤是雄鸟，而结婚的时候却称"龙凤呈祥"?  :科普:语言学:文化史:龙凤:

  - 本地原文：[[file:原文/2026-10-19-为什么凤是雄鸟而结婚的时候却称龙凤呈祥-2878470200.org][打开本地归档]]
  - 一句话概括：从联绵词（凤凰先秦写作「凤皇」）与龙凤意象的历史演变出发，说明「雄凤雌凰」是后起的合理想象「二创」，而「龙凤呈祥」本是龙凤两瑞兽并用的「原著」，元明清皇家垄断后才逐渐变成夫妻隐喻。
  【方法/论点要点】
  - 核心结论：~先有的"凤凰"，后有的"雄凤雌凰"一说~，明清皇家垄断龙凤意象后，~"龙凤呈祥"从一开始的瑞兽送贺逐渐变成了对夫妻的隐喻~。
  - 联绵词：双音节、不能拆成单字理解，如葡葡般「葡」「萄」，名词凤凰、鸳鸯、麒麟、蝴蝶、蟑螂、蜘蛛，动词彳亍、踯躅、踌躇，形容词参差、忐忑、崎岖；训诂有「逶迤八十三形，崔嵬十有五体」之说，同一词可变多种写法（逶迤=委蛇/委它，崔嵬=崔巍）。
  - 凤凰同理是联绵词，先秦写作「凤皇」，凰是后造字，~皇是雌鸟？没道理对不对~；高频词会被人挑一个字代表整体（凤、麟、蝶、蟑、蛛，如同今互联网用「尬」代表「尴尬」）。
  - 「雄凤雌凰」是古人在已有基础上的合理想象，最著名是司马相如《凤求凰》，~它终究只是一个二创~，不能拿二创去质问原著（类比对哪吒不同版本设定的冲突）。
  - 龙凤呈祥才是「原著」：用龙、凤两种瑞兽表示吉祥，有商代「龙凤冠人形玉佩」为证，后加两瑞兽成四瑞兽而龙凤雷打不动；战国亦有「人物龙凤帛画」。
  - 秦汉龙渐成帝王象征：秦始皇并非自称「祖龙」（「今年祖龙死」是谶语，他还说「祖龙者，人之先也」），黄帝则被龙迎上天，此后皇帝多以龙自比，凤渐用于女眷，但尚无清朝式「龙即帝王、凤即皇后」的完全等价。
  - 凤代表女性的苗头来自神话：西汉萧史弄玉（乘金龙/骑彩凤成仙，使龙凤呈祥变成庆祝新婚之词）与晋朝西王母神话（「西王母乘翠凤之辇」）。唐仍无官方限制，李世民作《威凤赋》自比（被戏称李二凤）。
  - 男龙女凤更可能是民间神话发展：宋《太平广记》以凤冠写仙女首饰，后世话本中凤冠霞帔成女性贵人标配。
  - 真正的「龙为帝王、凤为皇后」不过元明清三代：元代禁民间用龙凤纹，明洪武进而禁止王族以外使用；但明永乐皇后仪冠是「九龙四凤冠」，定陵出土四顶龙凤冠（三龙两凤、十二龙九凤、六龙三凤、九龙九凤）。
  - 清朝才明确皇帝为龙、皇后（太后）为凤：民间小说以「凤体」称皇后太后（《七侠五义》《狄青演义》），清皇后仪冠变为单纯凤冠，但礼服上仍织龙纹。
  - 附论「翟鸟」（雉鸡）：清以前皇后服饰用翟鸟纹饰（《周礼》三翟），清礼服主题变为龙与凤，翟鸟成陪衬，后宫等级越低凤凰越少、翟鸟越多。
  - 清末民国该图样流入民间：《儿女英雄传》写安龙媒（两妻金凤、玉凤）「龙凤合配」；《两晋演义》写帝后「乾坤合德，龙凤呈祥，恩爱缠绵」。

  - 一句话概括：按需求演进史从 MAC 地址、集线器、交换机讲到路由器与家用网络结构，说明交换机在局域网内靠 MAC 转发表点对点通信、路由器靠 IP 完成跨网段通信，而家用「路由器」其实内置了交换机。
  【方法/论点要点】
  - MAC 地址起源：电脑少时为了相互通信需要身份标记，于是有了全球唯一、类似身份证的网卡序列号，即 MAC 地址。
  - 集线器：为多机通信发明的星型交换中心，两个缺点——任两台通信时其他电脑不能通信，且像喇叭一样把消息广播给所有接口（「有一个网卡地址为macA的电脑A发送了一条信息给网卡地址为macB的电脑」）。现已基本废弃。
  - 交换机：能自动学习，~把交换机这个端口与接入这个端口的电脑的mac地址形成MAC地址转发表的一条新的记录~，于是接入的电脑可点对点通信且不干扰他人；~交换机里面没有网卡，只有端口~。
  - 路由器：全世界电脑全连一个大交换机不现实，于是把网络分成片区/网段并给每台电脑分配网段内的 IP 地址；IP 主要用于在公网上转发数据包。数据包请求头带源/目标 IP，路由器依据 IP 映射表看目标属哪个网段，转发到下一跳路由器（类比快递员与集散中心看邮编/省份）。总结：~路由器的作用就是为了完成跨网段通信~。路由器有多个 WAN 口、每个 WAN 口都有网卡。
  - 家用设备真相：~家里面的上网设备虽然叫路由器，但是实际上，并非是一个单独的路由器，而是由一个路由器加上一个交换机组成的小型具有网络转发功能的设备~。WAN 口是路由器的外端（有网卡，有 IP 和 MAC 两种属性），其内端接内置交换机，LAN 口和无线设备都接在这个交换机上，从而组成同一网段的局域网；~我们常说的网关就是封装在里面的路由器的端口的网卡的ip地址~。
  - 两种上网路径：一是目标与自己在同一局域网——发 ARP 广播问目标 IP 的 MAC，然后以 MAC 通过内置交换机通信；二是目标不在同一网段——ARP 解析出网关 MAC，把数据帧经内置交换机转发到网关（内置路由器内端），再由 WAN 口转发上公网，按目标 IP 网段转给下一路由器。~在互联网的公网上面进行数据传递……公网上只有路由器，没有交换机~，交换机只存在于局域网。
  - 光猫：只起模拟信号转数字信号的作用，~可以当猫不存在~（有些设备把光猫集成进家用路由器）。
  - 总结对比：功能上——路由器依赖 IP 实现跨网段通信并分配局域网动态 IP，交换机靠 MAC 地址转发表在本地局域网工作；结构上——路由器有网卡、交换机没有，有的路由器自带类似交换机的接口；公网主干上的路由器流量大，WAN 口多用串口。
  - 补充问答：既然 IP 唯一为何还要 MAC？因为二者定位不同——IP 为跨网段通信（也可用别的方式，只是 IP 普及），MAC 为两个 MAC 地址直接通信且全球通用。
  - 作者自述特意不用自上而下/自下而上的分层讲法，而是从现实需求演进史讲起，理解了交换机和路由器后再去看计算机网络 5 层结构就会简单很多。

  - 递进叙事：两台电脑一根网线相连 → 三台各开两个网口 → 太多后用中间设备 *集线器* 转发。集线器只把电信号 *广播到所有出口*、不做处理，属 *物理层*。
  - MAC 地址的诞生：广播后各机怎么判断包是不是给自己的？于是给每台设备一个 *全局唯一* 的标识即 MAC 地址（如 aa-aa-aa-aa-aa-aa），包头部带上目标 MAC，对上的收下、对不上的丢弃。
  - 交换机（数据链路层）：把集线器变智能，*只发给目标 MAC 指向的那台电脑*；内部维护 *MAC 地址表*（MAC↔端口）。表起初为空：从端口 4 进来一个包就先记录「源 MAC→端口 4」，查不到目标就泛洪所有端口，目标响应后（从端口 1 进）再记下「目标 MAC→端口 1」，各节点不断通信就建好整张表。多交换机互联也只要按同样规则接线即可。这种小范围网络叫 *以太网*。
  - 路由器的诞生（网络层）：机器数量涨到几十万，交换机记不下如此庞大的映射，于是让那根外接网线接入一个 *本身也有独立 MAC 地址、并能转发数据包* 的新设备，即路由器；路由器的每个端口都有独立 MAC 地址。
  - 为什么不能只靠 MAC 前缀划子网：MAC 48 位，前 24 位是厂商编号、后 24 位是厂家自分配；若靠前缀区分群组就要全网都买同一厂商设备或提前按子网规划烧录 MAC，不现实。于是发明 32 位的 *IP 地址*（软件层，可随时修改；MAC 一般不可改），如 192.168.0.1，可按网络拓扑灵活调整——「将 IP 为 192.168.0 开头的全部送给路由器，之后怎么转发交给它」。
  - 判断是否要走路由器——子网与子网掩码：源与目的 IP 处于同一子网就直接经交换机发出，否则交给路由器。用 *子网掩码*（如 255.255.255.0）分别与源、目的 IP 做 *与运算*，相等即同子网。例：192.168.0.1 与 192.168.0.2 同子网，与 192.168.1.1 不同。
  - 发给谁——默认网关：A 只能直接把包发给同子网下的某个 IP，*默认网关就是 A 在自己电脑里配置的一个 IP 地址*，发给不同子网机器时发给它。
  - 路由器怎么找 C——路由表：把目的 IP 映射到自己的端口，表项形如 192.168.0.0/24 → 端口 0；有下一跳时需再次匹配找到端口及其 MAC。~网络层（IP协议）本身没有传输包的功能，包的实际传输是委托给数据链路层（以太网中的交换机）来实现的。~
  - IP 到 MAC——ARP：A 不知道 B 的 MAC 时广播 ARP 请求，B 带自己 MAC 响应，A 更新 *arp 缓存表*（IP↔MAC）；反复广播后各机缓存表逐渐补全。
  - 各节点规则总结：电脑——知道双方 IP，用子网掩码判断是否同子网，同子网就 ARP 取对方 MAC 直接发出，不同子网就 ARP 取默认网关 MAC 直接发出；交换机——包必须有目标 MAC，查 MAC 地址表转发，查不到就全端口发；路由器——包必须有目标 IP，查路由表转发，查不到返回路由不可达。
  - 三张表：交换机有 *MAC 地址表*，路由器有 *路由表*，电脑和路由器都有 *arp 缓存表*；它们分别靠以太网内节点通信、路由算法+人工配置、ARP 请求逐步完善。
  - 完整案例（A→F）：A 用子网掩码算出与 F 不同子网 → 决定发给默认网关 → ARP 找到网关 MAC → 封装数据链路层头（源 MAC AAAA、目标 MAC 网关 ABAB）与网络层头（源 IP 192.168.0.1、目的 IP 192.168.2.2，*两个 IP 从始至终不变，只有 MAC 不断变化*）→ 交换机 1 按目标 MAC 转给路由器 1 → 路由器 1 查路由表得下一跳 192.168.100.5、再匹配到端口 2 发出 → 路由器 2 查表匹配端口 1、再查 ARP 得 F 的 MAC FFFF 并封装发出 → 交换机 3 按 MAC 表从 6 号口发出 → F 收到。作者另提供用 Cisco Packet Tracer 模拟该过程的源文件。

  - 一句话概括：说明「菜」走向「弱」义的两条不同路径——台湾「菜鸟」（源自闽南语对英文 trainee 的谐音）省作「菜」，以及方言里「菜」本就有「不好、水平差、下等货」之义，二者在长期使用中共同造就了今天的义项。
  【方法/论点要点】
  - 路径一（「菜鸟」省作「菜」）：早年间打 CS 把新人玩家称作「菜鸟」，慢慢「鸟」字被省去，只剩「菜」。
  - 「菜鸟」的来源：是标准网络词汇，和「机车」一样来自台湾，但其实诞生于部队，指军队中新来的士兵，当时流行「老鸟有交代，菜鸟要忍耐」。
  - 为什么叫「菜鸟」：竟是谐音梗——英文 trainee（见习生）在闽南语中读出来很像「菜鸟」。
  - 时间线：到上世纪 70 年代「菜鸟」已非常流行；而「菜鸟」到「菜」的义项转变此时已完成。1979 年台湾作家农晴依《小盼》已有「这么菜的化学，还敢去念甲组啊！」
  - 路径二（方言本义）：《现代汉语字典》里「菜」无「弱」相关义项，但《徐州方言词典》里「菜」有两个义项——烹调的副食品统称，以及「不好，水平差，不够标准」，说明徐州方言里「菜」本身就有「弱」义。
  - 其他辞书旁证：《汉语大词典》有「菜货：下等货，劣货」「菜骨：常年蔬食而骨瘦体弱」「菜包子：比喻无用的人」等词条，可见方言和民间说法中「菜」一直有「弱」义。
  - 成因推测：很可能是在日子不那么富裕的年代，人们在饮食系统中 *重视肉而轻视菜* 导致的。
  - 结论：这不是二选一——两条路径在漫长时间和人们不断使用中共同造就了该义项；~也许，是网络热词"菜鸟"唤醒了隐藏在方言记忆中的"菜"的义项~。

  - 一句话概括：用高德纳箭头（↑）从 G1 层层爬到 G64，让没有数学基础的人也能大致感受葛立恒数到底有多大，并说明它是有意义且可算的自然数。
  【方法/论点要点】
  - 高德纳箭头（↑）：一个箭头表示「前面那个数字的后面那个数字次方」，如 ~3↑3=3×3×3=27~、~4↑5=1024~，其实 4↑5 与 4 的 5 次方是一回事；用箭头是为表示幂塔这类大数。
  - 两个箭头=幂塔：~3↑↑3~ 理解为 3↑(3↑3)=3↑27=7625597484987，即 3 的 3 的 3 次方。
  - 三个箭头：3↑↑↑3=3↑↑(3↑↑3)=3↑↑7625597484987，展开就是一串 ~3↑（3↑3↑3↑……重复7625597484987次）~，即 3 的 7625597484987 级指数塔（不是 3 的那么多次方）；每秒写 3 个 3 也要 80602 年。
  - 关键规律：~每连续添加一个箭头，前一级别求出的那个数，就变成了当前级别拆成单箭头之后，单箭头的数量了（即指数塔层数）~。
  - 量级对比：宇宙粒子数量约 10^80，与 3↑↑↑3 的差距比一个粒子和银河系的差距还大。
  - 四个箭头：3↑↑↑↑3 已无法用指数塔描述，~这个数已经大到没边了~——这就是 G1，葛立恒数 G64 层塔的第一层。
  - G2 的恐怖：G2 有 G1 个连续箭头（而非以 G1 为指数塔层数），~用高德纳箭头，已经完全无法表示G2以上的级别了~；在 G2 面前 G1 小到连余额都算不上，如此爬到 64 层就是葛立恒数。
  - 有意义才难：G64+1、G(G64) 都能轻易超过葛立恒数，但那没有意义；~要超过葛立恒数，难就难在你要是一个有意义的数字。并且切实可算~。葛立恒数与多维超立方体模型有关，是一个有意义、可计算的自然数。
  - 定位：葛立恒数是~人类发射出去的最远的几条线之一~；在正数轴上随机取一点，其大于葛立恒数的几率约等于 100%。

  - 一句话概括：先澄清 /、/home、/boot、/swap 其实都是「挂载点」而非分区，再说明 Linux 一般至少需要 /boot、/swap、/ 三个分区各自的作用与大小建议。
  【方法/论点要点】
  - 概念澄清：~Linux下的/、/home、/boot、/swap等等并不是分区，而是所谓的"挂载点"（mount point）~，即目录树上的一个目录。
  - 目录树模型：~Linux的目录树是单根的，根目录就是/~，不像 Windows 有 C:、D: 等分区概念；有多块磁盘或若干分区时，只要用 ~mount~ 命令挂载到某个挂载点即可。举例：快的 SSD 挂到 ~/bin~ 和 ~/home/huge_app~；傲腾格式化成 swap 挂载到 ~/swap~ 以在内存不足时少掉性能；存电影 ~/home~ 不够就买 8T 硬盘挂到 ~/home~。
  - 一般至少准备三个区：
    1. ~/boot~ 分区——约 200~500M 够用，用来安装 grub、存放 Linux kernel 以及 initrd 映像（启动必需），单独存在便于管理。
    2. ~swap~ 分区——Linux 的 swap 格式为内存交换做过专门优化，用文件替代性能不如它；建议用最快的硬盘（SSD 最好选 MLC 甚至 SLC，否则内存不足时读写量大易写废）；大小一般建议与内存相当。
    3. ~/~ 分区——安装 Linux 系统以及用户文件，把硬盘剩余空间都留给它。
  - 更细致的方案：分 10~50G 安装 Linux 挂载到 ~/~，其余全部挂到 ~/home~，这样系统文件与用户文件分离，将来换发行版也不影响数据；要架网站还可单分一个区挂到 ~/opt~（甚至用 RAID）。
  - 偷懒方案：较新的发行版可以不管这些，只留足够未分区空间，安装程序会自动分三个区（对应 /、/boot、/swap）。
  - 基本思路：一个可靠但容量小的挂载到 /boot，一个速度较快的挂载到 /，一个耐读写同时速度快的挂载到 /swap，以此类推。

  【方法/论点要点】
  - 立论：很多人理所当然地认为 ~学习就是一个痛苦的过程~，作者说他们完全是错的。理论来源是 Piotr Wozniak 博士（波兰人，40 年专注学习与记忆研究，不断优化自己创建的学习软件 Supermemo）。其原话：~好的学习本身就是快乐的，没有快乐就没有好的学习~、~学习就和做爱一样爽~。
  - 人类大脑天生渴望学习（举例）：~晚上吃番茄炒鸡蛋行吗？好嘞！~ 枯燥，因为太容易理解以至于无聊；而 ~真没想到，一碗普普通通的番茄炒鸡蛋竟然吃出了上古神兽螭吻！~ 以「已知＋未知」引起好奇心。
  - 生理机制：神经影像显示前海马对视觉信息熵有反应，腹侧纹状体也有类似发现，即 ~人类的大脑会对「熵」作出反应，从而判断是否有学习机会~。大脑的奖励中枢需要「未知」来激活。不断探索未知、学习未知，让未知成为已知，再去探索新的未知——这是人类的本能，是刻在我们基因中生物算法的表现。~大脑中伏隔核和腹侧被盖区的持续活跃产生了学习中的快乐与上瘾。~ 未知是学习快乐的根源。
  - 什么让学习变得不快：以计算机专业书的一句「如选择太长的时间片，时间片轮转算法便退化为 FCFS 算法，无法满足交互式用户的需求」为例，外行读它「每个字都认识，连在一起就看不懂」——几乎全是「噪音」（不理解的无意义数据，和大脑中现存的知识储备没有关联），而可被理解的「信息」才是「已知」。高熵信号往往无趣，因为噪音太多，大脑会过滤掉过多知识，使信号的熵下降，难以激活奖励中枢。所以所学内容要有未知，但必须避免「和现存知识储备没有关联的未知（噪音）」——学习材料要有合适的「信噪比」，一句话概括：~所学不能太难~。
  - 难度平衡点：同一材料对不同人的「信息」与「噪音」不同，~学习材料的最佳难度是高度个性化的~。要相信人脑自己的判断——丘脑向杏仁体发送单独信号进行感性评估、向新皮层发送信号进行理性评估；进入大脑的知识都在「知识评估网络」中估值，高估值的信息激活奖励中枢，产生学习内驱力，最终达成学习乐趣。
  - 关键结论：~最合适的学习内容，往往就是我们最爱的。~ 只有难度合适的知识才会被大脑评估为高价值并触发奖励机制；倒过来说更成立——我们越想学，意味着学习内容越合适。越偏爱某领域，大脑对该领域知识估值越高，形成「越学越喜欢、越喜欢越学」的正反馈。要产生最好的学习效果，唯一要做的就是惯着大脑，听从内心的声音，尊重大脑的兴趣和选择的难度：~大脑喜欢的，就是最好的。~
  - 学校为什么是错的：Wozniak 是传统强制学校教育的坚决反对者，著有《我永远不会送我的孩子去学校》，认为传统强制教育应被完全废除。他称 ~现在的学校没有教育孩子，反而对许多孩子造成了伤害~，~它已经成为一种压迫的工具，剥夺了孩子们的自由和对学习的热爱~，教育系统的主要问题是千篇一律的流水线方法、很少考虑学习内驱力。

  - 一句话概括：作者指出理论上不存在无法破解的软件，防破解的目的只是让破解成本远大于购买成本，并用从硬编码注册码、机器码、MessageBox 断点、反调试、VMP、加密狗/网络验证到光盘坏道的一整串演进，演示了攻防手段的升级与各自软肋。
  【方法/论点要点】
  - 结论：理论上不存在无法破解的软件，但并不是说破解软件比开发容易一万倍；~防破解的目的不是要做一个无法破解的软件~，而是 ~让破解软件的成本远大于购买软件的成本~。知名软件大多有实力大大加大破解难度，但出于市场需求和争取用户的角度考虑会放水。
  - 最简单破解（V1，需一点 C 基础）：硬编码注册码的程序 ~if (strcmp(Key,"abc123456")==0)~ 编译成 exe 后把后缀改成 txt 打开、搜索注册码就能找到 key。原因是目前大部分编译器都会将字符串常量直接存储在可执行文件结构中，硬编码 key 的破解几乎屡试不爽。今天仍有一大堆软件用这种机制（多是不怎么值钱的工具，或作者防君子不防小人）。
  - V2.0 机器码：改用机器码（可由网卡 MAC、CPU 型号、内存大小等生成）经算法算出注册码 ~sprintf(Key,"%x",iID*8+123456)~，或拉上 MD5、SHA 等，明文 key 找不到了。但打开 OllyDbg 对弹窗函数 MessageBoxA 下断点，输入错误注册码命中后顺藤摸瓜来到判断注册码的逻辑，把判断代码删掉（nop 填充）后，不管输入什么都是注册成功——~万恶之源都始于那个MessageBox函数~，它成就了「软件发布后十分钟就被破解」的悲惨结局。
  - V2.1 不用 MessageBox：注册失败直接 ~exit(0)~，但 OllyDbg 查找字符串参考、双击「注册成功」仍能定位，换汤不换药。把检查代码复制 n 遍、逐字符检查、加密混淆「注册成功」等字样，也只能拖延时间（类似加 UPX 压缩壳，等解压完又是明文）；较聪明的做法是用时解密、用完马上抹掉明文，仍只是时间问题。
  - V2.5 反调试：用老而著名的 ~IsDebuggerPresent()~ 检测程序是否被调试器附加，检测到就弹窗嘲讽或直接退出；很多软件/壳还会在 TLS 段加载时检查，或用变形 PE 头让调试器无法加载。但这些手段都能绕——如通过修改 FS 寄存器的标志位让 IsDebuggerPresent 哑火，检查 int 3 软中断、Raw Call、Query PEB、检查 Debug Privilege 和父进程等同样都有绕过方式。~暗桩嘛，只要你插，一个一个拔总是拔的完的。~
  - V3.0 VMP（Virtual Machine Protection）：自己发明一套指令集、用它写程序并跑在自己的虚拟机上，破解者面对的不再是熟悉的 x86/x64/ARM 汇编。缺点是 VM 运行机制可能造成几十倍乃至几百倍的性能损失，所以 VMP 必须用于保护关键且非性能瓶颈的代码。VMP 也只能延长分析时间；但只要软件足够值钱，破解者仍可充分分析 VM 机运行机制。不过分析 VM 机执行机理比写 VM 机更头疼（前者靠代码揣测别人思路、后者是自己的思路转代码），所以 ~破解软件比制作软件简单，在很多情况下，不存在的！~
  - 商业保护壳的软肋：商业保护壳卖给一大票开发商，树大招风——只要某保护机制被分析清楚一次，几乎所有用它的软件都会沦陷，灰色产业甚至颇有利可图（一次投入、长期回报）。因此购买商业保护壳的保护效果没想象中强，甚至不如懂反逆向的码农自己写的。判断软件是否容易被破解，仍回到那句话：让破解成本远大于购买成本。
  - 更给力的思路——不让用户拿到代码：
    - 早期光盘防拷（物理）：在光盘上钉几条刮痕造出人工坏道，再把数据烧录到正确扇区，程序运行检查坏道标记；盗版者得在同样位置砸出同样刮痕（几乎不可能）。这叫防盗环技术。虚拟光驱出现后可复刻包括坏道在内的一切数据，该技术失效。
    - 加密狗 / UKey 保护：运行软件需插一个类似 U 盘的 Ukey（微型电脑），关键算法和代码在 Ukey 芯片里，PC 需要时向 Ukey 传数据、Ukey 算完把结果返回，避免用户直接逆向取得关键算法。缺点：带 Ukey 麻烦、丢了补办麻烦、性能与内存受限、通讯延迟造成性能损失、开发人员水平不到位可能留机会；只要软件够值钱，华强北能把 Ukey 拆开、用「药水」剥开外层找到芯片并接上熔断的读引脚（有的直接热风枪一吹接板读 ROM），读出芯片代码。
    - 网络验证：把关键代码从 Ukey 移到服务器、数据通过网络交互，原理与 Ukey 相同，同样有带宽、延迟导致的性能损失和设计缺陷。
  - 重点提醒：这类网络保护手段必须专门设计以保护程序中的一系列关键「功能」代码，而不是「防破解」代码（如代码解密、注册验证），因为后者几乎没用，仍能清除防破解代码、Dump 解密代码或伪造本地服务器实现破解。指望 x 盾、x 宝一键保护没用，必须由专业码农专门设计。
  - 结尾：代码保护手段很多、花样玩法也很多，本文只粗略介绍几个比较有代表性的破解和反破解手段；附作者自己的引擎 PainterEngine（C 语言编写的完整开源跨平台图形应用框架，https://www.painterengine.com/index.html ）。

* C 语言置零直接 =0 不就好了，为什么要按位与？  :科普:C语言:x86:汇编:
  :PROPERTIES:
  :链接:  https://www.zhihu.com/question/518241863/answer/2538501586
  :作者:  Studio TBsoft
  :原文:  [[file:原文/2026-10-19-C语言置零直接=0不就好了为什么要按位与-2538501586.org][本地原文]]
  :抓取:  2026-10-19
  :END:
  - 本地原文：[[file:原文/2026-10-19-C语言置零直接=0不就好了为什么要按位与-2538501586.org][打开本地归档]]
  - 一句话概括：从「C 是中级语言、特性针对 CPU 设计」出发，说明 ~a=0~、~a&=0~、~a^=a~ 分别对应 ~mov ax,0~、~and/or ax,0~、~xor ax,ax~，老编译器/嵌入式下生成的指令可能不同，并提醒操作外设寄存器要用 ~|=~ / ~&=~ 以免影响其它位。
  【方法/论点要点】
  - C 是「中级语言」：具备完整高级语言特性，但更多特性是针对 CPU 和硬件设计的，设计初衷是代替汇编开发操作系统。
  - 时代背景：设计 C 的年代 RISC 不流行，为提升低主频 CPU 性能采用 CISC 思路，8086/8088 起的 x86 是典型；CISC 与 RISC 孰优孰劣至今无绝对定论。
  - 很多 C 特性对应到 x86 指令一级就理所当然：~++~、~--~ 对应 ~INC~、~DEC~；~j=i++~ 与 ~j=++i~ 的区别只是生成 ~INC~ 与 ~MOV~ 的先后次序。
  - ~+=~、~-=~、~&=~、~|=~、~^=~ 直接对应 ~ADD~、~SUB~、~AND~、~OR~、~XOR~，一条指令即可，反倒是 ~+~、~-~、~&~、~|~、~^~ 一条指令往往还不能完全实现、还需附加 ~MOV~ 等。
  - ~[]~ 为何越界不检查：它实质是一种变址运算符，x86 本就支持相对寻址、基址—变址、基址—变址—相对等多种寻址，可直接实现；汇编里 ~mov al,data[si]~、~mov al,si[data]~、~mov al,[data+si]~、~mov al,[si+data]~ 都等价。所以 C 里 ~a[6]~ 与 ~6[a]~、~*(a+6)~ 与 ~*(6+a)~ 都等价。
  - 回到问题：x86 里把 AX 清零有 ~mov ax,0~ 和 ~xor ax,ax~ 两种写法。前者是立即数传送到寄存器的操作，只改 AX；后者是运算、会动用 ALU，清零 AX 的同时因结果为零把标志寄存器 PSW/FLAGS 的 ZF 标志位置位，等于一条指令干两件事，可能影响后续 ~JZ~/~JNZ~ 等条件跳转。
  - 速度：一般 ~xor ax,ax~ 更快，因为只涉及 AX 寄存器操作数、不涉及立即数，省去从指令中取立即数的译码步骤（评论补充为断开数据依赖更准确）。
  - 对应到 C：若变量 a 直接用寄存器实现，通常 ~a=0~ 相当于 ~mov ax,0~、~a&=0~ 相当于 ~and ax,0~、~a^=a~ 相当于 ~xor ax,ax~；现代主流 CPU 与编译器可能都优化成 ~xor ax,ax~，但在一些嵌入式 CPU 和较老编译器上三种写法生成的指令可能不同，从而影响执行速度与其它优化。
  - 补充（引 @夏侯蹲一蹲）：嵌入式/固件直接操作外设寄存器时，对某位置位/清零一般不要用 ~=~ 直接赋值，而应用 ~|=~ 或 ~&=~（相当于 OR/AND 指令），以免影响寄存器中除目标位之外的位、导致不可预知的结果。
  【原文摘录】
  #+begin_quote
  因为C语言虽然具备完整的高级语言特性，但更多特性的设计是针对CPU和硬件设计的，因为设计C语言的原始目的是为了代替汇编语言开发操作系统。
  #+end_quote
  #+begin_quote
  但两种写法的本质不同，mov ax,0指令是一种将立即数传输到寄存器的操作，除了影响AX寄存器的值之外不会有任何附加作用，但xor ax,ax指令则是一种运算，会动用到CPU的ALU，运算结果一方面将AX寄存器清零，另一方面由于运算结果为零，因此同时将标志寄存器PSW（或者FLAGS）中的ZF标志位也清零了，等于一条指令完成了两个工作。
  #+end_quote
  #+begin_quote
  所以一般来说，a=0就相当于mov ax,0的形式，a&=0就相当于or ax,0的形式，a^=a就相当于xor ax,ax的形式，尽管在现代主流CPU和主流C编译器上，三者可能都会被编译器最终优化为xor ax,ax的形式。
  #+end_quote
  #+begin_quote
  嵌入式系统和硬件固件（Firmware）的开发，直接与硬件底层，例如外设寄存器打交道时，如果要将外设寄存器中的某位置位（设置为1）或者清零（设置为0），一般不要用“=”直接赋值，而应该用“|=”或者“&=”进行。
  #+end_quote
  【我的想法】
  从汇编角度回答「=0 与 &=0」的差异，落到老编译器和嵌入式场景很扎实；最后「操作外设寄存器要用 |= / &=」这句才是真正的实战忠告。

  - 本地原文：[[file:原文/2026-10-19-为什么有的人看书会瞌睡-947292549.org][打开本地归档]]
  - 一句话概括：用「资讯阅读 vs 为求理解的阅读」的区分解释「刷公众号不困、看书却犯困」——后者的难点在于要克服与作者之间的理解力差距，而作者是「缺席的指导者」、无法随时提问，挫败感一来就犯困，可借助《如何阅读一本书》的方法应对。
  【方法/论点要点】
  - 现象：刷公众号、知乎回答能连看一两小时不累，拿起书本/Kindle 半小时就犯困、跑神、没耐心，看经典更是如此；这不能简单归咎于「不够自律」或「不是读书的料」。
  - 类比：说话被打断一次不悦、两次恼火、三次干脆不说——阅读同理，若总遇到难以理解的内容（情节平淡不知作者想说啥、专业术语看不懂），又找不到办法解决，自然失去耐心或打瞌睡。
  - 差别在于「资讯阅读」与「为求理解的阅读」。新媒体文章的最大特点是需要传播，这决定了内容不能太超出读者认知范围；一旦要花大力气理解，传播效果就大打折扣（读者会关掉去看下一条）。所以它多以读者熟悉的事物选题、以描述事件为主、对逻辑论证着墨不多——这种认知水平相近的阅读叫「资讯阅读」，不用花太多脑力。
  - 「为求理解的阅读」：因困惑或好奇心求助于书籍/文章时，会出现两种状况——①读者与作者对同一事物的理解程度不一样，作者理解更深（这也是要看他的书的原因）；②读者需要付出努力去克服这种不相等的理解力，才能保持在相当程度与作者清楚沟通。
  - 困难的来源：阅读是「非辅助的指导型学习」，与学校学习同属受他人指导，但作者是「缺席的指导者」，不像老师可随时提问（「这个词指什么、这段表达什么观点、如何求证」都无法问），只能自己思考解答；当问题多到自己找不到答案时，挫败感随之而来，典型如读文学/哲学经典。对着一堆看不明白的文字，就像看扭扭曲曲趴着不动的蚯蚓。
  - 提醒：这种二分只是就载体大致而言，新媒体也有需要费力理解的内容、书籍也有资讯阅读式的；困难在所难免，打瞌睡是正常现象，不必自责，根因是「为求理解的阅读有难度且需要正确方法」。
  - 药方：阅读是一门需要付出时间精力去掌握的艺术，推荐《如何阅读一本书》，本文的理解也来自这本书。
  【原文摘录】

  同样都是看文字，同样都是阅读，为什么差别就那么大呢？
  #+end_quote
  #+begin_quote

  #+end_quote
  #+begin_quote
  这时就会出现两种状况：第一是阅读的人与作者对共同探讨的东西的理解程度不一样，作者比读者理解得会更深。第二是读者需要付出努力去克服这种不想等的理解力，保持在与作者相当的程度内才能与作者进行清楚的沟通。

  【方法/论点要点】
  - 结论开头：一个突触可存储约 4.7 比特信息，人脑「硬盘容量」约 910TB，每个领域能掌握的概念约十万个。「永远不会遗忘」会导致人们更常出现「某个领域概念已装满」的情况，但那不太重要——你可能不需要更多概念，且题设技术也可能允许自行修改脑结构（添加神经细胞、切断不需要的突触）。

  - 短时记忆半衰期只有 7 秒，容量只有 7±2 个信息块。这些若按题设「永不遗忘」，新输入会与旧信息叠加，严重失真甚至无法解析。
  - 语义澄清：人声称想「永不遗忘」时，一般指「短期记忆一定变为长期记忆、长期记忆不被淡忘」，而非「工作记忆、视觉缓存全部堆积」；题中「大脑全被开发出来」大概来自「人脑开发了百分之十」之类的古老误会。
  - 脑的硬盘容量：神经细胞通过轴突与树突相互联系、传递信息形成神经网络，突触是记忆的物质储存结构基础，每个突触约 4.7 比特，全脑约可储存 910TB（对比 2017 年整个互联网约 500 万 TB）。突触不断形成与消失，动物受外界刺激时数量骤增，有的只存在几小时、有的长期存在并可能固定形成新的神经线路。

  - 人脑计算力估算之一：卡内基·梅隆机器人专家汉斯·莫拉维克分析视网膜神经图像处理电路，认为视网膜每秒执行一千万次图像边缘/移动检测、每次重现约需机器执行 100 条指令，故复制视网膜图像处理功能需十亿次/秒；视网膜神经元总重 0.02 克、是人脑重量的七万五千~十万分之一，据此复制整个人脑需每秒执行七十五万亿~一百万亿条指令。
  - 估算之二：劳埃德·瓦特等模拟人类听觉发现，机器至少需每秒一千亿次才能在接近人类的架构下和人一样好地确定声源位置；听觉皮层约占人脑皮层千分之一，故人脑总计算力在一百万亿次每秒以上。
  - 估算之三：得克萨斯大学模拟小脑区域实验估计，模拟每个神经元需一万次计算每秒，整个大脑约需一千万亿次每秒。
  - 综合（有一定冗余度）：人脑总计算力在一亿亿次每秒的程度。中国的天河二号已超越此计算力，但人脑远小而节能——意识清醒的成人大脑功率约 20 瓦，而天河二号光电费就突破天际。

  - 一句话概括：从原始前端开发一路讲到「变态级」静态资源缓存控制——用超长本地缓存 + 内容摘要化 URL + CDN 部署 + 非覆盖式发布，解决覆盖式发布导致的页面错乱，并指出前端性能优化本质是工程问题。
  【方法/论点要点】
  - 背景：作者是前百度工程师，负责过百度前端集成解决方案 FIS 的核心设计与开发，把这一领域叫「前端工程」；facebook 是这一领域的鼻祖。
  - 原始前端：写 index.html 加样式文件 a.css，用文本编辑器写、无需编译、本地预览 OK 就丢到服务器等用户访问，门槛极低。
  - 缓存优化第一步：a.css 每次访问都加载浪费带宽 → 用 304（协商缓存）让浏览器用本地缓存，但仍要与服务器通信一次 → 更「变态」的是用 cache-control/expires 强制浏览器用本地缓存、不和服务器通信。
  - 缓存更新问题：不让浏览器发请求了，缓存怎么更新？办法是通过更新页面中引用的资源路径，让浏览器主动放弃缓存、加载新资源。
  - 精确缓存控制：若页面引用 3 个 css、某次只改了 a.css，全量更新版本会导致 b.css、c.css 缓存也失效。要解决必须让 url 修改与文件内容关联——用数据摘要算法对文件求摘要信息，与文件内容一一对应，实现精确到单个文件粒度的缓存控制（url 带上摘要信息）。
  - CDN 与分集群部署：现代互联网企业会把静态资源部署到 CDN 节点、与动态网页分集群，网页引用的资源也变成对应部署路径。此时「先部署页面还是先部署资源」都会出问题：①先部署页面再部署资源——间隔内访问的用户会用新页面结构加载旧资源并把它当「新版本」缓存起来，导致页面样式错乱，除非手动刷新，否则缓存过期前一直错；②先部署资源再部署页面——有旧的本地缓存的用户正常，但无缓存/缓存过期的用户会「旧页面加载新资源」导致错误（页面部署完成后再访问又恢复正常）。所以访问量不大的项目只能半夜上线、先上静态资源再上页面。
  - 根本原因与解法：问题起源于资源的「覆盖式发布」（用待发布资源覆盖已发布资源）；解法是实现「非覆盖式发布」——用文件摘要信息对资源文件重命名、把摘要放进发布路径，内容有修改的资源就变成新文件、不覆盖已有文件。上线时先全量部署静态资源，再灰度部署页面，问题就较完美地解决。
  - 大公司静态资源优化方案四要素：①配置超长时间的本地缓存——节省带宽、提高性能；②采用内容摘要作为缓存更新依据——精确的缓存控制；③静态资源 CDN 部署——优化网络请求；④改变资源发布路径实现非覆盖式发布——平滑升级。
  - 注意：静态资源缓存控制要求在前端所有静态资源加载的位置都做此处理，包括 js、css 文件中引用的资源路径；由于涉及摘要信息，引用资源的摘要也会引起引用文件本身内容改变，形成级联的摘要变化。
  - 结论：前端性能优化「绝逼是一个工程问题」；不要觉得这是运维或后端工程师要解决的问题——若由其他角色解决，大家总把自己不关心的问题丢给别人，前端开发将受极大限制。作者建议大家观察百度/facebook 页面的资源引用路径处理与缓存控制。
  - 更新补充：rails 的 assets pipeline 与本思路一致（把静态资源变成 erb 模板、加 ~<%= asset_path 'image.png' %>~、上线前预编译），FIS 的实现思路几乎完全一样；作者还用 FIS 做了示例项目，可对照源码与部署代码（部署代码里能看到所有资源引用的 md5 化处理）。

  - 一句话概括：列举六个「中文翻译反而比英文更让人糊涂」的编程术语——双亲委派、鲁棒性、句柄、竞态条件、守护进程、存储过程，逐一吐槽译法并还原英文原意。
  【方法/论点要点】
  - 双亲委派（Parent-delegation）：译名严重误导，Java 的类加载器只有一个父加载器，是「单亲」，parent 本是单数，怀疑是机翻产物。
  - 鲁棒性（Robustness）：老生常谈，中文读音和意思都不如英文直观。
  - 句柄（Handle）：中文里找不出对应的「句柄」实体；handle 本身很形象——手握别人的「把柄」就能 manipulate 他。
  - 竞态条件（Race Condition）：condition 除了「条件」也指「状况」，race condition 就是多个线程/进程赛跑的状况；译成「竞态」反而看不出含义，且和「静态」谐音。
  - 守护进程（Daemon）：不是中文难懂，而是「英文不知所云、中文严重误导」。daemon 本意妖魔，操作系统里只是个跑在后台、父进程是 init 的「孤儿进程」，谁都没守护；命名源自麦克斯韦妖的思维实验，UNIX 用了无善恶倾向的古词 daemon 来指默默工作的后台进程。
  - 存储过程（Stored Procedure）：严格应译「被存储下来的过程」，省字导致主客体混淆；类似的「阻塞队列」（blocking queue）译成「阻塞式队列」会更清楚。
  - 引申：这种歧义不限于编程。康德《纯粹理性的批判》书名就歧义丛生，加个「对」字写成《对纯粹理性的批判》即可消除，但译者常常懒得加。
