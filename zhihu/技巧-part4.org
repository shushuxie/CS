  - 一句话概括：主张提高编程能力靠「疯狂的练习」，列出写代码、读源码、写博客、逛社区、打比赛等大量练法，用髓磷脂与一场交通数据比赛的经历说明熟能生巧，并推荐 Github、Kaggle 等练习资源。
  【方法/论点要点】
  - 练法清单：~去每天花两小时写代码，去研读各种开源项目源代码。去写技术博客，去蹭技术讲座、会议、公开课程。去逛Github，去StackOverflow上提问，去论坛上找技术大佬聊天。去参加软考，去参加ACM等正规编程比赛。去尝试自己写一个个人网站，或者开发一个游戏APP。~
  - 核心态度：让意愿充斥整个身体并相信能做好；~不积跬步无以至千里，新手想要成为高手，疯狂的练习是第一步~。~很多事都是孰能生巧，没有足够多练习不要提天赋。~
  - 练出髓磷脂：大量练习会产生髓磷脂（神经元外侧的脂质），让脑回路更灵活；大脑分反射、思考、记忆三个功能，反复练习让思考演变成习惯，最后仅靠反射完成，达到「生巧」。
  - 练习要有突破：~练习不是一味的重复，或者去完全复刻别人的代码，每一次练习都应该增加难度，有突破自己认知的成长~；经反复输入、评估、输出、纠正就会有惊人变化。
  - 亲历案例：工作第二年参加交通数据科学比赛（用历史数据预测未来车流），高强度使用 Google、翻遍 Kaggle/StackOverflow/Github，看大量车流论文，前后写了上万行代码（含数据探索、新老方案），赛后~发现自己在编程和算法上比以前通透了不少~——这是作者编程能力第一次突飞猛进。
  - 提醒：想要成为大佬还得勤于思考，~不然久而久之会变成没有灵魂的代码机器~。
  - 练习资源（以 Python 为例）：Github——全球最大代码托管站，Python 资源最多，有 pandas、django、tensorflow、pytorch、requests 等源码，以及 awesome python、Python-100-Days、ML-For-Beginners 等十几万 star 的学习资源，用 Python 关键词能搜出 300 多万仓库；Kaggle——世界最大的数据科学比赛网站和社区，涉数据分析、机器学习、深度学习、数理统计、可视化，还有免费数据集、模型、教程文档。

  - 一句话概括：主张从小就坚持「重视模块化、重视抽象但不滥用」，用代码行数瓶颈的自述与对比实验说明：合理抽象能把功能变成黑盒、极大减轻脑力负担，从而让人不遇瓶颈。
  【方法/论点要点】
  - 唯一要点：重视模块化，重视抽象但不滥用。作者从模仿大牛写模块化程序、看 SICP 知道抽象的好处中受益很大。
  - 反常现象：那篇讲程序员代码行数瓶颈的博客说 2k、20k、200k 行会遇瓶颈，但作者第一次写 8k+ 大程序没感觉，如今接手近 900k 行项目、自己写的部分近 10k，仍没遇到瓶颈。
  - 对比实验：作者很不认真地写小程序时也常写乱——一旦超过 200 行就觉得难受，做一点小修改都要花很久找该改哪里；~这种吃力感是我在那些精心思考的大项目里从未感受过的~。
  - 结论：~这说明了我并没有过人的天赋能在混乱中轻易找出清晰的脉络，那就是说，之前的如鱼得水，是因为好的习惯。~
  - 原理：模块划分合理、抽象合理的程序里，一个功能就是一个黑盒，只需知道它对什么输入给什么输出，无需了解内部反应，从而把精力投入真正需要考虑的地方；混乱程序则要理清每句话的关系，脑力消耗巨大。
  - 呼吁坚持：初期会觉得花时间思考模块划分、抽象层级是浪费时间，但久了会发现它在无声无息间帮你消除许多瓶颈，还会有思维能力增强的额外好处。
  【原文摘录】

  在模块划分合理、抽象合理的程序里，我可以简单的把一个个功能抽象为一个简单的黑盒，我不需要知道他们内部发生了什么复杂的反应，我只需要知道他们对什么样的输入会做出什么样的输出。
  #+end_quote
  #+begin_quote

  #+end_quote
  #+begin_quote
  这个习惯，真的让人十分受益，请一定坚持。刚开始的时候，你或许觉得花很长时间去思考程序的模块划分、抽象层级是十分浪费时间的无用功；但久了以后，你就会感受到这种习惯带来的好处。
  #+end_quote

  - 一句话概括：介绍在 M1 Mac 上借 Homebrew 安装 x86-64 交叉工具链（x86_64-elf-gcc/gdb/binutils）来编译、查看 x86-64 汇编的完整步骤，并给出借用 Xcode 头文件编译的办法。
  【方法/论点要点】
  - 背景：作者啃 CSAPP 第三章要用 x86-64 指令集，又嫌国外云服务器连接太卡，于是找在 M1 上编译 x86-64 的办法（网上多在讲反过来的 x86 上编译 arm）。
  - 第一步·安装交叉工具链：在 Homebrew 里搜到 x86_64-elf-gcc/gdb/binutils，执行 ~brew install x86_64-elf-gcc x86_64-elf-gdb~；装 gcc 时会自动装 binutils，~/opt/homebrew/bin~ 下会得到一整套 x86_64-elf-* 工具（as、gcc、ld、objdump、gdb、readelf 等）。
  - 第二步·设置别名：因命令过长，在 ~.zshrc~ 里加 ~alias xgcc="/opt/homebrew/bin/x86_64-elf-gcc"~、~alias xobjdump=".../x86_64-elf-objdump"~、~alias xgdb=".../x86_64-elf-gdb"~。
  - 编译技巧：x86_64-elf-gcc 头文件不全，可借用 Xcode Command Line Tools 的头文件，例如 ~xgcc -I/Library/Developer/CommandLineTools/SDKs/MacOSX12.3.sdk/usr/include -Og -S hello.c~（include 路径按自己系统版本号替换）即可编译出汇编。
  - 局限：这样只能编译成汇编，想编译成二进制文件仍会有问题。作者结尾吐槽「Vultr，退钱！」。

* 如何开始在 github 上学习东西？  :技巧:GitHub:Git:教程:
  :PROPERTIES:
  :链接:  https://www.zhihu.com/question/30119197/answer/1877067450
  :作者:  程序员吴师兄
  :原文:  [[file:原文/2026-10-19-如何开始在github上学习东西-1877067450.org][本地原文]]

  - 本地原文：[[file:原文/2026-10-19-如何开始在github上学习东西-1877067450.org][打开本地归档]]
  - 一句话概括：一篇两万字图文 GitHub 教程，从注册账号、修改个人信息、创建仓库、术语解释，到 Git 安装、十个常用命令、SSH 绑定与向 GitHub 提交代码，完整走一遍入门流程。
  【方法/论点要点】
  - 初识 GitHub：~GitHub 是一个面向开源及私有软件项目的托管平台，因为只支持 Git 作为唯一的版本库格式进行托管，故名 GitHub。~ 2008 年 4 月 10 日上线，除 Git 代码仓库托管和 Web 管理界面外，还提供订阅、讨论组、文本渲染、在线文件编辑器、协作图谱、Gist 等功能。为项目贡献代码的流程很简单：先点 Fork，把代码检出并把修改加入自己分出的库，最后通过内建的 pull request 机制申请合并。
  - 业界大神示例：Linus Torvalds（Linux 之父，github.com/torvalds）、John Resig（jQuery 创始人，github.com/jeresig）、Jake Wharton（Android 之神，GitHub 全球排名第二，github.com/JakeWharton）。
  - 著名开源项目：Linux（torvalds/linux）、Swift（apple/swift）、Ruby（ruby/ruby）；在 GitHub 开源的公司：Google、Microsoft、Alibaba。
  - 注册账号：进入 https://www.github.com → 点击 Sign up → 填 Username、Email Address、Password → Create an account → 选公开免费仓库（public repositories）→ 最后一步可 skip this step → 出现 Read the guide / Start a project。Username 要起有标识性的，若搭博客默认地址是 ~username.github.io~。
  - 主页与个人信息：点 View profile and more → Your profile；点 Edit profile 可填 Name、Bio、URL、Company、Location、上传头像，完成后 Update profile。Personal settings 里有 Account、Emails，以及很重要的 SSH and GPG keys（可通过它连本地 IDE，保证提交与检出的安全性）。
  - 创建仓库：Repositories → 点绿色 New → 填 Repository name、Description（可选）、选 Public、可勾选 Initialize this repository with a README → 点 Create repository。
  - 术语解释：Repository（仓库，项目存放处）、Issues（问题，别人可提 bug/改进）、Star（点赞）、Fork（复制一个完全相同的项目到自己账号、独立于原项目）、Pull Request（在 Fork 基础上向原作者提交合并请求）、Merge（合并 Pull 请求）、Watch（观察项目更新并收到通知）、Gist（分享代码片段）。
  - Git 安装（Windows 为例）：Git 官网 → Downloads → 选操作系统 → 下载 → 双击安装 → 一路 Next；关键一步选 ~Use Git from the Windows Command Prompt~（标注 2，兼顾 Git Bash 与 Windows 命令行；标注 3 会用 Unix 工具覆盖 Windows 工具，强烈不建议）；其余（HTTPS 传输后台、行结束标记、终端模拟器、补充功能等）默认即可 → 安装完成选 Launch Git Bash → 输入 ~git~ 验证就绪。
  - Git 常用操作的前提：进行任何 git 操作前，都要先切换到 Git 仓库的最顶层目录，再在此目录中打开 Git Bash（Linux 直接 cd 到仓库目录）。
  - 十个常用命令：
    1. ~git status~——查看仓库状态（未初始化时会提示 demo 不是 Git 仓库）。
    2. ~git init~——初始化 Git 仓库（之后默认进入 master 主分支，并用 Untracked files 提示未被追踪的文件）。
    3. ~git add hit.txt~——把文件添加到「临时缓冲区」，并未提交，可防止误提交。
    4. ~git commit -m "text commit"~——提交到仓库，~-m~ 后双引号内是提交信息；提交完 ~git status~ 显示 nothing to commit, working tree clean。
    5. ~git log~——打印提交日志（含 Author、Date、提交信息）。
    6. ~git branch~ / ~git branch a~——查看分支 / 创建名为 a 的分支（* 号表示当前所在分支）。
    7. ~git checkout a~——切换到 a 分支；~git checkout -b b~ 可在创建分支的同时直接切换到新分支。
    8. ~git merge a~——切到 master 后把 a 分支合并到 master（有冲突需先解决冲突）。
    9. ~git branch -d a~——删除 a 分支；删不掉时可用 ~git branch -D a~ 强制删除。
    10. ~git tag v1.0~——为当前分支加标签；~git tag~ 查看标签；~git checkout v1.0~ 切换到该标签下的代码状态。
  - 建议：几乎每个操作后都执行 ~git status~ 查看仓库状态，实时了解仓库情况。
  - SSH 绑定 Git 与 GitHub：
    1. 生成 SSH key：先确认装好 SSH（Linux/Mac 默认有；Windows 装了 Git Bash 通常自带），输入 ~ssh-keygen -t rsa~ 指定 RSA 算法生成密钥，连敲三次回车（不需密码），生成私钥 ~id_rsa~ 和公钥 ~id_rsa.pub~，默认在 Linux/Mac 的 ~/.ssh、Windows 的 C:\Documents and Settings\username\.ssh（Win10 为 C:\Users\think\.ssh）。
    2. 添加 SSH key：GitHub 主页右上角倒三角 → Settings → SSH and GPG Keys → New SSH key → 把公钥 id_rsa.pub 的内容粘贴到 Key 处（Title 可不填）→ Add SSH key。
    3. 验证：输入 ~ssh -T git@github.com~，出现相应提示即为绑定成功。
  - 向 GitHub 提交代码：先了解两个命令——~git push origin master~（把本地更新推到远程）和 ~git pull origin master~（把远程更新拉到本地）；一般 push 之前先 pull，不容易冲突。
    - 情况一：本地没有 Git 仓库——直接把远程仓库 clone 到本地：~git clone https://github.com/guobinhit/mybatis-tutorial.git~；clone 出来的本地仓库本身就是 Git 仓库、不用再 init，且自动关联远程仓库，改完 commit 后 ~git push origin master~（首次提交需输入账号密码验证）。
    - 情况二：本地已有 Git 仓库且多次 commit——先 ~git init~，再 ~git remote add origin https://github.com/guobinhit/springmvc-tutorial.git~ 关联远程仓库（origin 为远程仓库名，习惯如此命名，关联多个远程仓库时再取别名），接着 ~git pull origin master~ 同步远程到本地，然后 ~git add~ / ~git commit~，最后 ~git push origin master~。

  - 一句话概括：回答先纠正「指针是『指向』」这一误读，用六点例子讲清指针是保存地址的变量及其声明、赋值、运算、传参、指针的指针与空指针，后半段说明 C 语言为何长盛不衰。
  【方法/论点要点】
  - 开篇纠错：~不理解指针，是因为有人教错了你。~ 有人告诉你指针是「指向」某某某的，那就是误导、给你挖了个坑，初学者小心不要误读「指向」二字。
  - 第一，指针通常用于保存一个地址，这个地址的数据类型在定义指针变量时确定。
    #+begin_src c
    int a;   //定义一个变量a，用于保存一个int类型。
    int * b; //定义一个指针变量b，用于保存一个地址，这个地址所保存的数据应该是int类型。
    #+end_src
  - 第二，变量可以赋值，指针变量也一样；但一般不给指针直接赋值一个数值，而是把其他变量的地址、或其他指针的值赋给它。
    #+begin_src c
    b=&a;    //把变量a的地址赋值给b。“&”操作是取变量的地址。
    int * c; //我们又定义一个指针c
    c=b;     //c 的值和 b 一样，也是个 a 的地址。
    #+end_src
  - 第三，指针变量保存的值（地址）是可以变的。数组初始化例子：
    #+begin_src c
    int d[100];
    int * e;
    e=&d[0];    //e保存了数组d的第一个数据的地址
    for (int i=0; i<100; i++){
        *e = 0;     //把该地址中的数据赋值0
        e++;        //地址累加一次，也就是数组中下一个数据的地址
    }
    #+end_src
    指针和其他变量一样可以运算（一般是加减），也可以重新赋值。
  - 第四，指针有啥用。先看不用指针的函数：
    #+begin_src c
    int add（int x){
        return (x+1);  //把输入的值加1并返回结果。
    }
    #+end_src
    调用 ~a=add(a);~ 现在 a 等于 2。改用指针：
    #+begin_src c
    void add(int *y){   //给入的是一个int指针，是一个地址。
        *y = *y + 1;    //* 是指引用这个地址所保存的变量
    }
    #+end_src
    调用 ~add(&a);~ 把 a 的地址传进函数，a 的值加 1 再放回 a，现在 a 等于 2。若要对一个数据结构里的数据进行处理，就应传入这个结构的地址，在函数中依靠指针引用该地址的数据结构进行运算。
  - 第五，可以再用一个指针保存另一个指针变量的地址，即「指针的指针」；多用于函数指针或数据结构中有指针的情况，初学者搞不清就不必勉强。
  - 第六，空指针。指针不赋值（不给定地址）就拿来用会出错，这就是空指针；一般把指针赋值为 Null 表明它是空的、不能用，所以程序中一定要经常判别指针不是 Null 才能用。
  - 最后建议：初学 C 语言最好把复合语句拆开来看，如 ~int *a=&b;~ 拆成 ~int * a; a=&b;~ 就好理解了。
  - 为什么 C 语言长盛不衰：从底层往上看，在冯诺依曼架构的机器上，以内存地址和寄存器为操作单位的单条指令组成程序是非常自然的事情；学过汇编就会发现 C 语言只是对汇编做了一些包装（就像汇编对机器语言做简单包装）。你觉得不自然，是因为从数学、从顶层往下看，看到的是像 haskell、lisp 这样直观的语言；从底层往上看，C 语言也一样的直观。
  - C 的设计原则：第一是减法原则——~Perfection is attained, not when there is nothing left to add, but when there is nothing left to take away.~ 第二是符合实际需求——C 的各种假定立刻被其设计者在实现 Unix 的实际工作中检验，而不是建立在盲目的假设上。有了这两条，其它语言都不再试图替代它。

  【方法/论点要点】
  - 命令：~g;~（准确说是 ~2g;~），作用是跳转到「上上次」编辑的地方；与 ~gi~（跳转到上次编辑的地方）不同。
  - 使用场景：代码写到一半才发现某个变量或函数没声明。一般做法是先跳到前面声明好，再靠「数字+j/k」或「数字+gg/G」跳行、再用 ~f~ 跳到准确位置，效率低于鼠标；而用 ~g;~，声明完后只需 ~2g;~ 三个键就跳回来，还不用考虑在第几行、相隔多少行、在哪个字母后面。
  - 映射优化：~2g;~ 只是跳回位置，还需输入 ~a~ 才能继续编程，共四键；于是把 ~g<leader>~ 映射为 ~2g;a~，~至此，我只需要两个键就能跳转回来~。
  - 原理与配对：~g;~ 依据某个寄存器中的记录跳转，输入 ~:changes~ 可查看该寄存器内容；与之对应的是 ~g,~ 命令，二者配合能实现绝大部分精准跳转。
  - 缺点：声明变量或函数时要一次性输入完毕，中间不能返回 normal 模式，Ctrl+o 也不行；若必须返回，就多输入几次 ~g;~（或「数字+g;」）。
  - IDEA 的 Vim 插件没有这个命令，替代法：声明完变量或函数后不要按 ESC 或 Ctrl+[，而是按 Ctrl+o 再输入 ~gi~；缺点是同样要一次性输完，但用 Ctrl+o 可以（IDEA 判定 Ctrl+o 仍是 input 模式，而 Vim 判定为 normal 模式）。
  - vscode 的 Vim 插件在这方面和 Vim 一样，只是好像还不支持 ~:changes~ 命令。

  【方法/论点要点】
  - 动机：服务端命令太长、输入慢，用得少的记不住；用任务管理器把各种常见的冗余命令管理起来，敲 2-3 个字母就能启动。
  - 安装与部署：
    #+begin_src bash
    cd ~/github
    git clone --depth 1 https://github.com/skywind3000/asynctasks.vim
    ln -s ~/github/asynctasks.vim/bin/asynctask ~/bin
    #+end_src
    把 ~/bin~ 目录加入 ~$PATH~，再在 ~.bashrc~ 里加一行：~alias task='asynctask -f'~
  - 定义全局任务：编辑 ~/.config/asynctask/tasks.ini~：
    #+begin_src ini
    [git-fetch-master]
    command=git fetch origin master
    cwd=<root>

    [git-checkout]
    command=git checkout $(?branch)
    cwd=<root>
    #+end_src
    之后输入 ~task~ 就能运行上面的任务。~cwd~ 字段是命令运行的目录，~<root>~ 代表项目根目录（有 ~.git~ 和 ~.svn~ 的那个目录），不写就是当前目录；命令含 ~$(?xxx)~ 时运行前会让用户输入 xxx 再替换。
  - 局部任务：定义在各个项目文件夹下的 ~.tasks~ 中，作用于所有子目录，用于针对项目的编译、测试、发布等日常任务；本地任务比全局任务优先级更高。
  - 把 task 绑到 F5（连「task」几个字都省了）：在 ~.bashrc~ 中加
    #+begin_src bash
    bind '"\e[15~":"task\n"'
    #+end_src
    zsh 用：~bindkey -s '\e[15~' 'task\n'~。使用前先安装 fzf，否则只能输入完整命令 ~asynctask git-fetch-master~；装了 fzf 后就能模糊匹配输入命令。
  - 命令语义抽象（file-build / file-run）：把编译和执行统一成语义化任务，放进全局配置：
    #+begin_src ini
    [file-build]
    command:c,cpp=gcc -O2 -Wall "$(VIM_FILEPATH)" -o "$(VIM_PATHNOEXT)" -lstdc++ -lm -msse3
    command:go=go build -o "$(VIM_PATHNOEXT)" "$(VIM_FILEPATH)"
    command:make=make -f "$(VIM_FILEPATH)"
    cwd=$(VIM_FILEDIR)

    [file-run]
    command="$(VIM_FILEPATH)"
    command:c,cpp="$(VIM_PATHNOEXT)"
    command:go="$(VIM_PATHNOEXT)"
    command:python=python "$(VIM_FILENAME)"
    command:javascript=node "$(VIM_FILENAME)"
    command:sh=sh "$(VIM_FILENAME)"
    command:lua=lua "$(VIM_FILENAME)"
    command:perl=perl "$(VIM_FILENAME)"
    command:ruby=ruby "$(VIM_FILENAME)"
    cwd=$(VIM_FILEDIR)
    #+end_src
    于是统一成 ~asynctask file-build xxx~（编译文件）、~asynctask file-run xxx~（运行文件）；~$(...)~ 宏以 VIM 开头是为了兼容同名 vim 插件的配置，并不是需要 Vim 才能运行。
  - 项目编译（project-build / project-run）：
    #+begin_src ini
    [project-build]
    command=make
    cwd=$(VIM_ROOT)

    [project-run]
    command=make run
    cwd=<root>

  - 一句话概括：用好 Git 的七点——rebase 让提交记录清晰、reflog+reset 跳到任意 commit、cherry-pick 取指定 commit、commit --amend 改提交内容、revert 回滚某次提交、stash 暂存文件、配置 alias 提效，并附具体命令。
  【方法/论点要点】
  - 总览（七点）：~使用 git rebase 让提交记录更加清晰可读~；~使用 git reflog + git reset 跳到任意 commit~；~使用 git cherry-pick 获取指定的 commit~；~使用 git commit --amend 更改提交内容~；~使用 git revert 回滚某次的提交~；~使用 git stash 来暂存文件~；~配置 git alias 提升工作效率~。
  - 一、git rebase：变基，作用和 merge 相似，用于把一个分支的修改合并到当前分支。用法：基于 master 创建 feature 分支 → 在 feature 上开发功能点 → master 上也提交 commit → 在 feature 上执行 ~git rebase master~（以 master 最后的提交作为基点，逐个应用 feature 的每个更改）。
    - rebase VS merge：merge（~git merge branchname~）会保存每次 commit，用 gitk 看会有好几条颜色的线；rebase 则去除一系列提交记录、「复制」它们再逐个放下去，能创造更清晰的提交记录。merge 会保留所有 commit 的历史时间，人多后历史记录会混乱。
    - 交互模式（压缩多次无效提交为一次）：
      #+begin_src powershell
      git log
      # f9f6f3b commit 3
      # 2feb45f commit 2
      # 07a3cb6 commit 1
      # 我们要修改 2 的话，rebase 到它的下一个 commit，这里是 1
      git rebase 07a3cb6 -i
      git rebase -i <base-commit>
      # 或者是 git rebase -i HEAD~2 对最近的两次 commit 进行合并
      #+end_src
      在打开的对话框里修改，之后还要 rebase continue。有人称之为后悔药——无论写什么 commit 最后都能修改、合并，DIY 性强。
  - 二、git reflog + git reset：换句话叫时光机，通过查找所有分支的所有操作记录（包括已被删除的 commit 记录和 reset 操作），再用 reset HEAD 跳到指定 commit。
    #+begin_src text
    git reflog
    #afa2f45 HEAD@{10}: checkout: moving from 今天 to 明天
    #4abcda5 HEAD@{11}: commit: 打通1800处仙窍
    #de42069 HEAD@{12}: commit: 真言轮经大成
    git reset HEAD@{10}
    # 或者 git reset --hard afa2f45
    #+end_src
  - 三、git cherry-pick：意为「挑拣」提交，与 merge 合并一个分支的所有提交不同，它获取某个分支的单个提交并作为新提交接入当前分支。故事背景：张三在分支上开发 feature1~feature6 六个提交，再 ~git reset --hard feature1~ 跳回第一个 commit 开发出 feature7，要把 feature7 合并到 feature6 上：
    #+begin_src text
    git reflog
    # 找到 feature7 的 commit 4c97ff3
    # 回到 feature6 的 commit cd52afc
    git reset --hard cd52afc
    git cherry-pick 4c97ff3
    #+end_src
    简单说每一次 commit 就是一次记录，可以合并到任意地方；开发功能点或修复 bug 尽量做到一个功能点一个 commit，方便出错时挑拣代码。
  - 四、git commit --amend：修正，把新改动合并进最近一次的 commit。
    #+begin_src text
    git add .
    git commit --amend --no-edit
    #+end_src
    ~git commit --amend~ 会弹出让你修改内容；加 ~--no-edit~ 保持上一次的 commit 内容。PS：如果代码已经 push，慎用，因为会修改提交历史。
  - 五、git revert 回滚某次提交：与 ~git reset --hard xxx~（回到某次 commit）不同，revert 能撤销某次 commit。
    #+begin_src text
    git log
    git revert <commit-id>
    #+end_src
    这种做法会新建一条 commit 来撤回之前的修改，提交历史不会被抹去；所以个人开发或个人 feature 分支可用 reset 回滚，多人协作的集成分支上 revert 更合适、可安全撤回。
  - 六、git stash 暂存文件：先把本地改动存起来，等紧急 bug 修完再取回。先了解 Git 四大工作区域：
    - Workspace（工作区）：本地电脑所见的文件和目录。
    - Index/Stage（暂存区）：一般在 .git 目录下，~git add 改动文件~ 后改动放入暂存区。
    - Repository（本地仓库）：~git clone 地址~ 后存在本地的版本库，HEAD 指向最新放入仓库的版本，~git commit~ 后文件改动到本地仓库。
    - Remote（远程仓库）：Github、Gitlab、码云等代码托管平台。
    常见场景：开发功能点时突然有线上 bug 要紧急修复。基本命令：
    #+begin_src text
    git stash # 将本地的改动暂存
    git stash save "message" # 执行存储时，添加备注
    git stash pop # 应用最近一次暂存，并删除暂存记录
    git stash apply # 恢复最近的存储，但不会把存储从存储列表中删除；使用其他用 git stash apply stash@{$num}
    git stash list # 查看 stash 了哪些存储
    git stash clear # 删除所有缓存的 stash
    git ls-files --stage # 查看 index 暂存区
    #+end_src
  - 七、配置 git alias：基本用法 ~git config --global alias.<简化的字符> 原始命令~。
    #+begin_src text
    git config --global alias.co checkout
    git config --global alias.ci commit
    git config --global alias.br branch
    #+end_src
    也可在 .gitconfig 文件中设置：
    #+begin_src text
    [alias]
    st = status -sb
    co = checkout
    br = branch
    mg = merge
    ci = commit
    ds = diff --staged
    dt = difftool
    mt = mergetool
    last = log -1 HEAD
    latest = for-each-ref --sort=-committerdate --format=\"%(committername)@%(refname:short) [%(committerdate:short)] %(contents)\"
    ls = log --pretty=format:\"%C(yellow)%h %C(blue)%ad %C(red)%d %C(reset)%s %C(green)[%cn]\" --decorate --date=short
    hist = log --pretty=format:\"%C(yellow)%h %C(red)%d %C(reset)%s %C(green)[%an] %C(blue)%ad\" --topo-order --graph --date=short
    type = cat-file -t
    dump = cat-file -p
    lg = log --color --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit
    #+end_src
  - 其他不常见但好用的命令：~gitk~（打开图形化工具）、~gitjk~（撤销刚在 git 中所做的操作）、~git help -g~（展示帮助信息）、~cat .git/HEAD~（查看分支文件）、~git fetch --all && git reset --hard origin/master~（回到远程仓库的状态）、~git push -f origin master~（强行覆盖远程 master）。

  【方法/论点要点】
  - 核心规则：对于任意一种类型声明式，右边类型表达式经过 ~* () []~ 运算后的结果类型与左边相同。
  - 类型表达式里 ~()~ 也表示调用运算，但括号内可含参数的类型信息（如 ~int (*p)(int *)~ 表示可对 ~*p~ 传 ~int*~ 调用、结果 int，故 p 是函数指针）；~[]~ 也表示下标运算，括号内可含元素个数（如 ~int a[5]~ 表示对 a 做下标运算得 int，故 a 是数组）。
  - 反推六步（优先级最低的运算最先脱掉）：① ~(*(*fun(...))[5])(int*)~：括号优先级高于调用，故 ~*(*fun(...))[5]~ 是返回 int、参数 int* 的函数；② ~*(*fun(...))[5]~：~[]~ 高于 ~*~，取值后得函数，故 ~(*fun(...))[5]~ 是函数指针；③ ~(*fun(...))[5]~：括号高于 ~[]~，故 ~*fun(...)~ 是 5 元素的函数指针数组；④ ~*fun(...)~：调用高于取值，故 ~fun(...)~ 是指向数组的指针；⑤ ~fun(int*(*p)(int *))~：参数是 ~int*(*p)(int *)~；⑥ ~int*(*p)(int *)~：返回 int*、参数 int* 的函数指针。
  - 结论：~int (*(*fun(int*(*p)(int *)))[5]) (int*)~ 是一个函数，其参数是「返回值为 ~int*~、参数为 ~int*~ 的函数指针」，其返回值是「指向 5 元素数组的指针」，数组元素是「返回值为 int、参数为 ~int*~ 的函数指针」。
  - 正推验证：把类型表达式换成对应语句表达式 ~(*(*fun(0))[0])(0)~，结果类型为 int；过程是「对 fun 调用 → 对返回值取值 → 取元素 → 再取值 → 当函数调用 → 返回 int」，正好是前面反推的逆过程。
  - 可编译性：文中给出完整 C 程序（用 ~typedef int (*pfunc_t)(int *)~ 定义函数指针、声明两个函数指针数组，~fun~ 返回指向数组的指针，~main~ 里遍历调用），并贴出实际运行结果，证明该声明合法。

  - 本地原文：[[file:原文/2026-10-19-你是如何学会正则表达式的-748926080.org][打开本地归档]]
  - 一句话概括：一篇把正则从符号到进阶用法再到实战采集讲透的长教程——元字符、反义、量词、懒惰限定符、捕获分组、零宽断言逐条带例，最后用 C# 采集博客园首页做完整闭环，并附在线/离线匹配工具。
  【方法/论点要点】
  - 什么是正则：一种特殊的字符串模式，用于匹配一组字符串，好比用模具做产品；正则所用的字符其实不多，难的是组合后可读性差。
  - 常用工具：在线匹配 regexpal.com（可能已挂）、rubular.com；软件 McTracer（可把正则导出成 java/C#/js 并自动转义，还支持解释哪段是捕获分组、哪段是贪婪匹配）。
  - 元字符：~^~ 匹配行或字符串的起始位置（有时还匹配整个文档起始）；~$~ 匹配行或字符串的结尾；~\b~ 不消耗字符只匹配一个位置，常用于单词边界；~\d~ 匹配数字；~\w~ 匹配字母、数字、下划线；~\s~ 匹配空格；~.~ 匹配除换行符以外的任何字符（~\w~ 的加强版，~\w~ 不能匹配空格）；~[abc]~ 字符组，匹配括号内元素，也可写 ~[a-z]~ 匹配 a 至 z。
  - 反义：把字母改成大写即取反——~\W~ 任意不是字母数字下划线的字符、~\S~ 任意非空白符、~\D~ 任意非数字、~\B~ 不是单词开头或结束的位置、~[^abc]~ 匹配除 abc 以外的任意字符。
  - 量词的三概念：贪婪（如 ~*~）先匹配整个字符串、失败则回退一个字符（回溯），最耗资源；懒惰（如 ~?~，勉强）从起始位置每次只检查一个字符；占有（如 ~+~）覆盖整个目标字符串后只尝试一次，不回溯，「好比先抓一把石头，然后从石头中挑出黄金」。
  - 量词用法：~*~ 重复零次或更多；~+~ 重复一次或更多；~?~ 重复零次或一次；~{n}~ 重复 n 次；~{n,m}~ 重复 n 到 m 次；~{n,}~ 重复 n 次或更多。
  - 电话号例子：先用 ~^0\d\d\d-\d\d\d\d\d\d\d$~ 说明 ~\d~，学完量词后简化成 ~0\d+-\d{7}~，再限定区号得到 ~^0\d{2,3}-\d{7}~（区号可 3 位或 4 位）。
  - 懒惰限定符：~*?~ 重复任意次但尽可能少重复（如 ~acbacb~ 用 ~a.*?b~ 只取到第一个 ~acb~）；~+?~ 至少一次但尽可能少；~??~ 0 次或 1 次但尽可能少；~{n,m}?~、~{n,}?~ 同理尽可能少。
  - 捕获分组：~(\d)\d~ 中 ~(\d)~ 即一个捕获组，可用后向引用 ~\1~（如 ~\b(\w+)\b\s\1\b~ 匹配 ~zery zery~）；可用 ~(?<name>exp)~ 自定义组名、后向引用写作 ~\k<name>~。常用写法：~(exp)~ 捕获到自动命名组、~(?<name>exp)~ 捕获到 name 组、~(?:exp)~ 不捕获也不分配组号。
  - 零宽断言：~(?=exp)~ 匹配 exp 前面的位置（如 ~(?<txt>.+(?=ing))~ 取 ing 前所有字符）；~(?<=exp)~ 匹配 exp 后面的位置（如取 How 之后）；~(?!exp)~ 匹配后面不是 exp 的位置；~(?<!exp)~ 匹配前面不是 exp 的位置。
  - 实战：用 C# 发起 HTTP 请求抓博客园首页，再用正则过滤 HTML，依次取出推荐数、标题、文章链接、作者图片、作者博客 URL、文章简介、发布人与发布时间、评论数、阅读数，用到了 ~\s~、~\w+~、~.*?~、捕获分组、零宽断言等。

  【方法/论点要点】
  - 第一阶段：不要给自己「预设」。老师骂「笨」「最差一届」想激励学生，事实正好相反、学生表现会越来越差，这是哈佛终身教授埃伦·兰格提出的「潜念」mindlessness（无意识行为）的影响。两个自测：你是否相信智力不可改变？能力不可增长？答 yes 说明已被严重影响。最直接的危害是扼杀未发挥的潜能。
  - 第二阶段：专注解决问题的过程。①「享受」思考的乐趣：多反思多提问，别停在书本文字上；别给自己定「必须读完 10 页」这类目标，专注知识本身、多想多查，专注就不再难。②「主动」学习：事情做成都出于「我想做」而非「想我做」；别拖时长、别暗示自己必须学满 3 个小时，把关注点放在学习本身，「解决了问题」才值得庆祝。
  - 第三阶段：保持对学习的新鲜感，避免疲劳感。人面对长期不变的东西都会丧失兴趣、坐在书前多半是在耗时间，热情衰退是迟早的，所以保持新鲜感比完成计划更重要；要从中找到自己的兴奋点（如搞定一个新知识带来的满足感）。记住：新鲜感 = 高效。

  - 第五阶段：保持良好身体状态、持续输出。①每日睡眠大于 7 小时（荷兰神经学家伊斯布兰德·范德韦研究发现睡眠影响海马体活跃度、进而影响记忆力与专注度）；②减少能快速提升血糖的高碳水食物摄入（尤其周中下午要学习时，会让人「身体疲惫」、大幅降低效率）；③适当体育锻炼，舒缓压力、增强体质；④获得正面反馈，让自己觉得学习有意义（最直观是成绩提升、能力增长）。
  - 小技巧 1：养成动笔的习惯。一边学一边记笔记，写字能促进二次消化、提升专注度并帮你进入学习状态；「读过」不等于「留存」，不记第二天八成会忘 20%、第三天忘 40%；浮躁时强迫自己开始写，写着写着就沉浸进去了。
  - 小技巧 2：番茄工作法（老生常谈，自行百度）。
  - 小技巧 3：排除干扰信息。手机提前静音，别让不重要信息分散注意力、抬高你集中注意力的成本。
  - 小技巧 4：建立学习的「仪式感」。①学习前保证工具整洁齐全；②前一天晚上做好准备、养足精神；③提前进入学习状态（如定 8 点学就 7:50 开始准备），降低行动门槛。

  【方法/论点要点】
  - 思路：用 ~standalone~ 文档类 + ~tikz~，加载 ~positioning, calc, matrix, arrows.meta~ 库，用 ~matrix of math nodes~ 摆三张表，再用 ~\draw[->]~ 从单元格连线。
  - 样式准备：在 ~\tikzset~ 里定义 ~every matrix/.style={matrix of math nodes}~、~hp/.style={column 3/...}~、~Hp/.style={column 4/...}~（把第三/四列锚点设为 base east 以便对齐）、~>=Stealth~。
  - 结构：上表 ~(a)~ 三列 ~X Y φ₁(X,Y)~；下表 ~(b)~ 三列 ~Y Z φ₂(Y,Z)~；右侧 ~(c)~ 四列 ~X Y Z φ₃(X,Y,Z)~；用 ~\coordinate (x) at ($(a)!0.5!(b)$)~ 取上下表的中点，再用 ~[right = 3cm of x]~ 把右表放好。
  - 连线：用 ~\draw[->, 颜色] (源单元格) to[in=180, out=0] (目标单元格)~，红/橙/蓝/紫/青/灰线分别连接不同单元格，虚线用 ~dashed~，并可用 ~[xshift=...em, yshift=...em]~ 微调落点。
  - 关键代码（缩略，重复行以省略号代替）：

  \documentclass{standalone}
  \usepackage{tikz}
  \usetikzlibrary{positioning, calc, matrix, arrows.meta}
  \tikzset{
      every matrix/.style={matrix of math nodes},hp/.style={column 3/.style={anchor={base east}}},Hp/.style={column 4/.style={anchor={base east}}},>=Stealth
  }
  \begin{document}
  \begin{tikzpicture}
  \matrix [hp] (a) {\hline X & Y & \phi_1(X,Y) \hline 1 & 2 & 0.3 \\ ... \hline};
  \matrix[below = of a, hp] (b) {\hline Y & Z & \phi_2(Y,Z) \hline 1 & 2 & 0.3 \\ ... \hline};
  \coordinate (x) at ($(a)!0.5!(b)$);
  \matrix[right = 3cm of x, Hp] (c) {\hline X & Y & Z & \phi_3(X,Y,Z) \hline 0 & 1 & 2 & 0.3 \\ ... \hline};
  \draw[->, red] (a-2-3) to[in=180, out=0] (c-2-1);
  \draw[->, orange] (b-3-2) to[in=180, out=0] (c-5-3);
  \draw[->, purple, dashed] (c-1-1) to[in=100, out=80] ([xshift=-0.5em, yshift=0.5em]c-1-4);

  【方法/论点要点】
  - 前提：中国教育环境下多把学习当「成功」的手段而非目的，所以要从学习本身获得乐趣几乎不可能；先把学习当成现阶段的「工具」来理解。
  - 核心机制：学习的激励点来自学习之外——比别人强、被赏识与区别对待。学霸的「自我驱动」源于越早获得学习之外的正向反馈（赏识、钦佩、不被霸凌），从而进入「越学好越有奖励→越奖励越懂学习逻辑→越懂逻辑越学得好」的正向循环。名校标签、CFA/CPA/ACCA 证书都是这种正向激励，学习好坏直接作用于「区分人与人」，像奢侈品一样，甚至更强。
  - 常识一，有效时间和你的时间都有限。简化公式：得到知识的纯度 = 效率 × 时间。微信短文、游戏、所谓「知乎学习」缺乏体系化和进阶性，不算知识；一天学习 8 小时不玩手机就强过 99% 的人。基础知识到熟练没有 500 小时想都别想（如考过日语 N2 天资好的约 500 小时、笨一点 800 小时，且不含上课玩手机、自习刷知乎的时间）。这就是「知识相对论」：重要的不是知识本身，而是充分消化吸收知识所要付出的时间。
  - 常识二，真正的知识没积累到一关就打不了下一关，要注重关键节点。学习是体系化的，路径是 A→B→C……→P，无法从 A 直达 P（不能给只学过九九乘法表的小学生讲微积分）；缺了关键节点，整座知识大厦摇摇欲坠，只能在「补缺」和「学新」之间折返跑——别人学 D 时你在补 B、巩固 C 再学 D。很多人并非智商问题，而是「失去了正向反馈、方法不对、不成体系、有效时间不多」。
  - 常识三，意志力是有限度的，且可能是你学习上唯一的优势。引罗伊·鲍迈斯特《意志力》：①意志力是一种生理机制、是可被消耗的资源（与葡萄糖有关，饿了累了难保持记忆集中），心智被占据就无法并行思考；②可通过设定合理目标、养成良好习惯、自我监控来提高，有效练习办法是「做自己不习惯做的事」（刻意训练）。意志力同时影响时间与效率两个维度，对学习的影响比智商更根本。
  - 总结四步：①寻找正向激励的奖励（小到点赞关注，大到考入名校、考下 10%-20% 技能证书、进好公司，它们会成为带不走的「资历」，给你「我能比别人学得好」的暗示，且是终生式反馈）；②订立一个需要体系化的知识目标，做好投入 500-800 小时的打算，日有效时间从 4 小时起步，建立时间观念；③建立体系化目标并明确关键时点，把目标解剖到具体关键节点逐步完成；④训练意志力，并把有限的意志力花在重要的地方。
  - 2019 补丁：所谓「体系化目标」其实是达到目标的立体化结构——如健身不只是运动，还包括运动、意志力、睡眠、营养、控制食欲、防反弹、身体指标、补剂等，运动内部又有有氧/ HIIT /力量训练，再往下还有操课、跳绳、游泳、自重、固定器械、自由力量等；目标要点亮越多「知识树」越好。
  - 19 补：胜利者效应。引浙大胡海岚团队刊登于《Science》的研究（及 2011 年「钻管测试」）：刺激劣势小鼠前额叶脑区突触强度后，它能逆袭强敌；胜利 6 次后大脑发生质变，突触连接强度显著增加并自主维持优势——即「过去成功的经历会通过改变动物的生理结构，从而引导其赢得下一次竞争」。

  【方法/论点要点】
  - 前提：不建议直接看迭代了很多大版本的框架源码，要循序渐进。
  - 第一步：从 ~lodash~ 这种工具库看起——都是小块函数、好上手、容易调试看效果，还能补基础（节流、防抖、深拷贝等）；另推荐 30 seconds of code（全是小而美的代码片段，部分可替代 lodash 函数）。

  - 第三步：有基础和感觉后，看现在 MVVM 框架的实现原理——从单一功能开始，拆解 MVVM 的通用实现模式（双向绑定、虚拟 DOM 等），最后实现自己的 mini MVVM（参考《50 行代码的 MVVM，感受闭包的艺术》等）。

  - 最后：参与开源框架开发——对 preact、vue 等修 issue 或迭代功能，也可对 React/Vue 周边生态库提 PR，进而尝试做对标业界高质量的开源「轮子」。
  - 但业务里造轮子机会不多，想摆脱「页面仔」还有很多方向：多端秒开/性能优化；工程化套件（脚手架、开发调试工具、发布管理，先熟练 webpack 和 babel）；数据埋点/监控；多端融合（H5/iOS/Android/小程序，跨端框架如 omi、taro、Chameleon，更底层如 Weex、RN、Flutter）；组件库与 pro code / low code（基础组件如 ant design，pro code 如 ant design pro，low code 多可视化搭建）；互动平台（2D/3D 动效、前端图形、直播，动画路线 js/css → svg → lottie-web）；SSR、微前端；BFF、Serverless、BFF in Serverless；灰度平台/ABTest；职场软技能。

  - 针对个人·治标方法（立竿见影）：「熟练掌握 reflog + reset」——先学会「吃后悔药」就像学车先学会踩刹车，心里才有底；初次进 reflog 界面不知怎么退出（按 ~q~）不要害怕。

  - 针对个人·灵活使用 Stash：工作区里有很多无法/没必要 commit 又不能删的临时文件时，可以先 stash 暂存、还你清爽工作区，merge 之后再还原。
  - 针对团队·第一：所有人 push 之前先 merge；很久没 merge 了就「先 merge 再写码」——这是初学者最常犯的错。
  - 针对团队·第二：重构项目文件架构，让不同模块的人尽可能少碰别的模块，最好每人只动自己的文件（前后端分离、MVC、MVVM 等），别整个项目就俩文件、那样不出冲突才怪。
  - 针对团队·第三：项目管理人员要熟练掌握 blame 和 diff，知道怎么帮他人解决冲突。
  - 针对团队·第四：最好每人只在自己的 Repo/Branch 上操作、不直接 commit 到主干 master/main；这样主管可先 review 再帮他 merge，也要确保他们经常 merge 主干，或用自动化 CI 定期 merge 主干跑测试，防止子项目偏离主干太远。若有人总自己开发、从不 merge 主干，每次合并都是一堆相同的冲突，可据其对项目的重要程度决定是「打死他还是温和提醒他」。

  - 一句话概括：一位 vim 老手用「按键序列 vs 组合键、类编程的编辑体验、Unix 生态的一环、小功能定制方便」四点解释 vim 为何在熟手中显得神乎其技，并给出宏、:norm、外部命令整合等实战方法。
  【方法/论点要点】
  - 普及度洗脑：全平台制霸，除 Windows 外主流系统基本预装，iPad、安卓都能用；各种 IDE 都有 vim 模拟器，且都能配置一键跳到纯 vim 里改完再回来，「一次学习到处使用」，学习曲线再高也值回票价。
  - 理念一：主打按键序列而非组合功能键。组合键受功能键数量和表义限制，字母不够用、手指要一直按住、功能键本身不表义；按键序列可无限组合且表义，常用设短、不常用设长，如把 IDE 快捷键配成「空格打头空格结尾」，既好记又能减轻小指劳损。
  - 理念二：类似编程的编辑体验（吸引程序员的大杀器）——把编辑看成用短命令变换一坨文本数据。
  - 组合元素：~ciw~（change in word）拆成 3 个可替换元素，~diw~/~caw~/~ci"~ 同理；~xp~ 直接记成「交换两字符」、~ddp~ 交换两行、~bi~/~ea~ 在词首/词尾插入更自然。
  - 命令按逻辑体系设计而非功能拼凑：~r~ 在选中模式下把所选文本都改成同一字符，作者原本觉得没用，后来发现是 markdown 标题下划线的终极方案；常会发现顺理成章但看似没用的设定突然在某场景有奇效，连插件都省了。
  - 丰富的定位与范围限定：到绝对行首 ~0~、到第一个非空字符 ~_~/~^~、下一绝对行 ~j~、下一可视行 ~gj~，以及 ~f F t T W E { }~ 等；关键用途是方便录宏。
  - 录宏三步曲：对齐定位、操作、下一个。~qq~ 开录、~@q~ 重放、~@@~ 重复；例子——查 ~lambda~ 后把第二个括号内容改成 ~x+1~：~F"f(%f(~ 对齐 + ~ci(x+1~ + ~n~ + ~q~。建议尽量用对齐定位功能移动光标，避免滥用 ~hjkl~。
  - 命令像函数：接受「数字/动作/文本对象」参数，数字表示重复执行。
  - ~:norm~ 配合 ~:global~：可用编辑命令显式写「代码」；选中文本时对每一行执行命令。如选中每行行尾加逗号 ~:norm A,~；在选中每行回放宏 ~:norm @q~。
  - 理念三：Vim 是 Unix 生态的重要一环，不只是命令行下好用的编辑器。用 ~set EDITOR=vim~ 配合 ~ctrl-x ctrl-e~ 在命令行里编辑长命令；用 ~cmd | vim -~ 把命令输出当文件编辑；~:r !cmd~ 读入命令结果到光标下方；~:'<,'>!cmd~ / ~:%!cmd~ 把选中/全文喂给外部命令并用输出替换；连续 ~:%!cmd~ 相当于链式 pipe 且可中途改动；对选中内容执行 ~:'<,'>!bash~ 可直接跑 shell。
  - 由此两个体验：vim 可当大部分命令行工具的输入输出界面，自己用任意语言写个读 stdin 写 stdout 的工具即可；只要能找到合适的命令行工具，很多需求无需装插件——格式化 JSON 用 ~jq~、XML 用 ~xmllint~、JS 用 ~js-beautify~。
  - 理念四：小功能定制方便，不必写 vimL 插件，宏 + command + norm + 外部命令就能玩出花。例：在光标处插入 uuid——录宏 ~ma~、~:r !uuidgen~、~yg_~、~"_dd~、跳回标记 a，再把宏转成 vimrc 里的 ~:Uuid~ 命令；或配置 ~:TAFmtJson~ 调用 ~jq -S~ 格式化并排序、设语法高亮与折叠，搜关键字时自动展开路径折叠，是检查深层 JSON 路径的利器。
  - 结论：多数工具扩展靠调 API 且与日常编辑割裂；vim 有 vimL 层，也有「直接模拟手打命令」的流氓方案，并与「宏存寄存器」的特性相得益彰。
