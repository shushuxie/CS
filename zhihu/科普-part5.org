  - 一句话概括：用小故事和「密封饮料 + 吸管」的比喻讲清 API 与 SDK 的区别——SDK 是装着所需功能的软件包，API 是这个包对外的唯一接口，两者是关联而非对立的关系。
  【方法/论点要点】
  - API 的诞生：研发 A 把软件 A 中 B 需要的功能打包成一个函数，B 按流程放进软件 B 就能直接用，这个函数就是 API。日常类比：电脑和手机之间那根数据线的接口，相当于 API 接口。
  - SDK 是什么：Software Development Kit，软件开发工具包；凡辅助开发某一类软件的相关文档、范例和工具的集合都可叫 SDK，目的是减少程序员工作量。例：某公司把某项功能封装成 SDK（如数据分析 SDK）出售给其他公司做开发。
  - API 与 SDK 的区别：两者没有值得比较的区别，是具有关联性的两种东西。SDK 像一个近乎全封闭的虚拟程序包，里面有做好的软件功能，只有一个小小接口连通外界，这个接口就是 API。要在 ERP 里加功能（自动备份、数据分析、云存储），就接入这个 SDK 软件包、通过 API 接口调用其功能。
  - 实例（中铁大桥科研院）：有自研信息平台但系统独立、数据上传备份靠人工操作 Excel，效率低；后来用 API 把简道云插入公司数据库，数据自动上传统一展示，再用 webhook 推送到服务器自动备份——这里简道云扮演 SDK 的角色，其 API 用于对接外部系统。
  - 生活化比喻（核心记忆点）：SDK 是一杯密封饮料，API 是插在饮料上的吸管，你的系统是「你」；想喝到 SDK 里的饮料（让系统拥有该功能），必须通过 API 这根吸管连接，否则喝不到。
  - 一句话总结：SDK = 放着你想要的软件功能的软件包；API = SDK 上唯一的接口。
  - 延伸「前端事件」：一种新的数据获取方式，在数据提交或表单填报时主动调用外部接口，实现接口取数、数据验证、触发事件；可基于现成商业接口零代码配置，也可自行封装接口。说人话就是填快递单号返回物流、上传发票图片返回金额、上传身份证照片获取姓名和号码等，文中附了发票 OCR、身份证 OCR、物流查询、短信发送等一批 Demo。
  - 推广：文末推荐简道云（阿里云为依托的云办公平台），并列出进销存、OA、人事、CRM、SRM、ERP 等模板。

  「密封饮料 + 吸管」这个比喻确实好懂，把「SDK 是包，API 是包上的口」讲得比大多数定义清楚。不过要补充一点：SDK 通常包含 API，但 API 不依赖 SDK 也存在（比如一个 HTTP 接口根本没有 SDK）。这篇用于快速给小白建立直觉很合适，深究时仍需注意这个概念上的不对称。

  - 本地原文：[[file:原文/2026-10-19-如何跟小白解释路由器和交换机的区别并且家用路由器充当了路由器和交换机的功能吗-402261894.org][打开本地归档]]
  - 一句话概括：用「几个小伙伴联机玩《帝国时代》」的故事，从两台电脑直连讲到集线器、交换机、路由器，说明三者的分层与适用场景，并解释家用路由器是路由猫（兼具猫与简单交换机功能）。
  【方法/论点要点】
  - 起点：小 A 用小 B 发明的「网口」+ 一根网线实现两台电脑直连。
  - 集线器（HUB）：每台电脑只有一个网口，无法三台互联，于是做一台有多个网口的微型计算机——集线器。它只是把网线集结起来做最初级互通，靠网线直接传送数据，工作在物理层；缺点是不能分辨信息发给谁，只能广播，所有设备处于同一冲突域（一人说话别人不能发言，否则信息碰撞）。
  - 交换机：给设备加入「根据网口名称自动寻址」的指令，把网口命名为 macA、macC 等，数据按端口地址精确传送、不再广播给其他人，解决了冲突、实现任意两台电脑互联。因按网口地址（MAC）传送，工作在数据链路层。
  - 路由器：不同村落的交换机相连却无法通信，因为各村的「操作系统」（信息传送形式）不同。于是规定各村先加一套相同协议，通信时信息经协议加工成统一形式，再经一台特殊设备传送——路由器。它通过 IP 地址寻址，工作在计算机的网络层。这套协议就是 TCP/IP 协议簇，互联网由此形成。
  - 一句话区别：交换机适合局域网内互联，路由器实现全网段互联；局域网内对战用交换机，与外面更大的世界交流才用路由器。
  - 关于「猫」：学名调制解调器，作用是把电脑要发的数字信号转换成网线中的模拟信号（电流脉冲），所以计算机信号必须经它传送。目前家用路由器一般是路由猫，兼顾了猫和简单交换机的功能，选购时选一款性价比高的路由猫即可。
  - 补充：物理地址、逻辑地址、交换机与路由器的寻址方式等属于更专业范畴，作者留待另开专题。
  - 说明：本文为便于理解忽略了很多细节，实际发展过程和工作原理并非如此简单。

  #+end_quote

  #+end_quote

* 为什么航空器的速度单位是「节」，而不是更常用的「千米/时」？  :科普:航海:单位:航空:
  :PROPERTIES:

  :作者:  Choir Glee
  :原文:  [[file:原文/2026-10-19-为什么航空器的速度单位是节而不是更常用的千米时-2060826845.org][本地原文]]
  :抓取:  2026-10-19
  :END:
  - 本地原文：[[file:原文/2026-10-19-为什么航空器的速度单位是节而不是更常用的千米时-2060826845.org][打开本地归档]]
  - 一句话概括：因为航空与航海高度相似（缺参照物、只知相对介质的速度、需掌握经纬度绘航图、长距离航行需考虑地球曲率），故直接照搬航海单位「节」；并讲清「节」由扔圆木片测速而来、1 节 = 1 海里/时 = 1852 米/时的来历。
  【方法/论点要点】
  - 为何照搬：航行缺乏参照物，只能借助天文/地磁/航速/时间导航；只能获得相对介质的速度；可近直线行进（不像地面只能沿弯曲道路）；都需掌握经纬度以绘航图、规划路线；都需长距离航行，地球曲率不可忽略。飞机要独立导航，非用航海导航法不可，单位随之照搬。
  - 「节」的测法（现代化工具之前）：从船尾扔下一块系绳的圆木片（chip log，从整根圆木上切下的一片）测速。「log」既指圆木又指日志，正源于此（logbook→.log 文件、vlog）。
  - 测速原理：圆木片下端配重，上端浮起、下端垂直没入水中受阻力最大，而绳子可自由拉出，故木片相对水面可视作静止；绳上预先每隔一段距离打结，水手放绳并用 30 秒沙漏（现代规定 28 秒）计时，计时结束时放了几个结，船速便是几节。
  - 历史铺垫：1500 年前很难在开阔海域航海，只能靠「死推（dead reckoning）」——按测得船速、罗盘航向、简单计时估算位置，误差离谱，基本沿岸航行、入深海靠运气。
  - 定位问题的解决：六分仪（观测北极星高度角测纬度）+ 精确时钟（测太阳高度最大时为当地正午，对比出发地时钟得经度），船只终于能测经纬度。
  - 统一单位的动机：船能测经纬度后，若距离仍用里格、英里等陆地单位，换算极麻烦且易算错（算错可能触礁丧命、又少了喝朗姆的时间）。于是规定：沿任意大圆（过地球球心的圆）航行 1 分（1/60 度）的距离为 1 海里，每小时 1 海里的速度为 1 节——既便于计算又与陆地单位接近。
  - 标准化：地球非完美球体、测量有误差，各国海里长期不同；1929 年第一届国际水文会议统一为 1852 米，美英分别到 1954、1970 年才采用，形成今天世界公认的海里与节。
  - 由此推算绳结间隔：28 秒 × 1852 米 / 3600 秒 = 14.4 米；文中视频里为缩短长度/时间改用 10 秒计时，绳结距离约 5.14 米（上传者说 17 英尺 ≈ 5.18 米）。

  #+end_quote
  #+begin_quote

  #+end_quote
  #+begin_quote
  航行日志logbook也得名于此。后来航行日志又引申为用于记录的文件——因此有了.log文件，有了vlog。
  #+end_quote
  #+begin_quote
  使船沿着任意大圆航行1分（60分之1度）的距离为1海里，而令每小时1海里的速度为1节。

  【我的想法】
  把一个看似冷门的单位问题讲成了完整的航海史：从「为什么航空用节」倒推到「节怎么来的」，再顺带解释了 log/logbook/.log 的词源，信息密度很高。最有意思的是那个动机——用经纬度相关的海里、节，不是为了风雅，而是为了让水手少算数、多喝酒、少触礁，单位背后全是真实的生存压力。

  - 一句话概括：人类历史上第一个程序 Bug——1947 年哈佛 Mark II 计算机被一只飞进继电器的蛾子卡停，程序员找出虫尸后，「程序错误」从此被称为 Bug。
  【方法/论点要点】
  - 事件：1947 年，哈佛大学的哈佛二代（Harvard Mark II）突然停止运行，程序员费尽周折找到一具虫子尸体，「Bug」一词由此而来。
  - 背景：哈佛二代当时还没有二极管和晶体管，是继电器计算机，无数电磁开关喀哒作响；开关断开时会发出电弧闪光，蛾子飞了上去。
  - 结果：这只蛾子被永久保存在华盛顿的美国国家历史博物馆（作者注：有人指出是国家档案馆，但查无直接证据，目前流传的版本多为「国家历史博物馆」）。
  【原文摘录】

  你看到的是人类历史上的第一个程序Bug——烧糊的蛾子一枚。
  #+end_quote

  #+end_quote
  #+begin_quote
  当开关断开的时候会有电弧发出闪光，于是这只妖蛾子奋不顾身地飞了上去。
  #+end_quote
  【我的想法】
  短短几行讲清了「Bug」一词最著名的出处，也顺带还原了继电器计算机时代那点画面感——电弧、喀哒作响的开关、扑上去的蛾子。这更像一条冷知识而非技术分析，但确实是「目瞪口呆」这个词的完美注脚。

  - 一句话概括：把 SICP 从「Scheme 教材」重新定位成一本讲系统设计的书，指出计算机专业由算法与系统两条腿组成，而系统设计长期缺少独立课程，SICP 正是用构造抽象的方式补这一块。
  【方法/论点要点】
  - 作者认为 SICP 可以看做讲系统设计的书，计算机专业的核心是算法和系统两块（参照 Stanford 的 CS Core 分成 Theory 和 System）。
  - 软件工程更像工程项目管理，说 SICP 在讲软件工程「挺奇怪」。
  - 算法设计与分析的书很多、流传很广；系统设计与分析却没能总结出一套系统概念、形成独立课程，多靠操作系统、数据库、编译原理这类 Case Study 来学。
  - 这种 Case Study 式教学的代价：计算机专业课程量过大，重要概念被淹没在具体系统里，所以系统设计相对算法「不太好说清楚」。
  - SICP 提出的方法论分五部分：构造过程抽象、构造数据抽象、模块化/对象和状态、元语言抽象、寄存器机器里的计算。
  - 书中构建了很多小系统：第一章的素数、最大公因数、平方根、积分、黄金比例（讨论递归与迭代过程）；第二章的图形语言、赫夫曼编码解码、泛型算数包、多项式计算包（讨论数据结构与类型系统）；第三章实现一个面向对象系统；第四章实现 Scheme 解释器；第五章作者自称还没看。
  - 作者的保留意见：SICP 在语言（Scheme）、内容（数值计算系统、编程语言系统）、时间（第二版 1996 年）上都太非主流，不确定其中概念今天是否仍算主流。
  - 提到当前不少名校的系统设计入门教材是 MIT 出的《Principles of Computer System Design: An Introduction》。
  - 文末附作者做的前两章课后习题答案（140 道）及他人答案链接：GitHub 仓库 strint/sicpAns。

  - 一句话概括：从户外 LED 屏一路讲到显存和显卡，说明屏幕上的字和图片本质上都是像素点的亮暗与三原色配比，字符不过是显卡 BIOS 里预存的点阵图形，逐行扫描后才变成我们看到的画面。
  【方法/论点要点】
  - 核心结论：大多数计算机中的文字和图像都以像素形式显示；显示字符的本质也是显示图像，每个汉字、英文字符都是以像素形式输出。
  - 类比：十字绣用色块拼出图像，和像素显示同理；区别在于显示器要显示的内容是动态、变化的。
  - 单色 LED 显示屏：由一种颜色的发光二极管组成，驱动电路决定每个二极管亮或灭，每个二极管就是一个「像素」。
  - 彩色化：把红、绿、蓝三种发光二极管做到一起，以不同亮度发光即可合成多种颜色；户外广告屏就是这种原理，二极管越小越多，画面越细腻。
  - OLED：有机发光二极管，可做得很小很薄（如 iPhone X）。每个像素由三个发光二极管组成，像灯泡一样会老化，长期高亮度显示同一画面会导致老化不均，即「烧屏/残影」；因为是主动发光，还能做成透明屏。
  - LCD：本身不发光，靠白色背光；薄膜晶体管控制液晶偏转角度来调节透光亮度，再经彩色滤光片分成三色、强弱不同的光，合成颜色。LCD 的老化通常是背光整体老化，表现为颜色不鲜艳、屏幕发黄，不会局部残影。
  - 色彩数量：每种颜色亮度分 0-255 级，三色组合有 256×256×256 = 16,777,216 种，已超过人眼分辨力。
  - 驱动板：一边控制面板上每个子像素的亮灭，一边通过 VGA/HDMI/DVI 等接口与主机显卡连接、接收显示信号。
  - 扫描方式：显示器不是一次性控制所有像素，而是一次控制一行、自上而下逐行刷新，每秒约 60 次，所以看不到闪烁；这样做是为了降低硬件设计复杂度。用高速快门拍老式 CRT 能看到一行行显示，液晶也逐行扫描但拍不出来。
  - 显卡三要素：显存、显卡 BIOS、GPU。显存存放即将显示的数据，程序员把字符或图像数据送入显存，后续交给 GPU 和外围电路。
  - 显示字符：把 ASCII 编码送入显存即可，例如在屏幕左上角显示 Z，把 90 写入 0xB8000000 起的第一个字节，第二个字节控制显示格式（示例 C 代码为 char far *vBuffer=(char far*)0xB8000000; *vBuffer=90; vBuffer++; *vBuffer=7;）。之所以送 90 就出现 Z，是因为显卡 BIOS 里存了每个 ASCII 字符的像素图形数据，GPU 按编码取出并转成电信号。
  - 显示图像：把每个像素的 RGB 值送入显存，GPU 转成电信号输出给显示器；程序也可以直接向 GPU 发指令，做复杂 3D 显示或其他计算。

  - 一句话概括：以「一个数据包」为主角，把一次网页访问拆成 HTTP→DNS→协议栈→TCP→IP→MAC→网卡→交换机→路由器→服务器拆包十站，逐层讲清每层加了什么头部、靠什么表找到下一跳。
  【方法/论点要点】
  - 01 HTTP：浏览器先解析 URL，确定 Web 服务器和文件名；路径省略时访问根目录下的默认文件（如 /index.html、/default.html）；随后据此生成 HTTP 请求消息。
  - 02 DNS：委托操作系统发消息前必须知道对方 IP。域名用句点分隔，越靠右层级越高，结构为根 DNS→顶级域（com）→权威 DNS。解析流程：客户端问本地 DNS → 本地 DNS 查缓存，未命中则问根域名服务器 → 根只指路，给出 .com 顶级域名服务器地址 → 再问顶级域 → 顶级域给出权威 DNS 地址 → 权威 DNS 返回 IP → 本地 DNS 回传客户端。特点：「只指路不带路」。
  - 03 协议栈：应用层通过 Socket 库委托协议栈；上半部是 TCP/UDP，下半部是 IP；IP 还包含 ICMP（报告传输出错与控制信息）和 ARP（由 IP 查 MAC）；再往下是网卡驱动和网卡。
  - 04 TCP：头部含源/目标端口（否则不知发给哪个应用）、序号（解决乱序）、确认号（解决丢包，未收到就重发）、状态位（SYN 发起连接、ACK 回复、RST 重连、FIN 结束）、窗口大小（流量控制）。TCP 还做拥塞控制——改不了通路堵不堵，只能控制自己的发送速度。
  - 三次握手：服务端 LISTEN → 客户端发 SYN 进入 SYN-SENT → 服务端回 SYN+ACK 进入 SYN-RCVD → 客户端回 ACK 进入 ESTABLISHED → 服务端收到 ACK 也进入 ESTABLISHED。目的是保证双方都有发送和接收能力。Linux 可用 netstat -napt 查看连接状态。
  - 数据分割：MTU 是一个网络包最大长度，以太网一般 1500 字节；MSS 是去掉 IP 和 TCP 头部后能容纳的 TCP 数据最大长度；HTTP 消息超过 MSS 就按 MSS 拆分，每块加 TCP 头后交给 IP。
  - 05 IP：IP 头需源地址和目标地址，协议号填 06（十六进制）表示上层是 TCP。多网卡时靠路由表决定源地址：把目标 IP 与各条目子网掩码做与运算，结果与 Destination 匹配即选用对应网卡；都不匹配则走 0.0.0.0 的默认网关。Linux 用 route -n 查看路由表。
  - 06 MAC：MAC 头含发送方和接收方 MAC，用于两点之间传输；协议类型 0800 表示 IP、0806 表示 ARP。发送方 MAC 从网卡 ROM 读取；接收方 MAC 由路由表的 Gateway 决定，再用 ARP 广播「这个 IP 是谁的」来获取。查询结果存入 ARP 缓存（几分钟），可用 arp -a 查看。
  - 07 网卡：网络包只是内存中的二进制，需由网卡驱动复制到网卡缓存区，加上报头、起始帧分界符和末尾的 FCS 帧校验序列，再转成电信号通过网线发出。
  - 08 交换机：工作在 MAC 层，二层设备，将包原样转发。端口不校验接收方 MAC、直接收下所有包，因此交换机端口不具有 MAC 地址；查 MAC 地址表（MAC + 端口）决定从哪个端口发出。查不到就向除源端口外的所有端口泛洪，目标设备响应后即可学习进表；广播地址 FF:FF:FF:FF:FF:FF 和 255.255.255.255 也会泛洪。
  - 09 路由器：三层设备，端口同时有 MAC 和 IP。收到包先 FCS 校验、核对接收方 MAC，不匹配则丢弃；然后去掉 MAC 头，按 IP 头查路由表（子网掩码与目标 IP 做与运算匹配，找不到走默认路由）。发送时看网关列：网关是 IP 说明还没到终点，网关为空说明目标 IP 就是终点；再用 ARP 查下一跳 MAC，填自己出口端口的 MAC 作为源 MAC。
  - 关键结论：整个传输过程中源 IP 和目标 IP 始终不变，一直变化的是 MAC 地址，因为 MAC 只负责以太网内两个设备之间的一跳传输。
  - 10 服务器与客户端：服务器逐层拆 MAC→IP→TCP（校验序列号、回 ACK、按端口交给 HTTP 进程），HTTP 进程生成响应报文后再套上 TCP/IP/MAC 头原路返回；客户端拆包后交给浏览器渲染页面，最后四次挥手断开连接。
  - 文末作者分享学习心得：啃书太理论、易忘，用故事和生活例子讲网络协议更容易把知识点串起来，并推荐了极客时间《趣谈网络协议》专栏。

  【方法/论点要点】
  - 诊断：觉得《TCP/IP 详解》看不懂，是因为只记住了「协议很重要」这个概念，没见过协议具体在什么场合、以什么形式被使用；网络协议本身抽象，要先形象化再学工作过程。
  - 核心类比：网络协议相当于人与人之间的礼仪，人是礼仪的主体，网络设备是协议的主体；协议本身是一个软件，以系统组件形式装在操作系统里——就像两台电脑都装了 QQ 才能聊天。
  - 学习原则：初学者「知道为什么这么做」比「知道怎么做」更重要；不必一上来抠字段细节，否则只见树木不见森林。先理解 HTTP、FTP、DHCP、DNS、ARP 等常见协议的工作过程，其余依葫芦画瓢。数据包结构浏览各字段作用即可，重点记 IP 头部的源/目的地址和 TCP 头部的源/目的端口号。
  - 寄信类比逐层展开：写信产生数据，寄信传递数据；信封上的收信人地址/寄信人地址对应 IP 头部的目的 IP/源 IP；只有地址不够，因为一栋楼里住很多人，所以还要收件人姓名/寄件人姓名，对应 TCP 头部的目的端口/源端口。
  - 完整例子：南宁的李小明用 QQ 给沈阳的王小花发消息，电脑把消息打成 TCP 数据包，网络按目的 IP 送到王小花电脑；但她电脑上同时开着 QQ 和微信，不知道交给谁，于是靠端口号区分（文中假设 QQ 8000、微信 8080）。作者自己注明这个例子不严谨，因为 QQ 和微信实际走腾讯服务器中转，但初学者不必一开始深究。
  - 校验和：信封是否完整可判断有没有被拆开篡改，对应数据包里的 TCP 校验和字段。
  - 开销视角：寄信要买信封邮票信纸，这些对「传递信息」本身是额外花销，但没有就寄不出去；网络里对应的花销就是各层协议头部（应用层数据之外的部分）。平信与挂号信对应不同场景选不同协议，有时需要多协议配合。
  - 顺着一封信的疑问引出后续知识点：电脑怎么知道对方 IP（→ DNS）、数据包由谁帮我们传（→ 网关）、网关怎么送到目的地（→ 各种路由协议）。
  - 人类交流类比：打电话接通不会立刻长篇大论，要先互道「你好」确认对方在听，这就是 TCP 建连接前的先沟通、再传输；UDP 则像校园广播，播出去你有没有听到与广播站无关，也不会因为你没注意重播。
  - 广播与广播风暴：一个广播包会让子网内所有主机都收到并处理，方便但增加无关主机的负荷；作者用广场舞多个大喇叭同时播放来形容广播风暴。
  - 设计者思维（以 DHCP 为例）：电脑启动后广播寻找 DHCP 服务器，服务器广播响应。接着要自问异常：服务器恰好宕机怎么办（一直发？不再发？隔段时间再发？）、地址池分配完怎么办、同时有两台以上 DHCP 服务器怎么办、已分配的地址是否回收、是主动询问还是设定租期。
  - ARP 与 ARP 攻击：先学 ARP 工作过程，再查 ARP 攻击——ARP 用广播发送，且协议规定即使没发过请求，收到 ARP 回应也要处理并写入缓存；所以有人伪造「网关 IP 对应错误 MAC」并广播，你的电脑必须接受，于是上不了网。这说明协议设计时没考虑到有人会伪造回应包。
  - 学习路径建议：看《TCP/IP 详解》吃力就先放一放，改看《计算机网络：自顶向下方法》（作者写作《计算机网络自顶向下方法与 Internet 特色》），可读性强；理解常见协议后动手做实验，先用 Cisco Packet Tracer 模拟器（有动画式传输过程和抓包功能），比真机抓包直观。
  - 收尾提醒：TCP/IP 是一个协议族、一大堆协议的集合，那套书三卷每卷都很厚，别指望一篇帖子讲完。

  - 一句话概括：不讲加法器，而是从 Ice Lake 的 Sunny Cove 微结构讲指令进入流水线之前发生了什么：指令与数据分居两个 L1 Cache，CISC 指令在解码器被拆成若干 RISC 式微操作再进流水线，而微码存在 ROM 里、靠 RAM 打补丁，所以每次重启都要重打。
  【方法/论点要点】
  - 定位：其它答案常举加法器等逻辑运算单元，但那只是 decode 后端的末尾；真正复杂的逻辑在前端、后端发射和流水线部分。
  - 前提：高级语言被编译成机器码才能被 CPU 识别执行；汇编只是方便人类读写机器码的中间形式。指令和数据在解码前分别放进指令 L1 Cache 与数据 L1 Cache——L1 是唯一把指令和数据分开的 Cache。
  - 解码器分两种：硬件指令解码器完全由硬件连线实现，由有限状态机驱动，速度很快，至今仍在很多 RISC CPU 中发挥作用；微码指令解码器用于复杂指令。
  - x86 属 CISC，指令多且长短不一，全部用硬件解码不可能完成，所以一条机器指令被拆成数个类似 RISC 的精简微操作（Micro-Ops），这些微操作可以被硬件完整执行。
  - 拆分数量取决于指令复杂度：极简单的只有 1 个 micro-op，一般 3 个左右，复杂的 4 个以上。化繁为简之外，微操作作为可执行的最小单位还能被调度进流水线，从而提高指令级并行性；之后才进入 ALU、IMUL 等由逻辑门搭成的运算单元。
  - 微码（Microcode）并不遥远：它就是很多人每次重启都在更新的东西；Kaby Lake 等 CPU 的 Meltdown 问题就是靠它修正的。微指令解码时从 CPU 内的一块 ROM 中取出翻译好的微指令。
  - CPU 出 Bug 时还有一块 RAM 用来 patch 这块 ROM；正因为是 RAM，Microcode 补丁每次重启都要重新打上；也因为这个补丁在 decode 这么底层的位置介入，才能修正很多原本要改硬件才能解决的问题。
  - 收尾判断：decode 这个过程让 RISC 与 CISC 的界限变模糊——RISC 加入了越来越多指令，部分指令也改用微码解码；CISC 因为引入 Micro-Ops，在 decode 后端表现出 RISC 的特性。

  - 本地原文：[[file:原文/2026-10-20-CPU是怎么认识代码的-843382847.org][打开本地归档]]
  - 一句话概括：用二极管、门电路、加法器一路搭到一台只有三条指令的假想 CPU，再把机器码、汇编、逆波兰式、栈和流水线串起来，回答了「01 凭什么能指挥硬件」这个最常见也最难讲清的问题。
  【方法/论点要点】
  - 起点是半导体：二极管单向导通，正接相当于导线、反接相当于断开，用这个开关特性就能拼出逻辑门。
  - 四种基本门：与门（两输入都为 1 才输出 1）、或门（有一个 1 就输出 1）、非门（取反）、异或门（两输入不同输出 1，相同输出 0）。有电压记为 1，无电压记为 0，具体几伏不重要。
  - 实际芯片并不用二极管三极管做门，因为它们太费电，真实器件是场效应管（MOS 管）。
  - 先做半加器（两输入两输出，S 是结果、C 是进位），再为解决低位进位问题做全加器（三输入两输出：两个加数 + 上一位进位），把全加器串起来就是 4 位加法器。
  - 乘法不用专门电路：左移一位即乘 2，最低位补零；乘 3 = 移一次再相加，乘 5 = 移两次再相加。所以简单 CPU 没有乘法指令，乘法靠位移加加法由软件合成。
  - 早期计算机真的靠插线编程：改一个算法就要重新接线，「几分钟就算完了但插线好几天」。
  - 引入触发器（flip-flop，RS 型：R 置零、S 置一、都为 0 时保持）存 1 bit，并联几个就是寄存器；再引入 MUX 选择器，由 sel 决定输出 i0 还是 i1。
  - 给加法器、位移器各加一个「激活针脚」，就可以用指令位决定数据流向哪个模块，这是「CPU 看懂指令」的物理本质。
  - 示例 CPU 设计成 8 个输入针脚：4 位指令 + 4 位数据，三条指令分别是 0100 读入寄存器、0001 与寄存器相加、0010 左移一位；用 (1+4)*2+3 走了一遍。
  - 真实 CPU 模块太多，靠解码器（decoder）把指令翻译成各模块的使能信号；示例里加法器的激活条件从 p4 变成 (NOT (p1 OR p2)) AND p4。
  - 执行一条指令并非一步完成，要读指令、执行、写回；经典 RISC 分五级：IF 取指、ID 解码、EX 执行、MEM 访存、WB 写回，x86 有些指令要拆近 20 步。
  - 用触发器还能保存「走到第几步」的状态，这就是有限状态机（FSM）的硬件实现思路。
  - 机器码是 CPU 唯一能直接理解的语言，但人读不了；汇编与机器码一一对应，既能直接指挥硬件，也能把内存 dump 成汇编来调试。
  - 高级语言到机器码要经过编译：示例先把 (1+4)*2+3 转成后缀式（逆波兰式）1,4,+,2,*,3,+，消掉优先级和括号，再顺序翻译成 MOV/ADD/SHL/ADD。
  - 栈本身是数据结构、与 CPU 无关，但太常用所以被硬件优化：加寄存器 A/B、加 RD/WR 访存指令、再加 SP 和 PUSH/POP 专用指令，因为专用指令开销小、速度快。
  - 顺带解释 DDR：在一个开关周期内把地址和数据都换一次，按一下存两个数，即双倍速率。
  - 历史落点：1969 年 BUSICOM 想做程控计算器，负责 CPU 的美国公司不想每次都重设计，1970 年推出 4004，这家公司就是 Intel。

  - 一句话概括：一段十几行的 Processing 代码把「帧数」当成一个巨大的计数器，逐位映射到每个像素的颜色上，于是屏幕会穷举出所有可能的图片——然后作者用这个设定算出了那个荒谬到无法完成的时间。
  【方法/论点要点】
  - 核心思路只有一件事：穷举。每个像素的颜色由 frameCount（当前帧数）按 255 进制拆位后决定，`pow(255, i+j*width)` 就是第 i,j 个像素对应的位权。
  - 三个通道分别取第 k、k+1、k+2 位，再对 255 取模，就得到这个像素的 R/G/B；随着帧数递增，像素颜色按 255 进制像里程表一样进位。
  - 假设 frameCount 可以无限大，那么盯着屏幕看，就能看到所有像素的所有组合——包括所有艺术大师的作品、人类历史上所有光辉的瞬间，以及这个回答下的任何图片。
  - 数量级计算：每个像素 256³ ≈ 1600 万种颜色，1000×1000 分辨率共有 256 的 3000000 次方张图。
  - 按一秒看一张、一年 31536000 秒算，走完这条长廊需要 10^7224712 年；而宇宙年龄只有 140 亿年（1.4×10^10 年），从大爆炸看到现在也看不完。
  - 降精度也救不回来：100×100 黑白二值共 2^70000 ≈ 10^3010 张，分给 70 亿人，每人仍要不眠不休看 3.17×10^3002 年。

  }

  - 高低配（洋房别墅+高层）的算术：10 万平米若全做高层均价 1 万只得 10 万；8 万高层+2 万洋房（1.5 万/平）得 11 万。所以洋房侵占绿地，高层被牺牲楼间距和公共活动空间。
  - 销售常说「有别墅洋房的高层更高级」，作者判为纯忽悠：同等容积率下，纯高层社区的居住感往往更好。
  - 容积率对照品质：低于 0.3 高档独栋；0.3-0.5 一般独栋、密度偏大；0.5-0.8 双拼联排；0.8-1.2 多层为主；1.2-1.5 正常多层、环境一般；1.5-2.0 多层+小高层；2.0-2.5 小高层；2.5-3.0 小高层+18 层内二类高层（全小高层环境会很差）；3.0-6.0 百米内高层；6.0 以上摩天楼。
  - 层数口径：低层 1-3 层、多层 2-6 层、小高层 7-11 层、12 层以上高层、33 层以上超高层（原文如此）。
  - 学区归教育局定、地铁要多轮审批，除非已招标或在施工，否则不能算确定。判断依据是城市规划图，去规划局（住建局）网站找。
  - 先看城市总体规划的空间布局文字和图：北京「一核一主一副、两轴、多点、一区」，通州作为「一副」排在一核一主之后；杭州明确江北老城与钱江新城、钱江世纪城双主中心；深圳中心仍是福田-罗湖与前海，西优于东。
  - 再看区域用地规划图：浅黄住宅、红色商业、绿色公园、橙色中小学；蓝色线为短期规划/在建的确定地铁，销售口头的远期线路不确定性高。预售证、项目信息、签约情况可上住建部网站查。
  - 户型第一指标是面宽，因为得房率、公摊查不到确切数字，而面宽可以量。建筑师为做大总建筑面积并满足日照，常用「减面宽、增进深」，所以狭长户型多。
  - 户型图分三档：只画格局不标尺寸的（没良知）、标面宽进深的（尺寸含墙体）、连各房间面积都标的（可反算得房率）。售楼处不标就一定要问。
  - 净面宽参考：主卧标准 3.3m，小于即紧凑，舒适 3.6m，3.9m 以上常配主卫衣帽间；次卧最低 3.0m；儿童房书房最低 2.7m；客厅标准 3.6m，大于为舒适型，豪华 5-6m 以上。
  - 方正即进深/开间比合理，一般介于 1~1.5；比较时选比值大的。北方总进深 13、14m 是常态，南方超过 12m 基本没人买。
  - 必看楼层平面图，销售绝不主动给。「没看过楼层平面图，等于没看过户型图」，最关键是采光：窗户可能开在深凹槽里，中间户凸起还会挡两侧边户采光。
  - 高层连廊户型作者强烈反对：为了南北通透而通透，北窗在深槽内又被连廊挡住，公摊大到血亏，还有被偷窥风险，「中间户、边户，通通不要买」。
  - 平面图还能看出卫生间窗户贴邻居、门对门、卧室挨着邻居客厅等户型图上看不到的问题。

  - 本地原文：[[file:原文/2026-10-20-那些复杂的折纸艺术是怎么想到的-38771338.org][打开本地归档]]
  - 一句话概括：解释复杂折纸不是靠灵感硬折，而是「画折痕图（CP）」：先用几条可验证的几何规则保证图纸可折，再用圆圈法或蛇腹法把造型抽象成树状分支，最后才动手折。
  【方法/论点要点】
  - 折纸设计三步：定造型、把树（作品特征）与纸（折痕规律）结合、出成品。第一步最简单，第三步有经验者也不难，难的是第二步，往往要靠「奇技淫巧」。
  - 关键是先看纸的特征，即折到 Base（基本形）后展开的样子，也就是折痕图（Crease Pattern，CP 图）。
  - CP 构造基本规则一：若 Base 仍是平面结构，CP 可用两种颜色着色。
  - 规则二：折痕线上每个点，相连的峰线数 M 与谷线数 V 满足 ~|M - V| = 2~。
  - 规则三：矩形内部折痕线交点周围，各角交错求和为零，即 ~∠1 - ∠2 + ∠3 - ∠4 + ∠5 - ∠6 = 0~。
  - 规则四：纸层不能相互穿透——这条从 CP 图上直接看不出来。
  - 设计方法里最重要的是树状设计。一、圆圈法：树的一个叶子分支对应纸上一块区域，该区域是某个圆的外切多边形，设计时只需关注这个圆；枝干则看成两条平行线或同心圆弧构成的「河流」。
  - 举例：11 个圆 + 3 条河流，就能设计出一只昆虫（分支 J 在最后整形时被压平，所以不太看得出）。由圆与河流画 CP 就按前述规则来。
  - 二、蛇腹法：矩形纸里填圆有难度，填矩形就自然多了。叶子分支变正方形，枝干变平行四边形或直角梯形组成的「直角河流」；为不破坏 CP 规则，折痕之间通常成直角或 45 度，即要画格子，正方形边长与河流宽度都是整数格。
  - 蛇腹法因为画格子简单、成品方正，常被用来折字；作者自嘲「其实我就只会折字」，并让对方去找 @Milo Yip 看真东西。
  - 实际设计两种方法综合使用，例如用圆圈法设计的千纸鹤，可以用蛇腹法改造、加上尾羽。
  - 文中配图多引自 Robert Lang 的 TED 演讲《The math and magic of origami》。

* 为什么品牌衣柜的主材多是实木颗粒？  :科普:装修:板材:甲醛:

  :链接:  https://www.zhihu.com/question/21562137/answer/253200876
  :作者:  装小蜜监理王志峰
  :原文:  [[file:原文/2026-10-20-为什么品牌衣柜的主材多是实木颗粒-253200876.org][本地原文]]
  :抓取:  2026-10-20
  :END:
  - 本地原文：[[file:原文/2026-10-20-为什么品牌衣柜的主材多是实木颗粒-253200876.org][打开本地归档]]
  - 一句话概括：从生产工艺切入把胶合板、大芯板、指接板、密度板、刨花板、欧松板逐个拆开讲，再点破「实木颗粒板就是刨花板」的命名游戏，最后落到板材品牌、家具品牌和甲醛国标，是一份能拿去怼销售的板材底稿。
  【方法/论点要点】
  - 总纲：板材无非「皮和芯」，抓住根本，让销售说清皮是什么皮、芯是什么芯，就不会被「实木 / 生态 / 零甲醛」这类词绕晕。
  - 一、胶合板：原木旋切成薄片（最薄 0.3mm，厚的 8mm，常用 2-3mm），涂胶后一层层热压。便宜、硬度不错、适合现场裁切；但用胶多，所以现在少用它现场打家具。别名夹板、三合板、九厘板（按工艺、层数、厚度命名），商家叫「多层实木板」也是它。
  - 二、大芯板（细木工板）：小木条拼接成芯层，上下各贴一张涂胶表板热压。芯层木条间可施胶也可不施胶。北京地区多用于窗帘盒、吊顶造型、门框加衬垫。怕潮湿，不适合厨卫。
  - 三、指接板：不贴上下表板，木条端头开榫（像木梳的齿）再拼接、侧面涂胶冷压。分明齿与暗齿（正面无痕更美观）。被称大芯板 2.0：多一道开榫、少了表板所以胶少很多；硬度取决于树种。别名齿接板、实木集成材，商家常叫「实木板」，但不是整块实木——整块叫原木板。厨房切菜板就是它。
  - 四、密度板（密度纤维板）：木头和植物纤维打成粉末加胶热压。不去皮碾片，经洗、筛、煮、磨成细粉，加胶搅拌预压，切块后进多层吊笼，100 多度、约 5 兆帕热压，再锯边砂光。家装多用中密度，即中纤板 MDF，常用 16、18、20mm。板质密实、易加工上漆贴皮，适合做有造型的柜门。防水差、受潮膨胀快会翘，别用在厨卫；作者意见是衣柜柜体不建议、柜门没问题。
  - 五、刨花板：用木纤维（刨花）而非粉末，热压只要约 10 个压，紧实度不如密度板，横截面中间有孔隙。制刨花后过筛分粗细，加胶搅拌，铺装分三层（上下细、中间粗），预压后 100 多度热压。价格比密度板低：2440×1220×16mm 素板 70 多元起、通常 100 左右，密度板多在一百以上。
  - 两类板的坑：原料以针叶树最好、阔叶树稍差，但为降成本常掺蔗渣、草杆、稻壳，甚至纸、废旧家具、建材垃圾打碎掺入；因为都碎成粉或 2 公分内的纤维，一般人分不出来。
  - 六、颗粒板：就是刨花板，只是「刨花板」听着廉价，商家改叫颗粒板，再加「实木」二字。
  - 颗粒板性能：纤维交叉错落、有相互作用力，韧性好、抗弯、能承重，适合做柜体；比密度板轻、加工省力；防水也强一点，所以大牌橱柜柜体基本用它。表层尚平、里层全是毛刺，切割易爆边，难雕花，做柜门多是平板贴三聚氰胺双饰面。
  - 七、欧松板（OSB，定向结构刨花板）：七八十年代从欧洲引进，原料多为欧洲针叶树；国内建材公司注册「欧松」商标（谐音 OSB）后叫开。刨花特别大、呈几何长片，纯木片（松木、杨木、杉木或混用），没有里粗外细的分层；定向铺装为上下纵排、中间横排，厚度一般 20 以上。三层纵横结构使其材质均匀、韧性好、握钉力强、受潮不易膨胀，国外用于房屋结构；但厚、占地、表面不平，很少打家具。国内近似大芯板的升级替代品，2440×1220mm 要 200 多一张，多用于背景墙基层。
  - 八、板材品牌。爱格板：奥地利爱格集团，1961 年成立，17 家工厂（2 家地板、15 家板材），欧洲 E1、E2 标准最早由它制定；只用寒带针叶树的树干。好但贵。验真三步：官网查授权经销商及供货品牌；要授权书、连续日期的报关单与环保检测报告；合同写明并盖「假一赔十」章。
  - 露水河板：吉林森工产品，原料为长白山东北松与硬杂木。验真：门店用验钞紫外线灯照板面会显出「吉林森工」「露水河」水印；官网查授权商家；2018 年新增二维码查询。
  - 禾香板：烟台万华产品，属刨花板，不用木头而用秸秆和 MDI 胶，MDI 高温也不产生游离甲醛，检测显示 0.01，故「零甲醛释放」名副其实；万华是国内唯一有 MDI 生产资质的企业。验真：要万华授权书、查官网「零醛阵营」；万华只供素板，饰面封边由家具厂做，必须看加工后的检验证明。
  - 大亚板：江苏大亚，有密度板和刨花板，南方用得多。南方潮湿，颗粒板、密度板防潮不如胶合板；北方干燥，整木易裂，颗粒板密度板抗干裂。南方所谓「实木家具」里原木只占三成，其余多是指接板或胶合板。
  - 兔宝宝：浙江品牌，主打环保，明星产品是贴三聚氰胺纸的免漆生态板，2440×1220×17mm 约 200 多一张；「顺芯板」是欧松板芯，「实木多层」是胶合板芯。江浙还有千年舟、莫干山。
  - 九、家具品牌用料。飞美：只用爱格板或露水河板，自己封边，普通封边用汉高牛头牌热熔胶，进口封边只用于白色家具、靠激光融化瑞好封边带。索菲亚：主打大亚颗粒板，也有密度板，饰面用德国夏特。诗尼曼：主推万华禾香板（300-500 多一平），也用华洲颗粒板（200-300 多一平），用德国胶王封边。KD：原木与板材都有，档次大致原木＞密度板＞颗粒板，密度板卖得最好 500 多一平。尚品宅配：柜体主打颗粒板，供应商有翰森、威华等。
  - 价格差异的解释：定制家具卖的不只是板材，饰面、封边、五金、设计、售后都算在平米单价里；好设计能提高空间利用率、减少展开面积（平米单价×展开面积=售价）。
  - 十、甲醛。厂家未必愿意多加胶：最便宜的白乳胶也比木渣贵，胶能少用就少用，压板挤出的胶还会回收；热压 100 多度时甲醛已挥发很多。真正怕的是用好胶还是坏胶：酚醛与脲醛，脲醛便宜但生成反应可逆，温度一高就分解释放游离甲醛，所以不要买用脲醛树脂胶的板材。
  - 木材越细碎施胶越多，但压力越大挤出的胶也越多，加上封边、贴面、开孔等因素，无法断定某大类板材一定比另一类甲醛少，只能落到具体产品看检测报告。
  - 国标是 GB18580-2017，只规定 E1 一级，没有 E0 级。欧标与国标都用 1m³ 气候箱法，方法一样，不必迷信欧标；进口素板回国还要加工，封边不严甲醛照样跑出来，所以要看加工后的检测报告。
  - 检测都是送检，结果只对样品负责；大品牌相对靠谱，合同里写明环保级别，并可加一条允许消费者自行送样检测及不符时如何处理，要盖章。

  【方法/论点要点】
  - 立论：医疗进步让孕产风险大幅下降，反而让很多人（包括医护和计生官员）对风险一无所知；老人常说「过去没产检不也好好的」，作者反问「过去生小孩那么多损败你怎么不说」。
  - 1 提前准备：孕前 3-6 个月完成血常规、尿常规、肝肾功能、甲状腺功能、TORCH（巨细胞病毒、风疹病毒、弓形虫）、妇科、内分泌、传染病（乙肝、梅毒、艾滋病）、口腔、血压等检查；戒烟酒、避二手烟、不熬夜，避开重金属、苯、电离辐射；避免新婚蜜月期怀孕；有心血管、肾脏、精神等疾病先咨询专科与产科；甲减甲亢糖尿病控制正常后再怀；避孕药至少停 3 个月；单位体检和婚检不能代替孕前检查；有遗传病家族史或不良孕产史去遗传门诊。
  - 2 孕期感染：孕前子宫慢性炎症、口腔疾病、生殖系统与泌尿系感染并不少见，可引起胎膜早破、早产、流产、宫内感染、新生儿肺炎、败血症、颅内感染、感染性休克，进展快、死亡率高，也是医疗纠纷高发点。
  - 3 营养：孕前 3-6 个月开始补充，饮食均衡，避免过瘦过胖。营养不良致宫内发育迟缓、低体重、窒息、低血糖、慢性脑损伤，还与中老年代谢病相关；但也要避免增长过快和「大胖小子」观念，巨大儿会增加产伤（骨折、神经损伤、颅内出血）。
  - 4 产检：目的是早筛查、早预测、早诊断、早预防干预。不做或不规律做的理由五花八门——觉得骗人、舍不得钱、嫌排队、头胎正常二胎就不做、前期正常后期就不做，结果每年都有悲剧。
  - 5 确诊畸形该引产就引产：复杂性先心病、唐氏儿、肢体缺失等，生下来往往给全家带来无穷痛苦；不舍得手术的孩子可能死于重症肺炎、心衰，也有弃养、伤害的极端案例。

  - 7 高龄（≥35 岁）：器官功能减退、基础病增多，妊娠期糖尿病、高血压、前置胎盘、胎盘早剥、流产、死胎、早产、低体重、畸形风险都升高；放开二胎后高龄孕产妇死亡率明显上升。
  - 8 避免劳累：过劳是早产重要原因，上班压力大、时间长或长途飞行、坐车奔波都可能诱发。
  - 9 纠正贫血：铁缺乏降低携氧能力，可致宫内发育受限、低体重、早产、死胎、新生儿窒息，以及婴儿期缺铁性贫血；常见孕妇吃药几天就停、不复查，分娩前血红蛋白只有 50-60g/L。
  - 10 甲减：增加流产、胎盘早剥、早产、低体重、先兆子痫、妊娠高血压风险，影响孩子神经发育；不能用「药吃多了不好」为由擅自停优甲乐、不复查甲功。
  - 11 妊娠期肝内胆汁淤积症（ICP）：妊娠特有的肝病，表现为皮肤瘙痒、抓痕、黄染，胆汁酸升高，可伴转氨酶胆红素升高；可致死胎、死产、宫内窘迫、早产、羊水粪染、新生儿呼吸窘迫、心肌损害。孕中晚期不明原因瘙痒要及时就诊。
  - 12 妊娠期高血压疾病：包括妊娠期高血压、子痫前期、子痫、慢性高血压合并妊娠，是孕产妇死亡第二大原因；全身小动脉痉挛致胎盘缺氧缺血，引起宫内发育迟缓、低体重、早产、死胎、脑损伤、脑瘫。别因为「没不舒服」「怕依赖」而不用降压药、阿司匹林。
  - 13 血糖：妊娠合并糖尿病使胎儿畸形风险升高（文中说高 6-9 倍，也有数据说 3 倍），易巨大儿、难产、产伤，新生儿易低血糖、电解质紊乱、呼吸困难、黄疸。要规范做 OGTT、监测血糖、接受运动营养教育，有指征别拒绝胰岛素。
  - 14 胎动：母亲自数是简便的宫内安危评估，研究结论虽不一致，作者认为有参考价值；胎动频繁或减少都可能提示缺氧，需及时就诊做输氧、胎心监护。
  - 15 胎膜早破：临产前自然破膜，可致早产、宫内感染、脐带脱垂、胎盘早剥、新生儿呼吸困难与败血症；难与漏尿区分，可在家备羊水试纸条。
  - 16 B 组链球菌（GBS）：可致胎膜早破、绒毛膜羊膜炎、早产、晚期流产，新生儿肺炎、败血症、化脓性脑膜炎、感染性休克，进展快、死亡率高；国内很多医院已做孕期常规筛查与产时抗生素预防。
  - 17 中晚期腹痛：假宫缩是生理性、持续几秒、间隔长；病理性剧烈腹痛伴阴道流血，可能是胎盘早剥，起病急、可致休克与 DIC，别拖着不来医院。

  - 一句话概括：先区分自我接纳、自我提升与高自尊，再从童年被有条件接纳和时代焦虑解释「为什么接纳不了自己」，最后给出五个可练的方法，落点是行动先于感受。
  【方法/论点要点】
  - 定义：自我接纳是全然地接受此时此地的自己，既能欣赏积极的部分，也能接受消极阴暗的部分，与自身的复杂性共处。
  - 自我接纳聚焦当下，这是它与自我提升的关键区别：自我提升的潜台词是「修补」缺点，以换取未来更被认可的自己，本质是有条件的接纳。
  - 真正的自我接纳是无条件的——「我不是必须变得更好才被自己接纳，现在的我就可以」。
  - 与高自尊的区别：高自尊偏重对自我价值的认同，自我接纳则超越「价值」评价体系，即使眼下的自己还不够好，也仍然喜爱自己。
  - 原因一 未曾被父母全然接纳：临床心理学家 Leon Seltzer 指出，人最初接纳自己的能力来自养育者的无条件接纳；8 岁前自我概念尚未清晰，对自己的理解依赖父母眼中的自己。父母若常说「考不好就不要你了」、在亲戚家认生时指责「不懂事」，孩子会内化这些批评，相信爱是有条件的。
  - 原因二 时代焦虑与自我提升压力：权威与意见领袖设定的标准、优秀同龄人的光环、被贩卖的焦虑，都在说「你还不够好」，于是人越来越讨厌真实的自己，追逐脱离现实的理想自我。
  - 方法 1 设立自我接纳的目标：治疗师 Jeffery Sumber 认为，先在心里明确「讨厌自己不会让人生更好过」、真心希望接纳自己，改变才有契机。
  - 方法 2 列举长处：John Duffy 说人更擅长找缺点，他会鼓励来访者写下优点；写不出就从每天一条、最简单的开始（如「我人还挺好的」）。Ryan Howes 建议列一份清单，写下克服过的困难、达成的目标、建立的联系、帮助过的生命，保存并常更新。
  - 方法 3 觉察内心的「批评家」：那些声音并非理性真相，我们不会这样苛责朋友爱人，它来自非理性的自我厌恶。驱逐不现实，接纳也包括认识它、与它共处。Joyce Marter 建议准备一句「现实咒语」，如「我只是个普通人，我已经做到最好了」。
  - 方法 4 建立支持系统：远离总让自己觉得一无是处的人，多与接纳、相信自己的人相处。这不等于拒绝批评——真正关心你的人会就事论事讨论错误，而非否定贬低。
  - 方法 5 善待自己：有人以为善待自己是自私或不值得。Deborah Serani 说，自我关怀是理解弱点与缺陷是生而为人的一部分，是因为有这些缺陷而爱自己，而不是没有缺陷才爱。做法很具体：按时吃饭、小进步后夸自己、忙一阵就允许休息；窍门是像对待珍视的人那样对待自己。
  - 如果深陷自我厌恶、離自我接纳太远，就先按方法行动（fake it till you make it），让行为反过来影响对自己的态度。
