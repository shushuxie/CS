  - 本地原文：[[file:原文/2026-10-28-VIM学习笔记 文本排序(sort).org][打开本地归档]]
  - 一句话概括：把 Vim 内置 :sort 的行排序、去重、倒序、数字排序，以及「按文本块排序」的四步操作讲清楚；值得收是因为块排序那套「合并行→排序→拆行」的通用套路，可以迁移到日志、配置块、代码段等任何需要保持结构的场景。
  【方法/论点要点】
  - 行范围排序：:3,16sort 排第 3 到 16 行；可视模式下选中后 :'<,'>sort。
  - 去重：:%sort u 排序并删除重复行，只保留第一行。
  - 倒序：:%sort!；按数字排序：:%sort n；数字倒序：:%sort! n。
  - 注意 Vim 的 :sort 与 Linux 的 sort 命令并不完全一致，别混用参数。
  - 块排序（以 troff 的 .KS/.KE 块为例）：① 用 :g/^\.KS/,/^\.KE/-1s/$/@@/ 给块内每行行尾加 @@；② 用 :g/^\.KS/,/^\.KE/j 合并块；③ :%sort 排序；④ 用 :%s/@@ /^M/g 把 @@ 加空格换回换行。
  - 细节：合并行时 Vim 会自动插入一个空格，所以第 ④ 步要匹配「@@ 加一个空格」；^M 用 Ctrl-V Ctrl-M 输入，Ctrl-V 被占用时可用 Ctrl-Q 代替。
  - 这套方法的核心是「先把多行结构压成一行，让排序键落在行首，排完再还原」，并不依赖插件。
  【原文摘录】
  #+begin_quote
  Vim内置了针对文本进行排序的 :sort 命令。你可以使用 :help :sort 命令，查看详细的帮助信息。
  #+end_quote
  #+begin_quote
  使用以下命令，将在排序时去除重复的行。对于重复的多行，将仅仅保留第一行，而其它的行将被删除。
  #+end_quote
  #+begin_quote
  如果我们希望按术语进行排序，那么可以通过合并行将文本块整合为一个整体，然后进行排序；稍后再重新拆分行，来恢复原有的文本格式。
  #+end_quote
  #+begin_quote
  在第2步使用 j 命令合并行时，自动新增了一个空格；所以在第3步的替换命令中，需要查找「@@」字符以及紧随其后的一个空格。
  #+end_quote
  【我的想法】
  这篇短小但很实用，价值全在块排序那四步。它其实是一个通用模式：只要「一条记录的字段跨多行」，就可以用哨兵字符把记录压平、排序、再还原；同样的思路也能用 :g/pattern/ 加外部命令（如 sort -k）实现，但纯 Vim 方案不需要离开编辑器，也不依赖 Unix 工具。真正容易踩坑的是第 ④ 步的 ^M 输入和「@@ 后那个自动空格」，照抄命令时如果少了空格就会替换不干净。另外 :sort 默认按字节序，中文和带数字的混合文本最好显式加 n 或指定 locale；原文没展开这一点，实际用的时候要自己试。

  #+end_quote

  :END:

  - 本地原文：[[file:原文/2026-10-28-精通 vim 你应该理解的几个名词.org][打开本地归档]]
  - 一句话概括：把 Vim 里最容易混的七个概念——buffer、window、tab、mark、register、plugin、VimScript——逐个用类比和命令讲清；值得收是因为 buffer/window/tab 三者的关系一旦理清，多文件编辑就不会再乱开标签页。
  【方法/论点要点】
  - Buffer：打开文件时 Vim 在内存里创建的内容副本，打开几个就有几个；vim a b c 只显示第一个，其余在缓冲区里。:ls 列出、:bn/:bp 前后切换、:b N 按编号、:b name 按文件名（支持部分匹配/正则）。
  - Window：查看 buffer 的视口；多个 window 可以看同一个 buffer，也可以看不同 buffer。分屏操作是 window 层面的。
  - Tab：类似浏览器标签页，但一个 tab 可以包含多个 window；:tabnew [name]、:tabc、:tabn、:tabp、:tabs，normal 下 gt 下一个、1gt 跳到第 1 个。
  - 三者关系：buffer 存内容，window 负责显示，tab 是 window 的容器；日常多文件优先用 buffer + window，别把 tab 当文件列表。
  - Mark：m + 字母打标记；'a 跳到标记行首，`a 跳到标记时光标位置；小写字母文件内有效，大写字母可跨文件；:marks 查看、:delmarks a b 删除、:delmarks! 删除所有小写标记。
  - Register：y 复制进无名寄存器，p 从无名寄存器粘贴；"a 前缀指定命名寄存器（"ayy 复制当前行到 a，"ap 粘贴）；:reg / :reg a 查看；"" 是无名寄存器。
  - Plugin：用插件管理器（推荐 vim-plug）安装/更新/卸载，解决 IDE 类需求；找插件去 vimawesome、GitHub、Google。

  【方法/论点要点】
  - 交错动画：同批元素依次加大延迟（第二个比第一个晚 0.5 秒），起落便错开。
  - 中间扩散：延时取 ~delay + Math.abs(i - middle) * step~，~middle = letters.filter(e => e !== "").length / 2~。
  - JS 把句子拆成字母、逐个加延时；几百个随机延时与随机位置大小的粒子，纯 CSS 即可下雪。
  - 伪类：~:hover~ 最常用，~:nth-child~ 选子元素，~:focus~、~:focus-within~ 管焦点。
  - 伪元素：每个元素有 ~::before~、~::after~ 共三个矩形可画，配 ~clip-path~ 几乎任意形状；绝对定位加 ~padding~ 叠多重边框。
  - ~attr()~ 取 ~data-*~ 值写进 ~content~ 复制文本，再用 ~overflow: hidden~ 遮溢出，配合动画成文字飞舞。
  - 障眼法：渐变模拟光、~translateX()~ 平移、~overflow: hidden~ 裁掉按钮外部分；勾选框与饼图度量计同理。
  - 表单：~input~ 放进 ~label~，用 ~appearance: none~ 或 ~opacity: 0~ 抹掉原生样式，再用 ~+~ 或通用兄弟选择符定制相邻元素，伪元素画框、~:checked~ 表勾选。
  - 阴影：~box-shadow~ 多层叠加更顺滑，扩张半径够大可当遮罩，~inset~ 做内发光；~text-shadow~ 叠出发光、霓虹、伪 3D 字。
  - 背景渐变：~background-clip: text~ 配 ~color: transparent~ 出渐变字；~radial-gradient~ 叠圆点做微粒；~conic-gradient~ 画饼图，伪元素 ~content~ 由 CSS 变量算成度量计。
  - 滤镜：~backdrop-filter~ 毛玻璃，~mix-blend-mode: screen~ 做文字视频蒙版，~clip-path~ 裁形，~-webkit-box-reflect~ 投影。

  - 一句话概括：按建库、查看、修改、分支四类场景归纳 Git 常用指令，逐条说明参数与用法，适合当速查清单。
  【方法/论点要点】
  - 分区：工作区是能看到的目录，.git 是版本库，暂存区（stage/index）与自动创建的 master、HEAD 都在版本库里。
  - 两步提交：~git add~ 把修改放进暂存区，~git commit~ 把暂存区全部内容提交到当前分支。
  - 建远程库：远程库先留空（加 README.md 会推不上去）→ 本地 ~git init~（.git 勿手改）→ ~git remote add origin git@github.com:michaelliao/learngit.git~ → ~git push -u origin master~，~-u~ 兼做推送与关联，之后用 ~git push origin master~；本地与远程仓库名可不同。
  - 克隆：~git clone git@github.com:michaelliao/gitskills.git~ 生成同名目录 → ~cd gitskills~ → ~git push origin master~。
  - 查看：~git status~；~git diff 文件名~；~git diff 版本号1 版本号2 --stat~ 看差异文件与增删行数，换成 ~--name-status~ 显示 A/M 等状态；~git log~、~git log --pretty=oneline~；~git reflog~ 记录每次命令后的版本号前七位；~git branch~ 列出分支（当前分支带 *）；~git log --graph --pretty=oneline --abbrev-commit~ 看合并图；~git remote~ 与 ~git remote -v~。
  - 修改：~git add readme.txt~ 只添加不提交；~git commit -m "提交描述"~；“改文件→add→再改→提交”时第二次修改不会被提交。
  - 撤销：未 add 的改动用 ~git checkout -- 文件名~ 丢弃；已 add 的先 ~git reset HEAD 文件名~ 取消暂存，再 ~git checkout -- 文件名~。
  - 回退：~git reset --hard HEAD^~ 回上一版本；~git reset --hard 某版本号前几位~ 回指定版本，写前 7、8 位即可。
  - 分支：~git checkout -b dev~ 等于 ~git branch dev~ 加 ~git checkout dev~；~git checkout master~ 切回；~git merge dev~ 在 master 上合并；~git branch -d dev~ 删已合并分支，未合并需 ~git branch -D dev~ 强删；~git rebase master~ 变基，历史比 merge 干净。
  - 冲突：改完手动提交，~git status~ 可查冲突文件；~git merge --no-ff -m "merge with no-ff" dev~ 禁用快进、强制新 commit 以保留分支信息。
  - stash：~git stash~ 存现场，~git stash list~ 查看，~git stash apply~ 恢复（~git stash apply stash@{0}~ 指定），~git stash drop~ 删除，~git stash pop~ 恢复并删除。
  - 远程分支：~git fetch origin~ 抓取并移动 origin/master；~git push origin master~；~git push origin serverfix:awesomebranch~ 推到远程异名分支；~git push origin --delete serverfix~ 或 ~git push origin :remotebranch~ 删除远程分支；~git pull~ 约等于 fetch 加 merge。
  【原文摘录】
  #+begin_quote
  1. 第一步是用git add把文件添加进去，实际上就是把文件修改添加到暂存区；
  2. 第二步是用git commit提交更改，实际上就是把暂存区的所有内容提交到当前分支。
  #+end_quote
  #+begin_quote
  git reflog 记录你的每一次命令，最先显示的是这个命令执行之后的版本的版本号的前七位，这样就算你清屏了或者重启了，也能找到某个版本的版本号，就可以轻松回退到那个版本
  #+end_quote
  #+begin_quote
  简单来说，没有add过的修改，只需要git checkout -- 文件名即可撤销；add 过的修改，先git reset HEAD 文件名变成没add 过的修改，再git checkout -- 文件名撤销。
  #+end_quote
  #+begin_quote
  合并分支时，如果可能，Git会用Fast forward模式，但这种模式下，删除分支后，会丢掉分支信息。如果要强制禁用Fast forward模式，Git就会在merge时生成一个新的commit，这样，从分支历史上就可以看出分支信息
  #+end_quote

  - 平台认知：GitHub 2008 年 4 月 10 日上线，只托管 Git 仓库，靠“Fork 一份 → 改完 → Pull Request 请求合并”把协作成本压到极低；仓库分 public（免费）与 private（付费），个人练手选 public 即可。
  - 注册：官网点 ~Sign up~，填 Username（有标识性，日后博客默认域名就是 ~username.github.io~）、Email、Password，点 ~Create an account~；第二步选免费仓库；第三步问卷可 ~skip this step~。
  - 主页与资料：右上角头像 → ~Your profile~ → ~Edit profile~，可填 Name、Bio、URL、Company、Location、头像；~Settings~ 里的 ~SSH and GPG keys~ 是后面免密提交的关键。
  - 建仓库：~Repositories~ → 绿色 ~New~ → 填 Repository name、可选 Description、选 Public、勾选 ~Initialize this repository with a README~ → ~Create repository~。建完仓库即有 1 个 commit、1 个 master 分支、1 个 contributor。
  - 术语：Repository（仓库）、Issues（问题/bug 反馈）、Star（点赞收藏）、Fork（复制一份到自己的账号）、Pull Request（请求原作者合并你的修改）、Merge（合并）、Watch（订阅更新）、Gist（代码片段分享）。
  - 装 Git：官网点 ~Downloads~ → 选 Windows → 下载安装包 → 一路 ~Next~；关键一步选“Use Git from the Windows Command Prompt”（既可用 Git Bash，也可用 CMD），不要选会把 Unix 工具覆盖进 Windows 的那项；其余传输后端、行结束符、终端模拟器均默认；完成后 ~Launch Git Bash~，输入 ~git~ 能出版本即成功。
  - 前置铁律：任何 git 操作前都要先切到仓库最顶层目录，再在该目录右键 ~Git Bash Here~，让命令行自动定位到仓库根。
  - 十个命令的完整流程（以 ~demo~ 目录、~hit.txt~ 为例）：
    1. ~git status~ 查看状态，此时会提示 not a git repository；
    2. ~git init~ 初始化仓库，默认落在 ~master~ 分支；
    3. ~git add hit.txt~ 把文件加入暂存区，再 ~git status~ 可见 Untracked files 消失；
    4. ~git commit -m "text commit"~ 提交，~-m~ 后双引号内写提交信息，成功后 status 显示 ~nothing to commit, working tree clean~；
    5. ~git log~ 打印提交日志（Author、Date、提交信息）；
    6. ~git branch~ 看分支，~*~ 表示当前分支；~git branch a~ 新建分支 a 但不切换；
    7. ~git checkout a~ 切到 a 分支；~git checkout -b b~ 新建并立即切换到 b（b 是 a 的子分支）；
    8. 切回 ~master~ 后 ~git merge a~ 把 a 合并进来，有冲突须先解决；
    9. ~git branch -d a~ 删除已合并分支，未合并会删不掉，改用 ~git branch -D a~ 强制删除；
    10. ~git tag v1.0~ 打标签，~git tag~ 查看，~git checkout v1.0~ 回到该标签的代码状态。
  - 配 SSH：在 Git Bash 输入 ~ssh-keygen -t rsa~，连敲三次回车（不设密码），生成 ~id_rsa~ 与 ~id_rsa.pub~，默认在 ~/.ssh~（Windows 为 ~C:\Users\用户名\.ssh~）；把 ~id_rsa.pub~ 全文粘到 GitHub 的 ~Settings~ → ~SSH and GPG Keys~ → ~New SSH key~ → ~Add SSH key~；再用 ~ssh -T git@github.com~ 验证，出现成功提示即绑定完成。
  - 同步命令：~git push origin master~ 推送本地更新，~git pull origin master~ 拉取远程更新；push 前先 pull，避免不同步导致冲突。
  - 提交的两种情况：①本地无仓库——~git clone https://github.com/guobinhit/mybatis-tutorial.git~，clone 下来自带仓库与远程关联，改完 add/commit 后 ~git push origin master~（首次需输账号密码）；②本地已有仓库且多次 commit——~git init~ 后 ~git remote add origin https://github.com/guobinhit/springmvc-tutorial.git~，再 ~git pull origin master~ 同步，然后 ~git add~ / ~git commit~ / ~git push origin master~。

  【方法/论点要点】
  - 前提：WSL 从 Windows 10 周年更新（build 14393）开始内置，但本文方法要求秋季创意者更新（build 16299）以上，且必须是 64 位系统；更早版本只能搜「Bash on Windows」另找办法。
  - 开启组件：控制面板 → 程序和功能 → 左侧「启用或关闭 Windows 功能」→ 勾选「适用于 Linux 的 Windows 子系统」→ 确定（可能需要重启）。
  - 安装发行版：打开 Microsoft Store，搜索并安装 Ubuntu（也可选 Debian、Suse、Kali），装完在开始菜单出现「Ubuntu」应用。初学者建议 Ubuntu/Debian 系，包管理完善。
  - 首次启动：等待初始化，设置 Linux 用户名与密码（与 Windows 账号不通用，密码盲打不回显，建议用复杂密码）。
  - 查版本：~uname -r~ 显示内核（如 4.4.0-43-Microsoft）；~sudo lsb_release -a~ 显示发行版（如 Ubuntu 16.04 LTS）。
  - 换国内源（以阿里云为例）：
    1. ~sudo -i~ 提权并输入密码；
    2. 备份：~cp /etc/apt/sources.list /etc/apt/sources.list.old~；
    3. 编辑：~vim /etc/apt/sources.list~，按 ~i~ 进入编辑模式，粘贴阿里云 xenial 全套源（含 main/restricted/universe/multiverse 及 updates、backports、security、partner），按 ~Esc~ 后输入 ~:wq~ 保存退出；
    4. 生效并升级：~apt-get update~ 后 ~apt-get upgrade~。
  - 启用 SSH（便于用 Xshell/Xftp 操作）：
    1. ~sudo passwd root~ 给 root 设密码，之后可直接以 root 登录；
    2. 备份配置：~sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak~；
    3. ~sudo vim /etc/ssh/sshd_config~，按 ~i~ 后修改：~Port 8022~（Windows 侧 22 端口已被占用）、去掉注释的 ~ListenAddress 0.0.0.0~、~UsePrivilegeSeparation no~、~PermitRootLogin yes~、注释掉 ~StrictModes yes~、~PasswordAuthentication yes~，~Esc~ 后 ~:wq~；
    4. 启动：~service ssh start~。
  - 客户端连接：Xshell 新建会话，协议 SSH、主机 ~127.0.0.1~、端口 ~8022~、认证方式 Password、用户名 root；文件管理用 Xftp，协议选 SFTP，端口同样 8022。
  - 图形界面：~sudo apt-get install mate-desktop-environment~ 装轻量桌面 MATE（xfce 亦可）；~sudo apt-get install vnc4server~ 装 VNC 服务端；执行 =sed -i 's$x-window-manager$mate-session$' ~/.vnc/xstartup= 把默认窗口管理器换成 mate-session；~vncserver~ 首次启动设密码；本机装 RealVNC（可用 Chrome 应用版），连 ~127.0.0.1:1~ 即可看到桌面，再 ~sudo apt-get install firefox~ 装浏览器。
  - 实战部署静态站：~apt-get install apache2~ 安装，~service apache2 start~ 启动，浏览器访问 ~http://127.0.0.1~ 见到默认页即成功；用 Xftp 把项目目录传到 =/var/www/html= 下（如 xuyi），访问 ~http://127.0.0.1/xuyi~ 即可。

  - 一句话概括：把 Vim 内置 ~:sort~ 的用法一次讲清——范围排序、去重、倒序、按数字排序，以及"合并行—排序—拆行"对多行文本块按术语排序的完整套路，是顺手整理 CSS 属性、配置文件、词条的高频小技巧。
  【方法/论点要点】
  - ~:sort~ 与 Linux 的 ~sort~ 命令并不等价，先 ~:help :sort~ 看帮助（“Vim内置的sort命令与Linux系统下的sort命令并非完全一致”）。
  - 范围排序：~:3,16sort~ 只排第 3 至 16 行；可视化模式选中后执行 ~:'<,'>sort~ 即排选中区域。
  - 去重：~:%sort u~ 排序时删掉重复行，重复的多行只保留第一行。
  - 倒序与按数字：~:%sort!~ 全篇倒序；~:%sort n~ 按数字大小排；组合 ~:%sort! n~ 即数字倒序。
  - 文本块排序四步法（以 .KS/.KE 包裹的术语块为例）：
    1）把块内换行替换成标记：~:g/^\.KS/,/^\.KE/-1s/$/@@/~
    2）按首尾标记合并成一行：~:g/^\.KS/,/^\.KE/j~
    3）对合并后的行排序：~:%sort~
    4）把 ~@@ ~（含 j 命令自动补的那个空格）换回换行：~:%s/@@ /^M/g~，其中 ^M 用 ~Ctrl-V Ctrl-M~ 输入，Ctrl-V 被占用时用 ~Ctrl-Q~。
  - 结果验证：排序后格式完全保持，只是术语块整体换了位置。
  【原文摘录】

  使用以下命令，将在排序时去除重复的行。对于重复的多行，将仅仅保留第一行，而其它的行将被删除。
  #+end_quote

  #+end_quote

  - 一句话概括：把 Outlook 从"邮件客户端"改造成任务中枢的一套具体流程——邮件两分钟法则转任务/约会后归档、任务按紧急/机会/视线外三区排列、用优先级与自定义字段表达重要性和截止期，核心是"所有事只放在一个列表里"。
  【方法/论点要点】
  - 痛点诊断：把收件箱当任务管理工具，会让邮件堆积如山、反复重读、心理压力大；收件箱也没有任务管理需要的能力（主题、优先级、排序、分类、截止期限、需时）。
  - 邮件处理两步法：Step1 判断"是否需要我采取行动"——不需要就归档到"已处理邮件"子文件夹（可分类），垃圾邮件直接删；Step2 需要行动的，两分钟内能搞定就立刻做完再归档，否则判断它是任务还是约会，分别转成任务或日历项，**转完立即归档**。
  - 概念区分：任务=没有具体时间地点的下一步行动；约会=有明确时间地点的行动；下一步行动=紧接着要做的单步任务（动词开头）；MORE 任务=有前后依赖的多步小项目；项目=需分阶段管理的复杂任务。
  - 分类原则：只给少数邮件贴类别标签，大多数直接归档靠搜索找——省掉"这封该归哪类"的纠结时间。
  - 任务列表三区：高优先级=目前紧急任务（今天必须完成，红色）；普通优先级=目前机会任务（10 天内到期或计划要做的近期任务）；低优先级=目前视线外任务（10 天以后再说的，战略性推迟，"眼不见心不烦"）。
  - 目前目标任务：用蓝色下划线标在普通优先级顶部，表示今天计划要做的事；"目前紧急任务 + 目前目标任务 = 今日计划"。
  - 重要性用自定义字段 II（0~3）表达，越重要字体越大越粗，执行时"要事第一"；截止期限不用内置字段，改为在任务主题前加"Due 日期"。
  - 所有任务进同一列表：邮件外的任务（大脑、微信、QQ、OA、会议、电话）用三种方式录入——转发到自己邮箱再按流程提取、少量手工录入、大量用 Excel 模板批量导入。
  - 配套工具：MYN Pro 插件可把邮件主题/正文/附件一键转成任务或约会、自动归档、支持 MORE 任务完成后自动推送下一步、批量调优先级。

  【方法/论点要点】
  - 文件与目录：~ls~（~-a~ 含隐藏、~-A~ 排除 . 与 ..、~-r~ 反序、~-t~ 按时间、~-S~ 按大小、~-h~ 易读、~-l~ 详细，可组合成 ~ls -lhrt~）；~cd~（~cd -~ 回上一个目录、~cd !$~ 复用上条命令的参数）；~pwd~（~-P~ 显示软链接的真实路径）；~mkdir -p~ 一次建多级目录；~rm~、~rmdir~、~mv~、~cp~。
  - 查看文件：~cat~（适合短文件）、~more~（只前进）、~less~（可前后翻，处理大文件首选）、~head -n~、~tail -n~（~-f~ 实时跟踪日志）。
  - 查找定位：~which~ 查命令所在；~whereis~ 查二进制/源码/手册；~locate~ 走数据库、快但需更新索引；~find~ 走真实文件树，按 ~-name~、~-perm~、~-user~、~-group~、~-type~（b/d/c/l/p/f）、~-size~、~-mtime/-mmin/-atime~、~-maxdepth~ 组合，配合 ~-exec~ 或更安全的 ~-ok~ 处理结果。
  - 权限：~chmod~ 两种写法——字母法（~u/g/o/a~ + ~+/-/=~ + ~r/w/x~）与数字法（r=4、w=2、x=1，如 ~chmod 751~ = 属主 rwx、同组 rx、其它 x），~-R~ 递归、~-c~ 显示变更。
  - 归属：~chown~ 改属主/属组。
  - 打包压缩：~tar~ 本身只打包不压缩，压缩靠搭配的参数；~-c~ 新建、~-f~ 指定文件名、~-r~ 追加、~-u~ 更新、~-x~ 解包。
  - 磁盘与链接：~df~ 看分区占用、~du~ 看目录/文件大小、~ln~ 建硬链接与软链接。
  - 时间：~date~ 显示与格式化时间、~cal~ 看日历。
  - 文本处理：~grep~ 过滤匹配行、~wc~ 统计行数/词数/字节。
  - 进程与资源：~ps~ 快照、~top~ 实时排序、~kill~ 发信号结束进程、~free~ 看内存与 swap。
