  - 一句话概括：一篇面向 2018 年之后 Vim 8 的 C/C++ 开发环境搭建指南，按插件管理、符号索引、自动索引、编译运行、动态检查、代码补全、函数列表、文件切换、参数提示逐环节推荐现代插件与配置。
  【方法/论点要点】
  - 插件管理：别再用 Vundle，改用 vim-plug——全异步安装（50 个插件一分钟内）、更新快、支持延迟加载（~on~ / ~for~）、可指定分支或 tag、单文件便于纳入 dotfiles，且用 ~:PlugUpgrade~ 自我更新；建议给插件分组，vimrc 里只选启用哪些组。
  - 符号索引：不要排斥 ctags（支持 50+ 种语言，Vim 集成最好、依赖最少）。配置要写对：~set tags=./.tags;,.tags~——tag 文件名前面加点避免污染项目，分号表示找不到就向上递归到父目录，逗号后表示同时在 Vim 当前目录查找。并升级到 Universal Ctags（Exuberant Ctags 已停止维护近十年），注意用 ~--output-format=e-ctags~ 保持兼容。
  - 自动索引：用 vim-gutentags，做两件事——靠 ~.git/.svn/.project~ 等标志向上递归确定工程目录；增量更新对应工程的 ~.tags~ 并保持符号排序以便二分查找。配置要点：~gutentags_project_root~、~gutentags_ctags_tagfile~、把 tags 放入 ~/.cache/tags~ 避免污染工程、~gutentags_ctags_extra_args~ 加 ~--fields=+niazS~ 等。建议多用 ~CTRL-W ]~ 新窗口跳转、~CTRL-W }~ 预览，少用 ~CTRL-]~。
  - 编译运行：用 AsyncRun 后台运行 shell 命令并把结果输出到 quickfix。单文件 ~F9~ 编译、~F5~ 运行（~-cwd=$(VIM_FILEDIR)~、~-raw~）；项目用 ~<root>~ 或 ~$(VIM_ROOT)~ 表示工程路径，配置 ~g:asyncrun_rootmarks~，~F7~ make、~F8~ make run、~F6~ make test、~F4~ cmake。快捷键总览：F4 生成 Makefile、F5 单文件运行、F6 项目测试、F7 项目编译、F8 项目运行、F9 单文件编译、F10 开关 quickfix。注意 C 标准库后台运行会缓存标准输出，需 ~fflush(stdout)~ 或 ~setbuf(stdout, NULL)~；C++ 用 ~std::endl~ 即可。Windows GVim 可用 ~-mode=4~ 弹新 cmd 窗口。
  - 动态检查：别用老的 syntastic（不能实时、保存即卡），改用实时 linting 的 ALE（支持 gcc/clang/cppcheck/clang-format 等，保存前就实时标注错误、侧栏提示、红色波浪线）。
  - 代码补全：传统 omni 补全语义弱、无法后台运行；新一代 YCM/Deoplete 支持异步与基于 clang 的语义补全，C/C++ 推荐 YCM（Deoplete 的 clang 补全不稳定、吃内存）。配置要点：输入两个字符即触发语义补全（~ycm_semantic_triggers~）、关闭预览窗口与诊断 UI（~ycm_show_diagnostics_ui=0~）保持清静，诊断交给 ALE。
  - 函数列表：别再同步等待 ctags 的 tagbar（保存变卡），改用 LeaderF 的 ~:LeaderfFunction!~ 全异步显示函数列表，绑定 ~ALT+P~，可模糊匹配搜索、TAB 切换列表筛选，不占屏幕空间。
  - 文件切换：用 LeaderF 代替 CtrlP，支持文件、MRU、Buffer 名称搜索，~CTRL+P~ 文件搜索、~CTRL+N~ MRU、~ALT+N~ Buffer，匹配效率高于 CtrlP/Fzf；浏览新项目可用 NERDTree 或更 Vim 式的 vim-dirvish（按 ~-~ 在当前窗口回到所在目录）。头文件/源文件切换用 a.vim 或自己两行脚本。
  - 参数提示：用 echodoc 无缝搭配 YCM，靠 libclang 在命令行显示参数并高亮当前参数位置；配合 ~set noshowmode~ 把底部模式提示让给 echodoc。
  - 结尾参考：《Vim 8 中的 C/C++ 编译运行》《Vim 中文版入门到精通》《Vim 中文速查表》，并给出 vimzh 交流群。

  - 一句话概括：不用堆插件，而是围绕自己的真实工作流「发现问题→找更快的方式→习惯化」不断循环，用 VimScript 逐个打磨痛点，并给出透明窗口、跨窗口滚动、Tag 预览、函数原型、异步编译等八个具体例子。
  【方法/论点要点】
  - 核心心法（据 Bram 的视频）：1 检测工作流里哪里浪费时间；2 寻找更快的方式（官方文档、他人经验、自己写 VimScript）；3 使它习惯化。三点反复循环，重点是根据自己的需求迭代，而不是照抄教程装一堆插件——插件是别人为通用需求提炼的，和你的具体需求总有差别。
  - 问题1 边开发边参考网上方案：反复 ALT_TAB 切 Chrome/GVim 很低效，于是用 VimScript + 内嵌 Python 拿到 GVim 顶层 HWND，一键在透明/不透明间切换。
  - 问题2 浏览文档时的窗口滚动：左右分屏参考时，要滚左边就得切焦点再切回来。写 ~Tools_PreviousCursor~ 函数（用 ~wincmd p~ 暂切到前一窗口做 ~<c-y>/<c-e>/gg/G~ 等滚动再切回），绑到 ALT_U/ALT_D，不退出插入模式就能滚动参考文档；同理给 Quickfix 窗口写了滚屏函数。
  - 问题3 Tag Preview 低效：原生 ~CTRL-]~ 会切走当前文档，~<C-W><C-]>~ 又会打印一大串定义让人选且默认上下分屏。自己重撸：ALT+; 在右侧弹出预览窗口并高亮符号，底部显示「共 N 处、当前第几处」，连按 ALT+; 循环切换定义，ALT+SHIFT+; 关闭——全程不切焦点、不切模式，用一周后彻底淘汰原生 tag 功能。
  - 进一步做「函数原型」：忘函数参数时不需要打开整个预览窗口，写函数绑到 ALT_Q，在最底一行循环显示函数原型多处定义；比 YCM 支持语言广（基于 Universal Ctags，覆盖 85 种语言）。
  - 问题4 代码片段：常写的格式化注释框、copyright、带 main 的框架，用 VimScript 一键生成；UltiSnip 虽好但没为 Vim 8/Neovim 做异步优化、打开新文件变慢，所以作者仍用自己的简单实现。
  - 问题5 加速 Cygwin 开发：跨平台要反复用 MinGW/Cygwin 编译测试还得切终端窗口。借 Vim 8/Neovim 的后台任务机制写了 AsyncRun 插件，用 ~:AsyncRun [cmd]~ 替代阻塞式 ~!~，并映射 F7 编译 MinGW（~gcc "%" -o "%<"~）、F8 编译 Cygwin（~d:\cygwin\bin\bash --login -c "gcc % -o %<"~）。
  - 问题6 加速 Android NDK 开发：以前写 NDK 要命令行编译再导进 Eclipse/Android Studio 套 Java GUI，改一处折腾半天。结合 AsyncRun + 少量 Python/VimScript，实现 F9 按 Android 命令行程序编译 NDK 并 adb 上传到 /data/local/tmp 设 755，F10 打开 cmd 经 adb 运行——像开发 PC 命令行程序一样开发 NDK，还支持模拟器和真机。
  - 问题7 高效 Grep：原生 grep 不支持异步，用 AsyncRun 配合：~:AsyncRun! grep -n -R <cword> .~ 或加 ~-cwd=<root>~，一键在当前目录 grep 光标下的符号，结果实时输出到 Quickfix，双击即可跳转。
  - 问题8 日常小工具：如把挤在一起的 HTML 片段一键格式化（~asclib#html_prettify~ 用替换 + ~ggVG=~），还有 GTAGS 支持、一键 touch wsgi 主文件、头文件/源文件快速切换、快速打开 Zeal 查文档等——都是围绕自己习惯写的，通用插件解决不了。
  - 结论与对比：其他编辑器/IDE 的效率是常数，上手后很难再提升；Vim 的效率是变量，越调教越顺手。效率低的三种反面：学会基本用法后不再学新技巧；想学一切技巧反而浪费时间；只摆弄插件，插件做不到的就束手无策。
  - 推荐资料：《Five Minute Vimscript》、~:h index~、~:h quickref~、《Practical Vim》、《Learn Vimscript the Hard Way》、《Vim 中正确使用 Alt 映射》。

  【方法/论点要点】
  - 总方法：不懂车就看直观数据，数据比主观评价更可观。年轻人预算多在 15 万以内（土豪与富二代除外）。

  - 选车第一看销量：15 万落地车型月均低于 5000 台要慎重，销量低的车可能随时停产、后期维修保养是问题。
  - 第二看质量：用「投诉销量比」评质量可靠性；2023 年三季度 SUV 投诉销量比均值万分之 63.2、轿车万分之 69.7，高于平均线的一概不考虑（年销 6 万以上的燃油车仅别克君越未过关）。作者把数据都列出，读者可自设质量标准线。
  - 三类车型的入围与投诉（示例）：燃油车 38 款（轩逸、朗逸、速腾、卡罗拉、雅阁、思域等，附各车近一年主要投诉内容）；纯电 9 款（海豚、AION S、秦 PLUS EV、欧拉好猫、ID.3、元 PLUS 等，门槛设为月销 3000 台、投诉比万分之 67.3）；插混/增程 6-7 款（秦 PLUS DM-i、驱逐舰 05、深蓝 SL03/S7、宋 PLUS/Pro DM-i、银河 L7）；作者解释不推荐畅销的宋 PLUS DM-i 是因为「问题太多，大数据说话」。
  - 评价维度按动力类型不同：燃油车看内外颜值、使用成本、售后服务、保值率、舒适度（轿车）/空间（SUV）；增程/插混看颜值、售后、亏电与综合油耗、智能化；纯电看颜值、续航、快充、售后、智能化。
  - 数据来源与结论举例（燃油轿车）：颜值 TOP3 领克 03、长安 UNI-V、吉利星瑞；使用成本最低雷凌、卡罗拉、轩逸；售后满意度最高雷凌、领克 03、轩逸/天籁；5 年保值率最高雅阁、思域、卡罗拉；舒适度最高雅阁、天籁、型格。各指标换算百分制后综合排序。

  - 最终推荐榜：燃油轿车 TOP5（雅阁、思域、领克 03、天籁、长安 UNI-V）、燃油 SUV TOP5（皓影、RAV4 荣放、威兰达、星越 L、博越 L）、纯电 TOP3（秦 PLUS EV、元 PLUS、欧拉好猫）、增程/插混 TOP3（深蓝 S7、深蓝 SL03、驱逐舰 05），每款都列出优点与缺点（如雅阁隔音差/车机差，思域隔音差，领克 03 保养贵等）。
  - 实操建议：买车货比三家，同一城市不同 4S 店落地价也会不同。作者提醒数据会定期更新，当下最优不代表一直最优。

  - 命令提示 vs 补全：「命令提示和补全是两个完全不同的系统，很多时候提示比补全更有用」。输入完 tar 后，灰色即提示参数，并随每个字母动态修正（输入 `-c` 就立刻从解压提示切到压缩提示）；提示基于你的历史命令数据库，用得越多越准；按 `CTRL+F` 采纳整条建议。
  - 智能补全：内容较多时连按两次 TAB 进入「选择模式」，可用光标键或 emacs 键位 `ctrl+f/b/p/n`（前后上下）移动，也可自定义为 `ALT+hjkl`；回车确认，`CTRL+G` 退出。另有路径缩写补全（省去长路径逐层输入）与二级参数补全（如 `svn commit --` 后两次 TAB 选参数）。
  - 快速跳转：`cd -` 后按 TAB 列出本次登录去过的最近路径，输入序号回车即跳（例：`cd -5` 跳到 ~/software/libclang-python3），也可再按 TAB 进选择模式挑选。

    SELECT sum(Domestic_sales+International_sales) as sum_sale, director,
           count(*) as count,
           sum(Domestic_sales+International_sales)/count(*) as avg_sale
    FROM movies left join boxoffice on movies.id = boxoffice.movie_id
    group by director
    having count > 1
    order by avg_sale
    desc limit 1
    #+end_src
  - 核心心法：不管多复杂的 SQL，先归结到最简单的 SQL 法则——凡是 SQL 都分为 select、from、where 三段，复杂 SQL 只是这三段各自不简单，那就**分段解决**。
  - 第 1 步·只解决 from：不关心 select 和 where，先把联表写出来，并想象联表之后生成了一张新表 t1。
    #+begin_src sql
    SELECT *
    FROM movies left join boxoffice on movies.id = boxoffice.movie_id
    where 1
    #+end_src
  - 第 2 步·在 t1 上只解决 select：把 group 等结果集操作放到一边，只盯着要统计的列，逐个函数拆开看（sum、count、sum/count）。
    #+begin_src sql
    SELECT sum(Domestic_sales+International_sales) as sum_sale, director,
           count(*) as count,
           sum(Domestic_sales+International_sales)/count(*) as avg_sale
    FROM t1
    #+end_src
  - 第 3 步·最后再处理结果集：把 select 里的算法放在一边，加上分组、过滤与排序。
    #+begin_src sql
    SELECT ...
    FROM t1
    group by director
    having count > 1
    order by avg_sale
    desc limit 1
    #+end_src
  - 结论：「一个复杂 SQL 其实都是由简单的部分组成，只要你按照这个方法一层层的拆解，你会发现复杂 SQL 不过如此。」（作者标注原文未完待续）

* int (*(*fun(int*(*p)(int *)))[5]) (int*)表示的是什么?  :技巧:C语言:类型声明:指针:
  :PROPERTIES:
  :链接:  https://www.zhihu.com/question/542944040/answer/2573116176
  :作者:  Hippop
  :原文:  [[file:原文/2026-10-20-intfunintpint[5]int表示的是什么-2573116176.org][本地原文]]
  :抓取:  2026-10-20
  :END:
  - 本地原文：[[file:原文/2026-10-20-intfunintpint[5]int表示的是什么-2573116176.org][打开本地归档]]
  - 一句话概括：给出一条能拆解任意 C 复合类型声明的通用规则——右边表达式运算后的结果类型等于左边，然后从最外层运算符逐层「脱衣服」，把一串吓人的函数指针数组声明还原成人话。
  【方法/论点要点】
  - 核心规则：对于任意一种类型声明式，右边类型表达式经过 *、()、[] 运算后的结果类型与左边相同。
  - 类型表达式里的 () 也表示调用运算，括号内可附带参数类型信息。如 int (*p)(int *) 表示可对 *p 做函数调用、传 int* 得 int，所以 *p 是函数、p 是函数指针。
  - 类型表达式里的 [] 也表示下标运算，括号内可带元素个数。如 int a[5] 表示对 a 做下标运算得 int，所以 a 是数组。
  - 反推原则：优先级最低的运算最先被脱掉。逐层拆解该声明：
  - ① 最外层 (*(*fun(...))[5]) (int*)：后运算的是调用，所以 *(*fun(...))[5] 是返回 int、参数 int* 的函数。
  - ② *(*fun(...))[5]：[] 优先级高于 *，故 (*fun(...))[5] 取值得函数，说明它是函数指针。
  - ③ (*fun(...))[5]：() 优先级高于 []，故 *fun(...) 是含 5 个元素的函数指针数组。
  - ④ *fun(...)：调用优先级高于取值，故 fun(...) 得到指向数组的指针。
  - ⑤ fun(int*(*p)(int *))：括号内是参数，fun 是函数，调用后返回指向数组的指针。
  - ⑥ int*(*p)(int *)：返回 int*、参数 int* 的函数指针。
  - 合起来的结论：这是一个函数，参数是「返回 int*、参数 int*」的函数指针，返回值是「指向 5 元素数组」的指针，数组元素是「返回 int、参数 int*」的函数指针。
  - 正推验证法：把类型表达式改写成语句表达式 (*(*fun(0))[0])(0)，结果类型为 int；参数用值代替、下标填 0，执行顺序即 fun 调用 → 取值 → 取元素 → 取值 → 函数调用 → 得 int，正好是上面过程的反推。

  - 权重四等级：内联样式 1000；id 选择器 100；class、伪类和属性选择器 10；元素选择器和伪元素选择器 1。通用选择器 *、子选择器 >、相邻同胞选择器 + 不计入等级，权重为 0。
  - 伪类与伪元素的书写区分：一个冒号是伪类（:hover、:focus、:first-of-type、:first-child），两个冒号是伪元素（::before、::after）。
  - a 标签的三个作用：超链接、锚链接、打电话/发邮件。
  - CSS 画三角形：border 其实由四个三角形拼接而成；把宽高设为 0、四边给不同颜色即可看到四个三角形；再把不需要的三边设 transparent、把保留侧之外的 border-width 设为 0，就得到单个三角形。
  - 水平垂直居中：固定宽高用 absolute + left/top 50% + 负 margin；不固定宽高有四种——absolute + transform: translate(-50%,-50%)、absolute + 四边 0 + margin:auto、flex 的 align-items/justify-content: center、table-cell + vertical-align:middle（需父元素固定宽高，且 padding 与设定高度会互相影响）。
  - 元素三类：行内元素设宽高无效、只有左右外边距有效（span、a、em、label、strong）；行内块可设宽高和外边距（img、input、video、audio）；块级独占一行（div、p、ul、li、h1-h6、table、form）。
  - 盒模型：标准盒模型 width/height 只指 content；box-sizing: border-box 让宽高包含 content+padding+border，加 padding 时内容自动缩小；另有 inherit。
  - margin 塌陷（父子垂直 margin 取最大值，子元素会带着父元素下移）的四种解法：position: absolute/fixed、float、display: inline-block、overflow: hidden，本质都是触发 BFC。margin 合并则是兄弟元素垂直 margin 取最大值。
  - 清除浮动四法：父元素 overflow:hidden；父元素末尾加空子元素并 clear:both；父元素 ::after 伪元素 + clear:both；用 BFC（absolute/fixed、float、inline-block/table-cell、overflow 非 visible）。
  - 圣杯与双飞翼都是「两侧固定、中间自适应、中间 DOM 优先」的三栏布局，核心是左侧 margin-left:-100%；两者也都能用 flex 实现（中间 flex:1，左侧 order:-1）。
  - px 相对屏幕分辨率，em 相对父元素字体大小，rem 相对根元素字体大小；只适配少量设备用 px，适配各种移动设备用 rem。媒体查询示例为 @media screen and (max-width: 300px)。
  - HTML5 新特性列了音频、视频、地理位置、localStorage、sessionStorage。
  - Flex 是一维轴线布局，设置后子元素的 float、clear、vertical-align 失效；Grid 把容器划成行列、是二维布局。
  - 行内元素间距三种解法：写在一行不留空格、父元素 font-size 设为 0、使用 float。

  - 一句话概括：一位把 VS、Source Insight、Vim+ctags/gtags 各用三年以上的老手，论证代码阅读该用「懂语义」的 Understand：它能对宏求值、按参数类型精确匹配重载，配合预览窗和符号面板，读陌生代码比字符串检索式工具快一倍。
  【方法/论点要点】
  - 出发点：读优秀项目源码是自我提高的重要途径，好工具事半功倍。像 Lua，官方文档一天能看完，源码很多人一个月都看不明白。
  - 作者的工具演进：最早直接用 VS 读代码 → 用 Source Insight 替代 VS → 用 Vim + ctags/gtags → 各种工具都试过 → 近几年只用 Understand。
  - 建议所有 Source Insight 用户迁移到 Understand：SI 十多年基本没更新（虽出了 4.0），而 SI 有的功能 Understand 基本全覆盖。
  - 基本用法：点「地球图标」进入浏览模式，鼠标点击代码区符号（函数、变量名），下方 Previewer 就显示相关代码；双击 Previewer 可在上方代码区打开对应源文件。
  - 左下角符号详情面板列出符号的定义、引用、被调用、以及它调用了什么，信息比 SI 更方便。
  - 首次使用要在 View 菜单里打开 Previewer、Project Browser、Scope List 三项，这样就和 SI 的界面基本对齐了。
  - 语言支持：C/C++、Python、Java、汇编、VB、C#、Fortran、Ada、VHDL、Delphi/Pascal 等十多种，比 SI 丰富。
  - 与 Vim + gtags/ctags/cscope/grep 的核心差异：Understand 真的在分析、理解源码，而 ctags/gtags 只是按格式扫描文本。三个具体例子：① 无法处理宏条件编译，多平台同名函数会搜出一堆无关结果；② 同名不同参数的符号，Understand 能按调用处的参数类型精确匹配，ctags 只能全列出来；③ 对 x->update() 这类调用，ctags/gtags 的 Vim 插件分析不出 x 的类型，会把所有 update 都列出来。因此 C 语言尚可，C++ 基本没法看。
  - 与 Source Insight 4.0 的差异：SI 4.0 仍无法理解宏，查找 TEST_1 定义会得到多个结果、分不清哪个有效；Understand 能对宏表达式求值、准确识别有效代码块。
  - 与 Visual Studio 的差异：VS 的跳转会打开一堆文件挤掉工作区，Peek Definition 是插入一段代码、看完还要手动关；Understand 是「源码窗口 + 预览窗口 + 符号信息窗口」三合一，鼠标点点就能连看十几处定义。
  - 与 Sourcetrail 的差异：作者认为其很弱，像三岁小孩比成年人——它是个人兴趣开源项目，而 Understand 是商业团队持续迭代 15 年以上的产品。
  - 图表能力：符号 butterfly 图（左边调用者、右边被调用者，gtags 生成不了，因为它找得到 callers 却找不出 callees）、项目鸟瞰图（方块可点开看细节）、全局统计、流程图、定义图、继承图、UML 图、依赖图、Tree Map、交叉引用图等。
  - 宏解析补充：可直接导入 Visual Studio 的 sln 文件和 CMake 的 cache 数据（其中含基础宏定义），据此对更高级的宏表达式求值；裸项目可手动设置宏，支持预定义/导入导出，右下角 Undefined Macros 会提示哪些宏没定义，一般只定义几个平台相关的基础宏就够。有条件还是建议导入工程文件，更省事也更准确。
  - 收尾观点：作为三类工具各用三年以上的人，Understand 读代码效率最高、最方便，基本能提升一倍以上；工具若能在未来数年持续让你受益，值得花一天试用评估。它支持 Windows、Linux、macOS。

  - 一句话概括：把闲置路由器的 WAN 口空着、只用 LAN 口，关掉 DHCP、改掉默认 LAN 口 IP，它就退化成一台四口交换机，让两个路由器下的电脑落在同一局域网里共享文件和打印机。
  【方法/论点要点】
  - 需求场景：想把路由器当交换机，通常是为了让局域网内所有电脑共享文件或打印机；关键动作是关 DHCP、改 LAN 口 IP。
  - 背景：普通路由器只有 5 个网口——1 个 WAN 接外网、4 个 LAN 接电脑，所以默认只能带四台。
  - 电脑多于四台时的正路是加一台 8 口或 16 口交换机：腾出一个路由器 LAN 口与交换机相连，交换机其余口随便用。
  - 原理：路由器的 4 个 LAN 口本质上就是一个 4 口交换机，路由器本身是「路由器 + 交换机」的结合，只是交换口只有 4 个；接在同一交换机上的电脑同属一个局域网，可互相访问。
  - 方案一（不推荐）：后一台路由器的 WAN 口接前一台的 LAN 口。这样 7 台电脑被分成两个局域网，跨网段不能互访，也就无法把文件或打印机共享给所有电脑。
  - 方案二（推荐）：只用 B 路由器的 LAN 口，WAN 口不接。因为每个路由器都带 DHCP，为防止冲突必须关掉其中一个；又因为 LAN 口默认多是 192.168.1.1，两个 LAN 口接在一起会冲突，必须改掉其中一个。
  - 设置顺序很重要：最好先不接入现有网络再设置，避免 IP 冲突导致登不进路由器。用一台电脑用网线连到该路由器的 LAN 口，再登录修改。
  - 找登录地址：电脑接 LAN 口后，登录用的就是这个 LAN 口 IP，新路由器一般是 192.168.1.1；若改过，可在 cmd 里执行 ipconfig，看「默认网关」——默认网关就是 LAN 口 IP。然后在浏览器地址栏输入该地址；有些新路由器只需输密码、不需用户名。
  - 操作顺序建议：先关 DHCP，再改 LAN 口 IP。因为 LAN 口 IP 一改，有些路由器会立刻自动重启，比较麻烦。
  - LAN 口 IP 只需改成局域网内不会被用到的地址即可。
  - 注意：关掉 DHCP、改完 IP 后，电脑连这台路由器就不能自动获取 IP，需要设固定 IP 才能登录。若 LAN 口设为 192.168.200.200，电脑 IP 要在 192.168.200.1-192.168.200.254 范围内才能登录。
  - 无线不受影响：当交换机用不影响路由器的 Wi-Fi，手机或笔记本连它的 Wi-Fi 相当于接在 LAN 口，有线无线设备之间都能互访；记得给 Wi-Fi 设密码。

  实际上，路由器的4个LAN口本质上就是一个4口交换机，我们所使用的路由器，是路由器与交换机的结合，只不过交换接口就只有4个而已。
  #+end_quote
  #+begin_quote

  #+end_quote

  - 一句话概括：从面试官视角给出三条「科学面试原则」，用叙事自我与峰终效应解释「为什么临场表现比内容更重要」，再把自我介绍改写成「背景—悬疑—冲突—解决」的故事，并给出上台前调状态的动作。
  【方法/论点要点】
  - 三个原则（作者称遵循后通过率至少翻番）：
    1. 通过的人不是最优秀的，而是让面试官「感知最优秀」的，主观感觉比客观能力更起作用。
    2. 面试不是跟面试官 PK，而是跟你看不到的其他候选人竞争，所以不必面面俱到答问，而要拿出最高分的自己。
    3. 最重要的一条：打分依据不是整场平均表现，而是「峰终效应」——最佳表现与结束时表现的平均值。
  - 前提认知：书面考试是客观评分、考认知，临时抱佛脚求「大而全」是对的；面试是主观打分，拼的是 show 是否出彩。语言沟通只占沟通表现的约 15%，语调、表情、仪态、微动作都要演练。
  - 既然通知你来面试说明简历已证明能胜任，面试真正要选的是「感觉最佳的人」，同时确认经验真实性。
  - 理论依据：人用「体验自我」（实时、无记忆）和「叙事自我」（事后印象、只编故事）两种模式评价外界；面试官隔天综合比较，靠的是叙事自我，而叙事自我只看最佳表现和结束表现。
  - 推论：准备重点不是精修内容，而是反复演练自己的「最佳亮点」和「如何结束面试」。作者用分数举例：能力 6 分的人状态好能演出 8 分，状态差只有 4 分，这 4 分差距是一晚上就能争到的。
  - 反面例子：一段只报年限、产品、成绩和技能匹配的自我介绍，讲得抑扬顿挫，面试官心里仍是「又是同样的开场白」。
  - 正面做法：用讲故事模式（基于认知深度加工理论），戏剧体四段——背景（只体现一个核心亮点）、悬疑（引出好奇点）、冲突（常规方法难解决或两难）、解决（靠独特优势历经内心折磨解决）。示范版本从头到尾不自夸，却把有担当、敢创新、能抗压写出来了。
  - 面对面讲故事的关键是「真实」，夸大编造会被轻易识破，反而留下极差印象。
  - 演练方法：一定要说出来而不是默读；对着镜子看表情和肢体；找不到感觉就找气场相似、能讲的人的视频模仿（TED 上很多）。
  - 面试前调状态：双手握拳摆胜利姿态（务必在无人处）、做「扩张型」动作如双手舒展抱头或自信叉腰，均可提升自信感；愉悦心情比「如临大敌」更利于发挥。
  - 收尾：即使没通过，表现力（演讲力）也得到了锻炼；平常心，尽力即可。

    1. 第一印象：整理仪容，女生淡妆、男生整理发型，不穿短裤。
    2. 少说「我觉得/我认为」，多用数据和案例，例如「1 万用户时写出 12 篇 5~10 万阅读、3 篇 10W+，接手后平均高于以往 3000 阅读」。

    6. 自带简历、纸和笔，简历彩印别省两块钱。
    7. 提前 15~20 分钟到，太早先别进去，2:50~2:55 再进。
    8. 简历是概况，自我介绍是精华浓缩，不要因为简历写了就不说。
    9. 预判追问（「这个项目你怎么思考的」「PS 熟练到什么程度」），写上去的经历要经得起拷问。

  - 一句话概括：把自我介绍拆成「三种匹配度」（行业、工作内容、企业文化价值观），再用一段普通自我介绍做前后对比，讲清怎么用逻辑线、故事反转、数据和专业术语把它改得让面试官记得住。
  【方法/论点要点】
  - 开场立论：很多人把精力全花在准备问题回答上，却不知道一分半钟的自我介绍往往决定成败；首应效应下，讲得好后面提问都在印证「你不错」，讲得差就在印证「你一般」，后面很难翻盘。
  - 两个类比说明逻辑：人群里让你怦然心动的那个 TA，对应面试官一眼看中的候选人；饿着想吃川菜却端上清蒸饺子，对应招人急却来了个不对味的人。核心是让自己成为「对方喜欢且需要」的人。
  - 三种匹配度：
    1. 行业匹配：有目标行业相关实习/项目最好；没有就找类似行业，或目标公司的乙方、丙方建立连接。
    2. 工作内容匹配：做过相关实习、专业对口、上过相关课程都算。
    3. 价值观与文化匹配：前两者都没有时的兜底——公司重视创新，而你鬼点子多、思维活跃，就是匹配。
  - 改造方法四条：
    1. 重逻辑、串关联：自我介绍不是简历搬运工。以应聘市场推广为例，在讲校园经历前先插一句「我对市场推广很感兴趣，大学做的事都是有规划的」，再把大一到大三的经历串成一条线，而不是罗列信息点。
    2. 加故事性甚至反转：讲清是什么契机让你进入这个行业、你和这家公司有什么故事，让人像听故事一样听，才能在千百份相似自我介绍里被记住。
    3. 多用数据，两个方向：强调创造的价值大、强调花的时间精力短。同一件事三种写法——普通版「带领部员定期举办校园活动」；低阶版「办了一场大型活动，公众号加线下宣传共吸引 1000 人参与」；高阶版「带 10 人团队（领导力），仅用 2 周（时间短）吸引 1000+ 报名（成果佳），好评率 99%（体验好），并获学校嘉奖」。
    4. 多用专业术语显得像行内人：「建微信群、创造话题活跃气氛」改成「通过 xx 方法做社群运营，达到促活用户的目的」；「淘宝智能推荐」改成「通过大数据实现千人千面的个性化推荐」。术语来源是多看招聘贴。
  - 经历完全不相关怎么办：仍从企业文化价值观切入，硬挖出关联点，作者用一份专业、行业、工作内容都不匹配的简历做了改写示范。
  - 通用模板三段：①基础信息 + 性格优点；②相关经历（行业或工作内容相关），讲做得好的地方和相关技能；③对公司的了解和向往。此外要用神情和肢体语言体现诚意。
  - 作者自述背景：非 985/211，校招非海投拿到留德、香港、顶级广告公司跳级、五百强等 10+ offer，简历通过率 95%+，5 年求职咨询、改过 1000+ 简历。
